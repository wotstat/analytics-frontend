# Open Graph

Карточки и метаданные живут в обычном `src/` рядом со страницами сайта. Студия —
асинхронная страница основного SPA по `/meta`. Второе приложение, `App`, содержит
только renderer карточек для Bun backend. Общего отдельного проекта `meta/` нет.
`src/meta/` содержит общие протоколы и механизм Open Graph. Дизайн карточек,
default-определение и общие контексты сайта находятся в `src/shared/ui/meta/`.

Основной сайт остаётся SPA. Сервис `analytics-frontend-meta` добавляет мета-теги
в собранный `index.html`, а PNG получает отдельным запросом через Chromium.
Запрос HTML не запускает браузер. При первом прогреве он может ждать контексты
выбранного определения в пределах их `initialWaitMs`; затем метаданные вычисляются
синхронно из последнего успешного снимка.

Страница `/debug/meta` содержит только заголовок и ссылку на студию `/meta`.
Отдельных debug-страниц превью и категории Open Graph нет; тестовые карточки
и их определения сохранены для проверки в студии и renderer.

Debug-карточка для URL `/debug/meta/vehicle?tag=ussr:R45_IS-7` расположена рядом с карточкой
задержки: `pages/debug/pages/meta/cards/vehicle/`. Карточка читает русское название
по составному ключу `(RU, RU, tag)` из `VehiclesLocalizationDictionary` через
`dictGetOrDefault` и завершает `useMetaReady` после ответа. Неизвестный тег показывает
«Танк не найден», отсутствующий/некорректный — подсказку без запроса. Ошибка БД
отклоняет готовность и не превращается в успешную PNG. SQL кешируется до конца UTC-дня;
кеш HTML/PNG debug-примера выключен.

Заголовок этого же примера берёт имя из общего контекста
`shared/ui/meta/contexts/vehicleNames.ts`: «ИС-7 — WotStat Analytics». Контекст загружает
словарь `(region = 'RU', locale = 'RU')` целиком при старте и раз в час. Первоначальное
ожидание ограничено тремя секундами. Если имени ещё нет, title —
«Название танка — WotStat Analytics». Vue-карточка продолжает выполнять
свой отдельный запрос через `useMetaReady`.

В сборке renderer `VITE_META_RENDERER=true` выбирает `/api/db/` локального origin.
Этот маршрут существует только на loopback-сервере Chromium в Bun. Он добавляет
серверную авторизацию и обращается к локальному Nginx; пароль не входит в артефакт.
Студия в основном SPA использует обычный публичный endpoint и те же запросы/ключи кеша.
Production-настройки и SQL-миграция описаны в соседних `analytics-frontend-meta/README.md`
и `server-config/README.md`.

## Разработка и сборка

```bash
bun run dev     # основной SPA, студия на http://localhost:5173/meta
bun run test    # тесты совместимости ссылок compare
bun run check   # тесты и обе проверки типов
bun run build   # тесты, проверка типов, SPA в dist/ и meta-артефакт в dist-meta/
bun run preview # собранный основной SPA со студией на /meta
```

Команды, зависимости, lockfile и TypeScript-конфигурации общие с frontend.
Карточки разрабатываются через студию основного SPA. Отдельный dev-сервер или preview
renderer не нужен: собранное приложение запускает Bun backend.
`tsconfig.json` проверяет весь `src/`; `tsconfig.node.json` — `vite.config.ts`
с типами Bun. `check` запускает тесты и обе проверки типов; `build` вызывает его
один раз перед сборкой всех целей.

```text
vite.config.ts          # общий конфиг SPA, renderer и серверного модуля
package.json            # проверки и общая команда сборки
build-meta.sh           # сборка renderer, server.mjs и копирование spa.html
src/
├─ pages/
│  ├─ metaStudio/        # /meta и /meta/cards/:id основного SPA
│  ├─ debug/pages/meta/
│  │  ├─ Index.vue     # /debug/meta: переход в студию
│  │  └─ cards/        # debug-карточки delayed и vehicle с meta-definition.ts
│  └─ infographics/pages/vehicles/meta/
│     ├─ meta-definition.ts
│     └─ CompareMetaCard.vue
├─ shared/ui/meta/
│  ├─ components/
│  │  ├─ MetaCard.vue    # full, compact и compact-full
│  │  ├─ MetaCardBackground.vue # базовый слой и палитра подписей
│  │  ├─ MetaCardPattern.vue # точки, крестики, шум или SVG
│  │  ├─ backgrounds/    # отдельные Vue-компоненты фонов
│  │  ├─ assets/         # статические SVG-текстуры
│  │  └─ utils/
│  │     ├─ backgrounds.ts # каталог компонентов для студии
│  │     ├─ palette.ts   # цвета и локальный контекст палитры
│  │     ├─ pattern.ts   # общие props паттерна
│  │     └─ variants.ts  # тип компоновки карточки
│  ├─ contexts/
│  │  └─ vehicleNames.ts # общий контекст названий техники
│  └─ defaultMetaCard/
│     ├─ meta-definition.ts
│     └─ DefaultMetaCard.vue
└─ meta/
   ├─ renderer/
   │  ├─ index.html      # HTML-точка входа renderer
   │  ├─ main.ts         # монтирование App
   │  └─ App.vue         # полотно, context, prepare, ожидание готовности и reset
   ├─ utils.ts           # типы, форматы и чистые хелперы
   ├─ resolver.ts        # каталог и resolver; точка входа server.mjs
   ├─ context/           # типы контекстов, загрузка, запросы и адаптация для студии
   └─ cards/
      ├─ CardSurface.vue # выбор компонента и размер полотна
      └─ useMetaReady.ts # асинхронная готовность карточки
```

Команда `build` в `package.json` последовательно запускает `check`, сборку SPA в `dist/`
и `sh build-meta.sh` через `&&`: следующий этап выполняется только после успешного
завершения предыдущего. Скрипт собирает renderer в `dist-meta/client/`, серверный
модуль в `dist-meta/server.mjs` и копирует `dist/index.html` в `dist-meta/spa.html`.
`set -eu` останавливает скрипт при ошибке. Для отдельного запуска `sh build-meta.sh`
уже должен быть собран основной SPA.
Все цели используют корневой `vite.config.ts` с тремя конфигурациями верхнего уровня:
`mainConfig`, `metaRendererConfig` и `metaServerConfig`. Внутри конфигураций нет
условий выбора цели; в `defineConfig` остаётся только выбор нужного конфига.
Конфиг выбирается только по `BUILD_TARGET`: `main`, `meta-renderer` или `meta-server`.
Без переменной используется `main`; неизвестное значение останавливает запуск с ошибкой.
`dev` и `preview` используют `main` по умолчанию, а команда `build` последовательно
собирает `main`, `meta-renderer` и `meta-server`.
Серверная точка входа `build.ssr` задана непосредственно в `metaServerConfig`.
Режим `mode` остаётся `development` для разработки и `prod` для сборки.
Плагины Markdown, Vue DevTools и visualizer
подключаются только для основного SPA.
Неудачная сборка останавливает команду, её результат не публикуется.
Артефакт передаётся на сервер только после успешного завершения всей команды сборки.
Сборка `server.mjs` использует Vite SSR как режим упаковки модуля, без SSR страниц.
Точка входа — непосредственно `meta/resolver.ts`, который также экспортирует `formats`.
Glob раскрывается в статические импорты. Полученный модуль не зависит от Vue и DOM;
Bun загружает его при старте, создаёт клиент через `createDatabase(database)`
и передаёт его `query` в `createMetaResolver(query)`.
Контексты и их загрузчики включены в этот же `server.mjs`; отдельной сборки контекстов нет.

```text
dist/                   # основной SPA, включая асинхронную студию
dist-meta/
├─ server.mjs           # resolver, контексты, клиент запросов и форматы изображений
├─ spa.html             # копия dist/index.html той же сборки
└─ client/
   ├─ index.html        # только App для renderer
   └─ assets/           # карточки и их явные зависимости
```

Renderer не импортирует основной `App.vue`, его роутер или студию. Компоненты карточек
подключаются обычными импортами из `meta-definition.ts`. Каждый такой модуль содержит
`export default defineMetaDefinition({ ... })`. `CardSurface.vue` использует общий каталог
из `resolver.ts` и выбирает компонент по готовому `meta.definitionId`.
Определения собираются обычным Vite без специального преобразования. Код загрузчиков
контекстов может входить в renderer-бандл, но renderer не создаёт resolver и не запускает
эти загрузчики: метаданные ему передаёт Bun или страница студии/debug.
Собственные запросы Vue-карточек выполняются через `useMetaReady`.
Отдельного реестра и ограничения на имя `.vue`-файла нет.
Общие парсеры и компоненты можно импортировать обычным `@/…`; `public/` сайта
в renderer не копируется, поэтому ресурсы карточек импортируются явно.

При серверной сборке Vite-конфиг вместо Vue-плагина подключает один load-hook,
который заменяет содержимое `.vue`-модулей на
`export default {}`. Backend нужен только `hasImage`, поэтому наличие импорта сохраняется,
а код карточек, их CSS, ресурсы и зависимости даже не загружаются в серверную сборку.
Браузерные сборки компилируют эти же импорты обычным Vue-плагином.

## Общий дизайн карточек

`shared/ui/meta/components/MetaCard.vue` задаёт общий фон, отступы, цвета, шапку и подвал.
Он используется внутри компонента конкретной карточки; `CardSurface` продолжает отвечать
только за выбор компонента, размеры и готовность. `MetaCard` не зависит от URL или данных.
Оба формата — Open Graph 1200×630 и X / Twitter 1200×600 — используют одну компоновку.

У `variant` три значения (`MetaCardVariant` в `components/utils/variants.ts`):

- `full` (по умолчанию) — большой `title` и `subtitle` под ним, по вертикали в центре.
  В шапке — WotStat, в подвале — `footer` и wotstat.info.
- `compact` — `title` в компактной верхней полосе с разделителем, default-слот центрируется
  в свободной области между шапкой и подвалом.
- `compact-full` (Compact Full) — та же компактная шапка, но содержимое центрируется
  по всей высоте карточки независимо от шапки и подвала. Горизонтальные отступы сохраняются.

Типографику и предметные изображения слота задаёт специализация. Внутренний `.content-body`
служит контекстом позиционирования для абсолютных элементов слота, например изображения танка:
у `compact` он ограничен областью содержимого, у `compact-full` занимает всю высоту карточки.
Сравнение техники и обе debug-карточки используют `compact-full`.

`title` по умолчанию — WotStat Analytics. Необязательный `label` выводится справа в шапке.
Слот `title` заменяет текст заголовка в выбранном варианте; `subtitle` заменяет подзаголовок
варианта `full`. Default-слот заменяет центральное содержимое целиком, `footer` — весь подвал.

```vue
<MetaCard title="Статистика техники" subtitle="Динамика показателей и сравнение танков" />

<MetaCard variant="compact-full" label="Статистика техники" footer="Статистика. Динамика. Сравнение.">
  <VehicleComparison :vehicles />
</MetaCard>
```

Каждый фон — отдельный Vue-компонент в `components/backgrounds/`. По умолчанию карточка
рендерит `AuroraMistBackground` — вариант 09 «Сияние: дымка»: тёмную основу с мягким
бирюзовым и лиловым светом. Чтобы заменить фон, передай компонент через prop
`background: Component` или одноимённый слот. Слот имеет приоритет над prop.

```vue
<script setup lang="ts">
import MetaCard from '@/shared/ui/meta/components/MetaCard.vue'
import ContoursBackground from '@/shared/ui/meta/components/backgrounds/ContoursBackground.vue'
import AuroraMistBackground from '@/shared/ui/meta/components/backgrounds/AuroraMistBackground.vue'
import customPattern from '@/shared/ui/meta/components/assets/contours.svg?url'
</script>

<template>
  <MetaCard :background="ContoursBackground" title="Статистика техники" />

  <MetaCard title="Статистика техники">
    <template #background><AuroraMistBackground pattern="dots" /></template>
  </MetaCard>

  <MetaCard title="Статистика техники">
    <template #background><AuroraMistBackground :pattern="customPattern" pattern-size="cover" /></template>
  </MetaCard>
</template>
```

Слот позволяет настроить props фона или добавить произвольную разметку и изображения.
Общая и сравнительная карточки также принимают `background` и пробрасывают слот.
`MetaCard` импортирует только фон по умолчанию; каталог всех компонентов с названиями,
описаниями и стабильным порядком номеров находится в `components/utils/backgrounds.ts`
и используется студией. Добавление фона не требует изменений в `MetaCard`.

`MetaCardBackground.vue` — общий абсолютный слой на всё полотно с псевдоэлементами
для света и текстур. Конкретные фоны используют его как основу и задают `palette`.
Для своего CSS-фона можно передать в слот `<MetaCardBackground palette="teal" style="background: …" />`.
`VehiclesBackground` повторяет фон страницы «Статистика техники».
Паттерн — отдельный слой `MetaCardPattern`, а не разновидность фона. Все фоны принимают
общие props из `MetaCardPatternProps`: `pattern?: string` и `patternSize?: string`.
`pattern` выбирает `dots`, `crosses`, `noise` или строку с URL / содержимым `<svg>…</svg>`.
Для импортированного SVG используй `?url`; `none` отключает наложение.
`patternSize` принимает CSS-размер, например `28px 28px`, `80px` или `cover`.
Точки и крестики повторяются в исходном размере, свой SVG по умолчанию центрируется
и масштабируется через `cover`; явно заданный размер позволяет повторять свой SVG плиткой.
Шум использует `soft-light` без маски, остальные паттерны плавно проявляются к правому краю.
У сияний, медной орбиты и графитового фона по умолчанию остаётся шум; у рельефа,
диагональных полос и сетки дополнительное наложение не задано.
Статические SVG-текстуры находятся в `components/assets/`. Зерно фиксировано, фоны не анимируются.

Цвета переопределяются CSS-переменными `--meta-card-text` и `--meta-card-muted` на компоненте,
отступы — `--meta-card-padding`, размер крупного заголовка — `--meta-card-title-size`.
Вторичный текст использует светлый ненасыщенный непрозрачный оттенок, близкий к белому
и подобранный к фону: оливковый для зелёного
рельефа, голубой для стальных фонов, лавандовый для сияния, бирюзовый для холодного рельефа
и тёплый медный для `EmberBackground`. `palette` базового `MetaCardBackground` выбирает
цвет из `metaCardSecondaryColors` в `components/utils/palette.ts` и через локальный
provide/inject сообщает его родительской карточке. Палитра меняется вместе с компонентом
фона, в том числе внутри слота; `--meta-card-muted`
по-прежнему позволяет задать свой цвет поверх выбранной палитры.
Для `VehiclesBackground` используется более приглушённый голубой `slate`, чтобы вторичный текст
не конкурировал с основным заголовком на почти однотонном тёмном фоне.
Общая, сравнительная и обе debug-карточки используют этот компонент;
запросы данных и `useMetaReady` остаются в специализациях.

## Определения и выбор по URL

Создайте `meta-definition.ts` в любой вложенной директории `src/`. Ручной регистрации
нет: каталог автоматически импортирует `src/**/meta-definition.ts`. В каждом модуле
один default-экспорт вызова `defineMetaDefinition` с объектом определения.

```ts
import { defineMetaDefinition } from '@/meta/utils'
import Card from './Card.vue'

export default defineMetaDefinition({
  id: 'player',
  component: Card,
  priority: 100,
  match: (url: URL) => url.pathname === '/player',
  meta: (url: URL) => ({
    title: `Статистика ${url.searchParams.get('nickname') ?? 'игрока'}`,
    description: 'Статистика игрока WotStat',
    imageAlt: 'Карточка игрока',
  }),
  cache: { htmlSeconds: 300, imageSeconds: 3600 },
  name: 'Игрок',
  examples: [{ name: 'Пример', url: 'https://wotstat.info/player?nickname=Player' }],
})
```

`match` принимает точный pathname, `'*'` или синхронную функцию от полного URL.
Определения проверяются по убыванию `priority`. При равном приоритете порядок задан
по `id`, независимо от директории. Выбирается одно определение, без объединения
с менее приоритетными. Дубли `id` и отсутствие подходящего правила — ошибки.

`shared/ui/meta/defaultMetaCard` — обычное определение: `id: 'default'`, `match: '*'`,
`priority: -1000`. Отдельной логики fallback нет; его можно переопределить теми же
правилами приоритета. Compare имеет приоритет 100 и матчится на `/session/vehicles`
(включая завершающий `/`) с непустым после `trim()` параметром `compare`.
Без `compare` используется default. Пока обе карточки статические, compare —
заглушка с текстом о сравнении, без графиков и запросов статистики.

`meta` — объект или синхронная функция, возвращающая `title` и необязательные
`description`, `imageAlt`. Здесь разрешены быстрые вычисления из URL и контекста, но не сеть,
DOM или импорт browser-only модулей для вычисления метаданных. `cache` необязателен: по умолчанию HTML 300 с,
изображение 86400 с. `name`, `summary`, `examples` нужны только студии и тоже необязательны.

`component` — необязательный Vue-компонент, импортированный из `.vue` обычным
`import Card from './Card.vue'`. Имя файла и расположение произвольные; работают
относительные пути и алиас `@/…`. Определения — обычные TypeScript-модули:
можно использовать константы, spread и функции.
Модули определений и контекстов не должны выполнять запросы, запускать таймеры
или другие побочные действия при импорте: загрузка выполняется только внутри `load`.
Импорт определения не запускает подготовку метаданных; её запускает создание resolver.
Импорт карточки служит для рендера; вычисление `match` и `meta` не должно обращаться
к внутренним свойствам Vue-компонента, поскольку для backend он заменяется пустым объектом.

Для страницы без картинки достаточно такого определения:

```ts
import { defineMetaDefinition } from '@/meta/utils'

export default defineMetaDefinition({
  id: 'about',
  priority: 10,
  match: '/about',
  meta: { title: 'О WotStat Analytics' },
})
```

Такое правило не получает картинку или description из default. Студия показывает
текстовые метаданные и поле URL. Backend не добавляет image-теги, а запрос картинки
этой страницы возвращает 404 без обращения к Chromium.

## Контексты определений

Общие контексты сайта объявляются в `src/shared/ui/meta/contexts/`. Специфичный контекст можно
объявить прямо в `contexts` определения; его `load` также может быть импортированной
функцией. Все загрузчики работают без Vue, DOM и browser-only импортов.

```ts
import { defineMetaDefinition } from '@/meta/utils'
import { vehicleNames } from '@/shared/ui/meta/contexts/vehicleNames'

export default defineMetaDefinition({
  id: 'vehicle-title',
  priority: 100,
  match: '/vehicle',
  contexts: { vehicleNames },
  meta: (url, { vehicleNames }) => {
    const tag = url.searchParams.get('tag') ?? ''
    return { title: vehicleNames?.[tag] || tag || 'Название танка' }
  },
})
```

Объявление контекста содержит обязательные `id`, `initialWaitMs`,
`refreshIntervalMs` и `load({ query, signal })`. Загрузчик получает обычный `query`
из `src/db/client.ts`, с теми же параметрами и результатом `{ data, ... }`, что и сайт:

```ts
const { data } = await query<Row>(sql, {
  abortSignal: signal,
  cache: { ttl: 3600 },
  proxyCache: true,
})
```

`proxyCache: true` включает общий Nginx-кеш группы `public`; доступен обычный формат
политики `cache` из `db/cache`, локальный кеш, очередь и отмена запросов.
Конкретные ограничения задаёт сам загрузчик через `settings` и `abortSignal`.
Например, `vehicleNames` ограничивает запрос восемью секундами, выполнение в ClickHouse —
пятью секундами; SQL ограничивает количество возвращаемых строк.

Ключ в `contexts` становится именем значения во втором аргументе `meta`.
`defineMetaDefinition` выводит его тип из результата `load` и добавляет `undefined`.
Это функция для вывода типов: она возвращает исходное определение без копирования
объекта или обёртки над `meta`. Все определения, включая статические и определения
без картинки, используют этот же хелпер.
Значения общие для процесса, не зависят от URL и используются как неизменяемые снимки.
Нужную запись по URL выбирает сам `meta`; полный словарь в HTML и Chromium не передаётся.

- Все объявления собираются автоматически из определений. Один и тот же объект
  контекста можно использовать несколько раз; разные объявления с одинаковым `id`
  останавливают инициализацию до запуска загрузок.
- При создании resolver запускается прогрев всех контекстов. HTTP-запрос ждёт только
  зависимости выбранного определения, параллельно. Срок `initialWaitMs` считается
  от начала первого прогрева и не продлевается новыми запросами.
- `initialWaitMs: 0` отключает ожидание. По истечении срока запрос получает `undefined`
  для ещё не загруженных значений; загрузка продолжает выполняться.
- После завершения загрузки следующее обновление запускается через `refreshIntervalMs`.
  Загрузки одного контекста не пересекаются. Ошибка записывается в лог и сохраняет
  последнее успешное значение; при первой ошибке остаётся `undefined`.
- Перед синхронным вызовом `meta` собирается объект текущих значений всех его контекстов.
  Обновления заменяют значения целиком. `resolver.close()` отменяет загрузки,
  освобождает ожидающие запросы и останавливает таймеры.

В Bun resolver создаётся один раз при запуске. В студии он создаётся при первом
обращении к метаданным и живёт до закрытия страницы; обновления реактивно меняют
title и предпросмотр. Студия использует `public`, Bun — настройки `internal-public`
из окружения. В браузере используется существующий `query` из `@/db`, без второго
клиента или кеша. Объявления контекстов не содержат адресов сервера или паролей.

## Студия

`/meta/backgrounds` — подбор фона: сохранённые варианты 05–07, 09, 12 и 15, сохранённые
сочетания дымки с точками (16) и крестиками (18), увеличенное превью выбранного.
В превью можно выбрать паттерн: по умолчанию, без паттерна, точки, крестики, шум или SVG
с линиями рельефа. Для фонов со своей геометрией (рельеф и диагональные полосы)
переключатель скрыт. Доступны три компоновки: «Полный», «Компактный» и «Compact Full»
на настоящих default/compare-карточках, а также форматы Open Graph / X.
Исходные номера явно заданы в каталоге и сохраняются при удалении вариантов из подборки.
09 — затемнённая дымка на основе 06, 12 — рельеф со свечением, 15 — исходный фон статистики техники.
Выбор на этой странице не меняет фон карточек сайта. `CardSurface` и `ScaledCard`
предоставляют default-слот для таких превью, сохраняя размеры, типографику и протокол готовности.

`/meta` — каталог определений, `/meta/cards/:id` — редактор. Оба экрана загружаются
асинхронно из основного SPA. Превью — те же Vue-компоненты через `CardSurface`, без iframe.
Карточки доступны в боковой навигации и адаптивной сетке превью с подписями снизу. Общая URL-форма
находится в `Studio.vue` над содержимым страницы и остаётся смонтированной при
переключении между каталогом и редактором. Поле занимает доступную ширину,
кнопка «Посмотреть» находится рядом с ним на всех размерах экрана.
По Enter или кнопке форма открывает редактор определения, выбранного общим resolver,
и передаёт введённую ссылку в режим «Свой URL». В редакторе ввод также обновляет
превью сразу. Выбор примера расположен в заголовке карточки; текстовые теги и TTL — рядом с полотном.
Можно вставить полный URL и увидеть реально выбранное определение. Вкладка «В сервисах»
показывает сразу четыре превью — Telegram, Discord, Slack и X / Twitter — в адаптивной
сетке. Каждое подписано названием сервиса, сохраняет его фон и показывает отправленную
ссылку над карточкой. Переключателя сервисов и пояснения о приблизительном виде нет.
URL, пример и формат сохраняются в localStorage между перезагрузками.
Выбор вкладки «Карточка / В сервисах» также сохраняется. Старое сохранённое значение
`render` восстанавливается как `card`. Вкладка «Карточка» через `RenderPreview`
встраивает тот же `meta/renderer/App.vue` с параметром `embedded`,
масштабирует его до доступной ширины и вызывает зарегистрированный им `window.prepare`.
Вызов запускается при открытии режима, изменении URL или формата и по кнопке
«Перезапустить». Кнопка находится под полотном, над журналом последних десяти вызовов,
который показывает время завершения,
длительность, фактический URL и ошибки. При смене URL или формата студия отменяет
текущую подготовку через `AbortSignal` и запускает вызов с актуальными параметрами,
не дожидаясь асинхронной карточки. Отменённый вызов не попадает в журнал.
Если HMR отменил незавершённую подготовку при пересоздании компонента, просмотр
автоматически повторяет вызов с актуальным кодом. После ошибочного вызова следующий
hot update также повторяет подготовку. Успешные вызовы при HMR не перезапускаются:
обычные обновления шаблона, стилей и состояния остаются в ведении Vue.
Замер включает общий код подготовки карточки, Vue, шрифты, изображения и кадры отрисовки;
скриншот Chromium в него не входит. Логика `prepare` одинакова в студии и backend.
`useStudioState` создаёт общее состояние оболочки студии и редактора через `createGlobalState`,
восстанавливает настройки и сохраняет их через `useLocalStorage`.
Передача URL между экранами работает и без localStorage; редактор меняет поля `cardState` напрямую.
`ScaledCard` использует `useElementSize` для масштаба превью.

Изменения компонентов обновляются через Vite HMR. Добавление, удаление или правка
`meta-definition.ts` обновляет каталог через стандартный механизм Vite, без собственного
watcher. При перезагрузке страницы введённый URL сохраняется. Страница студии закрыта от индексации так же, как debug.

Стили компонентов находятся в `<style scoped lang="scss">` с вложенностью по структуре
компонента. `CardSurface` задаёт базовую типографику полотна для совпадения студии и renderer.
Глобальные правила HTML renderer находятся в `src/meta/renderer/App.vue`,
в отдельном блоке `<style lang="scss">` без `scoped`, под классом `html.meta-renderer`.
Встроенный режим не включает этот класс, не меняет URL или прокрутку студии
и показывает `CardSurface` внутри собственного полотна без полноэкранного позиционирования.

## Backend и prepare

`createMetaResolver(query)` возвращает `readMeta`, `resolveMeta`, `warmup` и `close`.
`warmup()` ждёт первоначальную готовность всех контекстов: успешную загрузку,
ошибку с предусмотренным fallback или истечение `initialWaitMs`. Периодические
обновления продолжаются независимо от завершения прогрева.
Bun явно создаёт один экземпляр общего DB-клиента через экспортированный
`createDatabase(database)` и передаёт его `query` в этот resolver.
Студия и debug-страницы используют `getBrowserMetaResolver()` с существующим
браузерным `query`. Создание остаётся ленивым. Обновления контекстов вызывают
`triggerRef`, чтобы эти страницы пересчитали метаданные и передали их в `RenderPreview`.
Renderer не импортирует браузерный resolver и не запускает загрузку контекстов.
`readMeta(URL)` синхронно читает текущие снимки; `await resolveMeta(URL)` сначала
дожидается первоначальной готовности нужных контекстов в пределах их сроков.
Оба возвращают `definitionId`, `hasImage`, текстовые метаданные и `cache`.
`server.mjs` также экспортирует размеры форматов. Backend загружает артефакт один раз
при старте; отдельной версии протокола и внедряемых глобальных констант нет.

Браузерная точка входа состоит из `main.ts` и `App.vue`. Первый только монтирует `App`.
Компонент владеет полотном, текущим `context` и внешним `prepare` и напрямую
рендерит `CardSurface` с этим context. Vue Router в renderer не используется.
В `onMounted` App регистрирует `window.prepare` и инициализирует ресурсы renderer.
В `onUnmounted` удаляет свой обработчик, отменяет незавершённую подготовку
и снимает класс глобального reset. Метод доступен после монтирования.
Ожидание Vue, шрифтов, изображений и кадров остаётся в App; асинхронную подготовку
сама карточка регистрирует через `useMetaReady`.

Пул Chromium открывает `/render` отдельного App. Вызов
`window.prepare({ url, format: 'og', meta })` принимает уже рассчитанные метаданные
от Bun, студии или debug-страницы и монтирует карточку с `context: { url, format, meta }`.
`meta` обязательна и в `prepare`, и в props `RenderPreview`; fallback без метаданных нет.
`prepare` проверяет наличие
изображения у выбранного определения, очищает предыдущий context и дожидается
размонтирования перед установкой нового. Отдельные маршруты карточек и счётчик заданий не нужны.
Встроенная студия дополнительно передаёт `signal`; renderer объединяет его с сигналом
своего жизненного цикла. Отмена снимает текущий `CardSurface`, поэтому `useMetaReady`
прерывает таймеры и запросы старой карточки.
`Promise<void>` завершается после подготовки карточки, обновления Vue, шрифтов,
изображений и двух animation frame.
Backend задаёт размер viewport из `formats` и после `prepare` делает PNG всей страницы.
Страница обслуживает одно задание за раз. `onErrorCaptured` перехватывает ошибки
дочерних Vue-компонентов; сбой карточки или загрузки изображения отклоняет `prepare`. Backend выбрасывает неисправную страницу из пула и создаёт новую.

Карточка без `useMetaReady` считается синхронной: ей не нужны событие готовности
или дополнительные настройки определения. Для асинхронной подготовки вызовите хук
в синхронном `setup` карточки:

```ts
import { useMetaReady } from '@/meta/cards/useMetaReady'

useMetaReady(async ({ signal }) => {
  data.value = await loadStatistics(props.context.url, { signal })
})
```

Callback запускается после монтирования. Он должен дождаться всей собственной работы,
включая асинхронную отрисовку графика, если она нужна. `CardSurface` через `provide/inject`
собирает Promise только своих экземпляров карточек и предоставляет `waitUntilReady()`.
App ждёт его, затем делает `nextTick` и обычную финальную подготовку изображения.
Ошибка callback отклоняет `prepare`. При размонтировании карточки её `signal` отменяется,
а ожидание отклоняется; используйте этот сигнал для отмены запросов и таймеров.
Хук работает и в обычных превью студии, где App отсутствует.

Карточка для URL `/debug/meta/delayed` и её определение лежат в
`src/pages/debug/pages/meta/cards/delayed/` и автоматически появляются в Meta Studio
как `debug-delayed` (`/meta/cards/debug-delayed`). На вкладке «Карточка» доступны App
и журнал `prepare`. Карточка показывает ожидание, через 5 секунд меняет текст на
«Карточка готова» и завершает хук. Метаданные по этому URL вычисляются синхронно;
задержка применяется только при рендере изображения. Кеш для этого определения выключен.

Внутренний Bun-сервер возвращает HTML renderer по `/render`, а отсутствующие assets дают 404.
Подготовка карточки не меняет адрес страницы. Параметр `embedded` управляет только
оформлением App; выбор карточки и ожидание готовности общие для обоих режимов.

## Nginx, кеш и обновления

Внешний Nginx раздаёт `/assets/` из общего каталога, а public-файлы — из `current`
(на диске эта ссылка указывает на `releases/<id>/dist`). HTML и
`og.wotstat.info/analytics/image.png` направляются через внутренний gateway
на активный blue/green meta. В Bun и gateway нет отдельного кеша HTML/PNG.

URL картинки содержит исходный путь, query, формат и версию `v` — общий ID
frontend-релиза из обязательного `dist-meta/release.json`. Он вычисляется при сборке
по всем файлам SPA и meta и используется также в dev. В production backend проверяет
его совпадение с ожидаемым `RELEASE_ID`. Старые версии PNG перенаправляются на актуальную
с `Cache-Control: no-store`.

HTML имеет `max-age` из определения, ограниченный backend сверху 300 секундами.
Ни Nginx, ни CDN не должны увеличивать этот срок или бессрочно выдавать stale HTML:
эта граница включена в срок хранения assets. Если gateway недоступен, внешний
Nginx возвращает локальный актуальный `index.html` с `200` и `no-store`.
Для PNG разрешён stale cache при ошибке upstream; при MISS возвращается ошибка PNG.
Отсутствующие assets по-прежнему дают 404, а не HTML.

Каждый процесс монтирует конкретный неизменяемый `dist-meta` релиза. Новый процесс
создаёт собственные контексты и Chromium; `/ready` подтверждает прогрев всего пула
и первоначальное ожидание контекстов. Перед активацией выполняется реальный рендер
общей карточки `/debug/deploy-smoke`, не зависящей от БД. Старый процесс продолжает
завершать запросы до ухода старых workers gateway, после чего останавливается.
При SIGTERM Bun сначала закрывает вход для новых соединений и дожидается принятых
запросов, затем освобождает resolver и Chromium. Общий предел завершения — 30 секунд.

Все контексты пересоздаются; значения не переносятся по id между версиями.
Resolver обязан экспортировать `warmup`; без него новый meta-процесс не запустится.

`dist`, `dist-meta` и манифест публикуются одной версией. Активная, предыдущая для
отката и ещё не истёкшие версии сохраняются; общие assets удаляются по ссылкам из
манифестов, а не по mtime. Подробнее — [деплой](01-overview.md#деплой).
