# Open Graph

Карточки и метаданные живут в обычном `src/` рядом со страницами сайта. Студия —
асинхронная страница основного SPA по `/meta`. Второе приложение, `App`, содержит
только renderer карточек для Bun backend. Общего отдельного проекта `meta/` нет.

Основной сайт остаётся SPA. Сервис `analytics-frontend-meta` добавляет мета-теги
в собранный `index.html`, а PNG получает отдельным запросом через Chromium.
Запрос HTML не запускает браузер и не ждёт загрузки статистики.

## Разработка и сборка

```bash
bun run dev     # основной SPA, студия на http://localhost:5173/meta
bun run test    # тесты совместимости ссылок compare
bun run check   # тесты и обе проверки типов
bun run build   # тесты, проверка типов, SPA в dist/ и meta-артефакт в dist-meta/
bun run preview # собранный основной SPA со студией на /meta
```

Команды, зависимости, lockfile и TypeScript-конфигурации общие с frontend.
Карточки разрабатываются через студию основного SPA. Отдельный dev-сервер или preview
renderer не нужен: собранное приложение запускает Bun backend.
`tsconfig.json` проверяет весь `src/`; `tsconfig.node.json` — `vite.config.ts`
с типами Bun. `check` запускает тесты и обе проверки типов; `build` вызывает его
один раз перед сборкой всех целей.

```text
vite.config.ts          # общий конфиг SPA, renderer и серверного модуля
package.json            # проверки и общая команда сборки
build-meta.sh           # сборка renderer, server.mjs и копирование spa.html
src/
├─ pages/
│  ├─ metaStudio/        # /meta и /meta/cards/:id основного SPA
│  ├─ debug/pages/meta/
│  │  ├─ Delayed.vue    # стенд /debug/meta/delayed
│  │  └─ cards/delayed/ # DelayedMetaCard.vue и meta-definition.ts
│  └─ infographics/pages/vehicles/meta/
│     ├─ meta-definition.ts
│     └─ CompareMetaCard.vue
└─ meta/
   ├─ renderer/
   │  ├─ index.html      # HTML-точка входа renderer
   │  ├─ main.ts         # монтирование App
   │  └─ App.vue         # полотно, context, prepare, ожидание готовности и reset
   ├─ utils.ts           # типы, форматы, каталог и resolver; точка входа server.mjs
   └─ cards/
      ├─ CardSurface.vue # выбор компонента и размер полотна
      ├─ useMetaReady.ts # асинхронная готовность карточки
      └─ defaultMetaCard/
         ├─ meta-definition.ts
         └─ DefaultMetaCard.vue
```

Команда `build` в `package.json` последовательно запускает `check`, сборку SPA в `dist/`
и `sh build-meta.sh` через `&&`: следующий этап выполняется только после успешного
завершения предыдущего. Скрипт собирает renderer в `dist-meta/client/`, серверный
модуль в `dist-meta/server.mjs` и копирует `dist/index.html` в `dist-meta/spa.html`.
`set -eu` останавливает скрипт при ошибке. Для отдельного запуска `sh build-meta.sh`
уже должен быть собран основной SPA.
Все цели используют корневой `vite.config.ts` с тремя конфигурациями верхнего уровня:
`mainConfig`, `metaRendererConfig` и `metaServerConfig`. Внутри конфигураций нет
условий выбора цели; в `defineConfig` остаётся только выбор нужного конфига.
Конфиг выбирается только по `BUILD_TARGET`: `main`, `meta-renderer` или `meta-server`.
Без переменной используется `main`; неизвестное значение останавливает запуск с ошибкой.
`dev` и `preview` используют `main` по умолчанию, а команда `build` последовательно
собирает `main`, `meta-renderer` и `meta-server`.
Серверная точка входа `build.ssr` задана непосредственно в `metaServerConfig`.
Режим `mode` остаётся `development` для разработки и `prod` для сборки.
Плагины Markdown, Vue DevTools и visualizer
подключаются только для основного SPA.
Неудачная сборка останавливает команду, её результат не публикуется.
Артефакт передаётся на сервер только после успешного завершения всей команды сборки.
Сборка `server.mjs` использует Vite SSR как режим упаковки модуля, без SSR страниц.
Точка входа — непосредственно `meta/utils.ts`, который также экспортирует `formats`.
Glob раскрывается в статические импорты. Полученный модуль не зависит от Vue и DOM;
Bun загружает его при старте, а `resolveMeta(URL)` работает синхронно.

```text
dist/                   # основной SPA, включая асинхронную студию
dist-meta/
├─ server.mjs           # resolver и форматы изображений
├─ spa.html             # копия dist/index.html той же сборки
└─ client/
   ├─ index.html        # только App для renderer
   └─ assets/           # карточки и их явные зависимости
```

Renderer не импортирует основной `App.vue`, его роутер или студию. Компоненты карточек
подключаются обычными импортами из `meta-definition.ts`. `CardSurface.vue` использует
`definition.component` напрямую: отдельного glob компонентов, реестра и ограничения
на имя `.vue`-файла нет. В renderer попадают только импортированные карточки и их зависимости.
Общие парсеры и компоненты можно импортировать обычным `@/…`; `public/` сайта
в renderer не копируется, поэтому ресурсы карточек импортируются явно.

При серверной сборке Vite-конфиг вместо Vue-плагина подключает один load-hook,
который заменяет содержимое `.vue`-модулей на
`export default {}`. Backend нужен только `hasImage`, поэтому наличие импорта сохраняется,
а код карточек, их CSS, ресурсы и зависимости даже не загружаются в серверную сборку.
Браузерные сборки компилируют эти же импорты обычным Vue-плагином.

## Определения и выбор по URL

Создайте `meta-definition.ts` в любой вложенной директории `src/`. Ручной регистрации
нет: каталог автоматически импортирует `src/**/meta-definition.ts`.

```ts
import type { MetaDefinition } from '@/meta/utils'
import Card from './Card.vue'

const playerMeta = {
  id: 'player',
  priority: 100,
  match: (url: URL) => url.pathname === '/player',
  meta: (url: URL) => ({
    title: `Статистика ${url.searchParams.get('nickname') ?? 'игрока'}`,
    description: 'Статистика игрока WotStat',
    imageAlt: 'Карточка игрока',
  }),
  component: Card,
  cache: { htmlSeconds: 300, imageSeconds: 3600 },
  name: 'Игрок',
  examples: [{ name: 'Пример', url: 'https://wotstat.info/player?nickname=Player' }],
} satisfies MetaDefinition

export default playerMeta
```

`match` принимает точный pathname, `'*'` или синхронную функцию от полного URL.
Определения проверяются по убыванию `priority`. При равном приоритете порядок задан
по `id`, независимо от директории. Выбирается одно определение, без объединения
с менее приоритетными. Дубли `id` и отсутствие подходящего правила — ошибки.

`defaultMetaCard` — обычное определение: `id: 'default'`, `match: '*'`,
`priority: -1000`. Отдельной логики fallback нет; его можно переопределить теми же
правилами приоритета. Compare имеет приоритет 100 и матчится на `/session/vehicles`
(включая завершающий `/`) с непустым после `trim()` параметром `compare`.
Без `compare` используется default. Пока обе карточки статические, compare —
заглушка с текстом о сравнении, без графиков и запросов статистики.

`meta` — объект или синхронная функция, возвращающая `title` и необязательные
`description`, `imageAlt`. Здесь разрешены быстрые вычисления из URL, но не сеть,
DOM или импорт browser-only модулей для вычисления метаданных. `cache` необязателен: по умолчанию HTML 300 с,
изображение 86400 с. `name`, `summary`, `examples` нужны только студии и тоже необязательны.

`component` — необязательный Vue-компонент, импортированный из `.vue` обычным
`import Card from './Card.vue'`. Имя файла и расположение произвольные; работают
относительные пути и алиас `@/…`. Определения — обычные TypeScript-модули:
можно использовать константы, spread и функции. Отдельного AST-парсера нет.
Импорт карточки служит для рендера; вычисление `match` и `meta` не должно обращаться
к внутренним свойствам Vue-компонента, поскольку для backend он заменяется пустым объектом.

Для страницы без картинки достаточно такого определения:

```ts
import type { MetaDefinition } from '@/meta/utils'

export default {
  id: 'about',
  priority: 10,
  match: '/about',
  meta: { title: 'О WotStat Analytics' },
} satisfies MetaDefinition
```

Такое правило не получает картинку или description из default. Студия показывает
текстовые метаданные и поле URL. Backend не добавляет image-теги, а запрос картинки
этой страницы возвращает 404 без обращения к Chromium.

## Студия

`/meta` — каталог определений, `/meta/cards/:id` — редактор. Оба экрана загружаются
асинхронно из основного SPA. Превью — те же Vue-компоненты через `CardSurface`, без iframe.
Карточки доступны в боковой навигации и адаптивной сетке превью с подписями снизу. Общая URL-форма
находится в `Studio.vue` над содержимым страницы и остаётся смонтированной при
переключении между каталогом и редактором. Поле занимает доступную ширину,
кнопка «Посмотреть» находится рядом с ним на всех размерах экрана.
По Enter или кнопке форма открывает редактор определения, выбранного общим resolver,
и передаёт введённую ссылку в режим «Свой URL». В редакторе ввод также обновляет
превью сразу. Выбор примера расположен в заголовке карточки; текстовые теги и TTL — рядом с полотном.
Можно вставить полный URL и увидеть реально выбранное определение. Вкладка «В сервисах»
показывает сразу четыре превью — Telegram, Discord, Slack и X / Twitter — в адаптивной
сетке. Каждое подписано названием сервиса, сохраняет его фон и показывает отправленную
ссылку над карточкой. Переключателя сервисов и пояснения о приблизительном виде нет.
URL, пример и формат сохраняются в localStorage между перезагрузками.
Выбор вкладки «Карточка / В сервисах» также сохраняется. Старое сохранённое значение
`render` восстанавливается как `card`. Вкладка «Карточка» через `RenderPreview`
встраивает тот же `meta/renderer/App.vue` с параметром `embedded`,
масштабирует его до доступной ширины и вызывает зарегистрированный им `window.prepare`.
Вызов запускается при открытии режима, изменении URL или формата и по кнопке
«Перезапустить». Кнопка находится под полотном, над журналом последних десяти вызовов,
который показывает время завершения,
длительность, фактический URL и ошибки. При смене URL или формата студия отменяет
текущую подготовку через `AbortSignal` и запускает вызов с актуальными параметрами,
не дожидаясь асинхронной карточки. Отменённый вызов не попадает в журнал.
Если HMR отменил незавершённую подготовку при пересоздании компонента, просмотр
автоматически повторяет вызов с актуальным кодом. После ошибочного вызова следующий
hot update также повторяет подготовку. Успешные вызовы при HMR не перезапускаются:
обычные обновления шаблона, стилей и состояния остаются в ведении Vue.
Замер включает общий код подготовки карточки, Vue, шрифты, изображения и кадры отрисовки;
скриншот Chromium в него не входит. Логика `prepare` одинакова в студии и backend.
`useStudioState` создаёт общее состояние оболочки студии и редактора через `createGlobalState`,
восстанавливает настройки и сохраняет их через `useLocalStorage`.
Передача URL между экранами работает и без localStorage; редактор меняет поля `cardState` напрямую.
`ScaledCard` использует `useElementSize` для масштаба превью.

Изменения компонентов обновляются через Vite HMR. Добавление, удаление или правка
`meta-definition.ts` обновляет каталог через стандартный механизм Vite, без собственного
watcher. При перезагрузке страницы введённый URL сохраняется. Страница студии закрыта от индексации так же, как debug.

Стили компонентов находятся в `<style scoped lang="scss">` с вложенностью по структуре
компонента. `CardSurface` задаёт базовую типографику полотна для совпадения студии и renderer.
Глобальные правила HTML renderer находятся в `src/meta/renderer/App.vue`,
в отдельном блоке `<style lang="scss">` без `scoped`, под классом `html.meta-renderer`.
Встроенный режим не включает этот класс, не меняет URL или прокрутку студии
и показывает `CardSurface` внутри собственного полотна без полноэкранного позиционирования.

## Backend и prepare

`resolveMeta(URL)` возвращает `definitionId`, `hasImage`, текстовые метаданные и `cache`.
`server.mjs` также экспортирует размеры форматов. Backend загружает артефакт один раз
при старте; отдельной версии протокола и внедряемых глобальных констант нет.

Браузерная точка входа состоит из `main.ts` и `App.vue`. Первый только монтирует `App`.
Компонент владеет полотном, текущим `context` и внешним `prepare` и напрямую
рендерит `CardSurface` с этим context. Vue Router в renderer не используется.
В `onMounted` App регистрирует `window.prepare` и инициализирует ресурсы renderer.
В `onUnmounted` удаляет свой обработчик, отменяет незавершённую подготовку
и снимает класс глобального reset. Метод доступен после монтирования.
Ожидание Vue, шрифтов, изображений и кадров остаётся в App; асинхронную подготовку
сама карточка регистрирует через `useMetaReady`.

Пул Chromium открывает `/render` отдельного App. Вызов
`window.prepare({ url, format: 'og' })` выбирает определение по переданному URL
и монтирует карточку с `context: { url, format, meta }`. `prepare` проверяет наличие
изображения у выбранного определения, очищает предыдущий context и дожидается
размонтирования перед установкой нового. Отдельные маршруты карточек и счётчик заданий не нужны.
Встроенная студия дополнительно передаёт `signal`; renderer объединяет его с сигналом
своего жизненного цикла. Отмена снимает текущий `CardSurface`, поэтому `useMetaReady`
прерывает таймеры и запросы старой карточки.
`Promise<void>` завершается после подготовки карточки, обновления Vue, шрифтов,
изображений и двух animation frame.
Backend задаёт размер viewport из `formats` и после `prepare` делает PNG всей страницы.
Страница обслуживает одно задание за раз. `onErrorCaptured` перехватывает ошибки
дочерних Vue-компонентов; сбой карточки или загрузки изображения отклоняет `prepare`. Backend выбрасывает неисправную страницу из пула и создаёт новую.

Карточка без `useMetaReady` считается синхронной: ей не нужны событие готовности
или дополнительные настройки определения. Для асинхронной подготовки вызовите хук
в синхронном `setup` карточки:

```ts
import { useMetaReady } from '@/meta/cards/useMetaReady'

useMetaReady(async ({ signal }) => {
  data.value = await loadStatistics(props.context.url, { signal })
})
```

Callback запускается после монтирования. Он должен дождаться всей собственной работы,
включая асинхронную отрисовку графика, если она нужна. `CardSurface` через `provide/inject`
собирает Promise только своих экземпляров карточек и предоставляет `waitUntilReady()`.
App ждёт его, затем делает `nextTick` и обычную финальную подготовку изображения.
Ошибка callback отклоняет `prepare`. При размонтировании карточки её `signal` отменяется,
а ожидание отклоняется; используйте этот сигнал для отмены запросов и таймеров.
Хук работает и в обычных превью студии, где App отсутствует.

`/debug/meta/delayed` — стенд с тем же App и журналом `prepare`. Его карточка и определение
лежат в `src/pages/debug/pages/meta/cards/delayed/` и автоматически появляются в Meta Studio
как `debug-delayed`. Карточка показывает ожидание, через 5 секунд меняет текст на
«Карточка готова» и завершает хук. Метаданные по этому URL вычисляются синхронно;
задержка применяется только при рендере изображения. Кеш для этого определения выключен.

Внутренний Bun-сервер возвращает HTML renderer по `/render`, а отсутствующие assets дают 404.
Подготовка карточки не меняет адрес страницы. Параметр `embedded` управляет только
оформлением App; выбор карточки и ожидание готовности общие для обоих режимов.

## Nginx, кеш и обновления

Nginx раздаёт статику сайта, направляет SPA fallback в backend с исходным путём и query,
а запрос `/_og/image.png` — туда же отдельно. Backend выставляет `Cache-Control` из
определения; ответы кеширует Nginx. В Bun нет отдельного кеша HTML/PNG.
URL картинки содержит исходный путь, query, формат и параметр версии `v`. Backend
вычисляет версию при старте как хеш `server.mjs` и `client/index.html`, содержащего
хешированные пути браузерных assets. Она меняется при изменении определений или
renderer, сохраняется при перезапуске с теми же файлами и не передаётся в браузер.
Старые версии перенаправляются на актуальную с `Cache-Control: no-store`.

При обновлении frontend передаётся полный `dist-meta/` через read-only volume,
затем backend перезапускается для импорта модуля и прогрева новых страниц.
`spa.html`, определения и browser assets должны относиться к одной сборке.
Если каталог заменяется через rename/symlink, контейнер пересоздают для обновления bind mount.
Перезапуск не сбрасывает кеш Nginx; старые SPA assets сохраняют на срок жизни HTML.
Команды сборки ничего не отправляют на сервер; CI и публикация настраиваются отдельно.
