# Формат `compare`

Модель — `timeSeriesCompare/query/state.ts`; весь кодек — `query/codec.ts`.
Его интерфейс — `serializeComparison(state, context?)` и `deserializeComparison(raw, context?)`.
Порядок полей, словари настроек, версия, сжатие и base64url находятся в этом файле.
Бинарные примитивы `Writer`/`Reader` — `shared/uiKit/queryStorage/utils/compactBinary.ts`: байты, unsigned LEB128,
строки UTF-8 и проверки границ. Они не знают о компактерах, игровых сущностях или структуре compare.
Там же находятся общие `compactMask`/`expandMask` для упаковки выборок из словарей в битовые маски.
Игровые значения преобразуются компактерами из `shared/game/encoding/{vehicles,arenas,battleModes}.ts`.
Текущая версия бинарного формата — 1. Новая несовместимая упаковка получает отдельную реализацию
с новой версией; словари упаковки остаются внутри соответствующего кодека.
Игровые компактеры не версионируются: постоянные словари дополняются только в конце,
архивные записи и старые индексы сохраняются. Один игровой ID всегда обозначает текущую сущность с этим ID,
даже если её тег или содержимое со временем изменились; исторические снимки каталогов не сохраняются.

## Контекст и отложенное разрешение

QueryStorage передаёт кодеку снимок шести фильтров страницы (`VehicleFilters`). Источники сохраняют
полные снимки своих фильтров; URL содержит только отличия от фильтров страницы.
Пустые регионы/режимы переопределяют непустой контекст и означают все регионы/режимы.
Без контекста (память вкладки) база не содержит ограничений, поэтому представление самодостаточно.
Без источников настройки сохраняются в памяти, а `compare` отсутствует в URL.
Пороги боёв/игроков, зум и период таблицы в модель не входят.
Defaults считаются постоянными; при переданном контексте значения наследуются из него.

Сохранённая модель допускает числовой ID танка и числовые ID карт в `filters.arenas`.
Потребитель вызывает `expand`/`expandMany` внутри обычного `computed` и получает полные теги
после загрузки каталогов. Неразрешённый токен сохраняется,
в UI показано состояние загрузки/ошибки; история источника до разрешения всех значений не запрашивается.
Загрузка каталогов сама по себе не пересериализует URL. Полные теги остаются корректными значениями;
при следующем изменении сравнения или его query-контекста кодек снова сокращает все источники
с учётом уже загруженных каталогов.

## Общая упаковка

`base64url(version + header + payload)` без padding. Первый байт — версия 1,
второй — заголовок. Версия и заголовок не сжимаются.
Бит 7 заголовка — raw DEFLATE, только если payload становится короче.
Биты 0/1 — настройки и отличия фильтров. Биты 2–5 — выключение первых четырёх источников;
бит 6 — дополнительная маска выключенных источников начиная с пятого. Источники идут до конца payload без счётчика.
Целые числа — unsigned LEB128 в пределах безопасных целых JS; строка — длина UTF-8 и байты.
Атом компактера — `number + 1`; ноль означает следующую полную строку. Список — количество и атомы.
Названия полей и сущностей в payload не записываются: порядок определяет кодек этой версии.

Ограничения: payload 256 КиБ, строка 256 байт, 1000 источников/элементов списка. Декодер проверяет
границы, значения, повторные источники, маски и окончание записи. Неизвестная версия и некорректная
ссылка сбрасываются QueryStorage к default. Прежний экспериментальный формат без версии не поддерживается.

## Игровые ID

Основа танка: `number * 16 + nationIndex`. Основа карты: число перед первым подчёркиванием тега.
При одном регионе источника флаг `HAS_REGION_FLAG` снят: ID равен `baseId * 2`, регион берётся из контекста. Кодек передаёт этот контекст компактеру при чтении и записи.
При смешанном/пустом выборе флаг `HAS_REGION_FLAG` установлен: `baseId * 32 + regionIndex * 2 + 1`. Биты 1..4 содержат регион, биты 5+ — ID.
Список регионов фиксирован в `shared/game/domain/regions.ts`; поле региона читается только при установленном `HAS_REGION_FLAG`.
Так `Ch62` в RU и WG восстанавливается в разные полные теги. Относительный ID без региона разрешается
лишь при однозначности во всём каталоге; неоднозначность выдаёт один warning, сохраняет токен и не выбирает случайный тег.
Суффиксные специальные варианты, неизвестные теги/префиксы и другие неразрешимые сокращения записываются полным тегом.

Короткие коды режимов, семейств и частых пар заданы явно в `encoding/battleModes/battleModeCodes.ts`
с проверкой покрытия известных доменных значений. Известные пары вне короткой таблицы —
`128 + pairCode * 16 + gameplayCode`: четыре бита геймплея и отдельный диапазон пар.
Неизвестные пары сохраняются полным нормализованным ключом, без `@`.

## Настройки

Первый байт секции настроек: биты 0–1 — день/неделя/месяц; биты 2–3 — сглаживание выключено/3/5/7;
бит 4 — далее метрика, бит 5 — далее аннотации. Defaults: средний урон, день, сглаживание и аннотации выключены.
Метрика — `baseMetricIndex * 16 + aggregationIndex + 1`; ноль — следующая строка.
Аннотации: байт видимости версий/патчей/микропатчей/недоступности (биты 0–3), бит 4 — далее список событий.

## Фильтры

Дескриптор 1–63 — маска единого набора отличий. Дескриптор 65+ — `64 + число наборов`, затем наборы.
В последнем случае ссылка 0 означает контекст, 1+ — соответствующий набор. Повторные наборы записываются один раз.
Биты маски 0–5: регионы, режимы, арены, взвод, результат, уровень боя.
Регионы — битовая маска; режимы и арены — списки атомов компактеров; остальные поля — индексы словарей.
При чтении региона он известен до чтения арен. При сравнении с контекстом разрешённые ID карт приводятся к полным тегам.

## Источники

Первое число задаёт цель и наличие дополнительных полей:

- 0 — следующий полный тег танка;
- 1–15 — уровень (с проверкой существования в игровом списке);
- 16–23 — класс (`16 + typeIndex`);
- 32–151 — уровень и класс (`32 + (level - 1) * 8 + typeIndex`);
- 152 — полный тег с дополнительными полями;
- 153 — следующий код категории с дополнительными полями;
- 154+ — танк: `(compactId + 77) * 2 + hasExtras`.

Числа в неиспользуемых диапазонах категорий отвергаются. Постоянный шаг 8 позволяет добавлять классы,
не меняя старые коды пар. Текущие обычные категории занимают один байт.
Из кода категории восстанавливаются `rowKey` и базовая выборка уровней/классов/наций.

Биты дополнительных полей: 0 — ссылка на фильтры, 1 — цвет, 2/3/4 — переопределение уровней/классов/наций категории.
Значения следуют в том же порядке. Маски выборки сохраняются только при отличии от базовой категории,
включая нулевую маску для снятия ограничения. У танка переопределения выборки запрещены.
Цвет `paletteIndex + 2`; 0/1 — следующие 3/4 байта RGB/RGBA. Альфа `ff` (полностью непрозрачный цвет)
не записывается: `#RRGGBBff` и `#RRGGBB` упаковываются одинаково. Альфа `00`–`fe` сохраняется.
Цвет по позиции источника пропускается.
Выключение первых четырёх источников хранится в заголовке и не добавляет байтов.
Если выключен источник начиная с пятого, перед источниками записываются длина и дополнительная битовая маска:
бит 0 первого байта соответствует пятому источнику. Нулевой хвост пропускается.
Нулевой бит означает включённый источник; без дополнительных битов/секции все источники включены.

## Примеры после загрузки каталогов

При стандартном контексте RU/random:

| Сравнение | compare | Символов |
| --- | --- | --- |
| ИС-7 | `AQDaFw` | 6 |
| ИС-7, линия выключена | `AQTaFw` | 6 |
| ИС-7 + Объект 261 | `AQDaF5ob` | 8 |
| ИС-7 на Прохоровке | `AQIEAQvaFw` | 10 |
| Ch62 в RU и Ch62 в EU | `AQJBAQKmIKcgAQE` | 15 |
| Ch62_ZZT_58 с фильтром RU + EU | `AQIBA9zyAw` | 10 |
| X уровень, тяжёлые | `AQBo` | 4 |

Ручной стенд `/debug/game/compact` показывает преобразования игровых значений,
длины типовых сравнений и восстановленные модели.

Замер альтернативных форматов: [game-encoding-size-comparison.md](game-encoding-size-comparison.md).
