# Параметры сравнения

Модель — `timeSeriesCompare/query/state.ts`; кодек — в папке `query/codec/`.
Его интерфейс — `serializeComparison(sources, context?)` и `deserializeComparison(raw, context?)`.
Кодек принимает и возвращает массив `SavedComparisonSource[]`, без настроек графика.
`codec.ts` задаёт версию и заголовок и синхронно декодирует ссылку без БД, Vue и браузерного окружения.
`serialize.ts` записывает ссылку с прежним сокращением тегов через браузерные каталоги.
Общие служебные файлы чтения и записи собраны в `query/codec/utils/`:
`filters.ts` реализует отличия от контекста и таблицу фильтров,
`sources.ts` — цели, выборки и видимость, `colors.ts` — нормализацию и упаковку цветов,
`limits.ts` — ограничения размера.
Бинарные примитивы `Writer`/`Reader` — `shared/utils/encoding/compactBinary.ts`: байты, unsigned LEB128, маски `bitset`,
строки UTF-8, атомы `number | string`, списки и проверки границ. Ограничения задаёт кодек.
Они не знают о компактерах, игровых сущностях или структуре compare.
Там же находятся общие `compactMask`/`expandMask` для упаковки выборок из словарей в битовые маски.
Общие Base62 и ограниченная распаковка raw DEFLATE находятся в соседних `base62.ts` и `deflate.ts`.
При записи игровые значения преобразуются компактерами из `shared/game/encoding/`,
которые передаются функциям записи фильтров и источников. Декодер проверяет форму токенов
без каталогов и сохраняет числовые ID для последующего разрешения потребителем.
Текущая версия бинарного формата — 1. Поддерживается одна актуальная реализация,
без миграций экспериментальных форматов; словари упаковки остаются внутри кодека.
Игровые компактеры не версионируются: постоянные словари дополняются только в конце,
архивные записи и старые индексы сохраняются. Один игровой ID всегда обозначает текущую сущность с этим ID,
даже если её тег или содержимое со временем изменились; исторические снимки каталогов не сохраняются.

## Контекст и отложенное разрешение

QueryStorage передаёт кодеку снимок шести фильтров страницы (`VehicleFilters`). Источники сохраняют
полные снимки своих фильтров; URL содержит только отличия от фильтров страницы.
Пустые регионы/режимы переопределяют непустой контекст и означают все регионы/режимы.
Без контекста (память вкладки) база не содержит ограничений, поэтому представление самодостаточно.
Без источников `compare` отсутствует в URL. Настройки графика сохраняются отдельными query-параметрами.
Пороги боёв/игроков, зум и период таблицы в модель не входят.
Defaults считаются постоянными; при переданном контексте значения наследуются из него.

Сохранённая модель допускает числовой ID танка и числовые ID карт в `filters.arenas`.
Потребитель вызывает `expand`/`expandMany` внутри обычного `computed` и получает полные теги
после загрузки каталогов. Неразрешённый токен сохраняется,
в UI показано состояние загрузки/ошибки; история источника до разрешения всех значений не запрашивается.
Загрузка каталогов сама по себе не пересериализует URL. Полные теги остаются корректными значениями;
при следующем изменении сравнения или его query-контекста кодек снова сокращает все источники
с учётом уже загруженных каталогов.

## Общая упаковка

`base62(header + payload)`, алфавит `0123456789ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz`.
Байты трактуются как одно беззнаковое big-endian число, которое записывается в системе счисления с основанием 62.
Общая утилита сохраняет каждый ведущий нулевой байт отдельным символом `0`; пустой массив — пустая строка.
У compare первый байт ненулевой, поэтому такой префикс не используется. Padding и пунктуации нет.
Один символ не соответствует фиксированной группе битов; границы полей видны после восстановления байтов.
Преобразование больших чисел делится на половины, малые части обрабатываются безопасными целыми JS.
Декодер ограничивает длину строки до преобразования и итоговое число байтов до выделения массива.
Base64url больше не читается и не определяется автоматически.

Один байт заголовка остаётся вне сжатия:
`VV Z M D2 D1 F D3` от старшего бита к младшему.
Биты 6–7 — версия: текущая `01`, коды `00`/`10` доступны для других коротких версий,
`11` зарезервирован для расширения — следующего unsigned LEB128 с полным номером версии (3+), тоже вне сжатия.
Текущий декодер принимает только `01`; неизвестные короткие и расширенные версии отвергаются.
Бит 5 — raw DEFLATE, только если payload становится короче.
Бит 0 — выключение третьего источника, бит 1 — отличия фильтров. Биты 2–3 — выключение первых двух источников;
бит 4 — дополнительная маска выключенных источников начиная с четвёртого. Источники идут до конца payload без счётчика.
Целые числа — unsigned LEB128 в пределах безопасных целых JS; строка — длина UTF-8 и байты.
Атом компактера — `number + 1`; ноль означает следующую полную строку. Список — количество и атомы.
Названия полей и сущностей в payload не записываются: порядок определяет кодек этой версии.

Ограничения: payload 256 КиБ, строка 256 байт, 1000 источников/элементов списка. Декодер проверяет
границы, значения, повторные источники, маски и окончание записи. Неизвестная версия и некорректная
ссылка сбрасываются QueryStorage к default. Прежние экспериментальные форматы,
в том числе с отдельным байтом версии, не поддерживаются.

## Игровые ID

Основа танка: `number * 16 + nationIndex`. Основа карты: число перед первым подчёркиванием тега.
При одном регионе источника флаг `HAS_REGION_FLAG` снят: ID равен `baseId * 2`, регион берётся из контекста. Кодек передаёт этот контекст компактеру при чтении и записи.
При смешанном/пустом выборе флаг `HAS_REGION_FLAG` установлен: `baseId * 32 + regionIndex * 2 + 1`. Биты 1..4 содержат регион, биты 5+ — ID.
Список регионов фиксирован в `shared/game/domain/regions.ts`; поле региона читается только при установленном `HAS_REGION_FLAG`.
Так `Ch62` в RU и WG восстанавливается в разные полные теги. Относительный ID без региона разрешается
лишь при однозначности во всём каталоге; неоднозначность выдаёт один warning, сохраняет токен и не выбирает случайный тег.
Суффиксные специальные варианты, неизвестные теги/префиксы и другие неразрешимые сокращения записываются полным тегом.

Короткие коды режимов, семейств и частых пар заданы явно в `encoding/battleModes/battleModeCodes.ts`
с проверкой покрытия известных доменных значений. Известные пары вне короткой таблицы —
`128 + pairCode * 16 + gameplayCode`: четыре бита геймплея и отдельный диапазон пар.
Неизвестные пары сохраняются полным нормализованным ключом, без `@`.

## Настройки графика

Определения находятся в `query/settings.ts`, отдельно от бинарного кодека. Шаг и усреднение
используют `oneOfParam`; метрика преобразуется между внутренним `Slot` и URL-ключом в kebab-case.
Значения по умолчанию исключаются из URL.

| Параметр | Значения | Default |
| --- | --- | --- |
| `metric` | Ключи из `availableSlots` в kebab-case: `damage`, `winrate`, `damage-q50`, `damage-per-life-minute-q50`, `mastery-p99`, `marks-p95` | `damage` |
| `step` | `day`, `week`, `month` | `day` |
| `avg` | `3`, `5`, `7` | `null` — усреднение выключено, параметр отсутствует |

Пример: `metric=winrate&step=week&avg=3&compare=HpeZ`.
Планки API имеют фиксированные ключи с префиксом `mastery-` и суффиксами
`p1`/`p5`/`p10`/`p25`/`p50`/`p75`/`p80`/`p90`/`p95`/`p99`/`p100`; для `marks-` —
`p0`/`p20`/`p40`/`p55`/`p65`/`p75`/`p85`/`p95`/`p100`. В коде используются единообразные
идентификаторы `mastery_p99`, `marks_p95`, как у `damage_q95`. Бинарный формат `compare` не меняется.
Общий сериализатор метрик находится в `vehicleMetricSelector/utils/slotSerializer.ts` и также
используется для выбранных столбцов и сортировки таблицы. URL-ключи строятся из существующего
каталога метрик: границы camelCase и `_` заменяются дефисами,
буквы переводятся в нижний регистр. Обратное преобразование использует таблицу известных ключей;
коллизии проверяются при её создании. Внутри графика остаются прежние `Slot` (`damagePerLifeMinute_q50` и т.п.).
Максимальный вид содействия — `maxAssist`, в URL — `max-assist`, его агрегации —
`max-assist-q50`, `max-assist-max` и т.д. Ключ `assist-max` обозначает `assist_max`.
Старые query-значения с `_` или заглавными буквами не поддерживаются.
Ключи памяти: `vehicles.compare.metric`, `vehicles.compare.step`, `vehicles.compare.averageWindow`.
Владелец — `useVehicleComparison`, запись — replace с debounce 150 мс. Настройки сохраняются
в памяти без источников, но `metric`, `step` и `avg` записываются в URL только при непустом составе сравнения.
Условие задано через `context: { compare }` и `enabled` в `useVehicleComparison`;
параметры появляются и исчезают вместе с `compare`. Танки, категории и выключенные линии
считаются источниками. Неизвестное значение сбрасывает только свой параметр к default;
источники и остальные настройки сохраняются. Истории раскрытых строк таблицы имеют собственные настройки.
Бинарная секция настроек, её маска, флаг заголовка и словари метрик/агрегаций удалены.
Старые ссылки с настройками внутри `compare` не мигрируются.

## Аннотации

Отдельный читаемый параметр: `annotations=versions,patches,razvorot`.
Определение `query/annotations.ts` использует стандартный `setOfParam`; в памяти это Set ключей,
для графика он преобразуется в `HistoryAnnotationState`. Ключ памяти — `vehicles.compare.annotations`,
запись — replace с debounce 150 мс. Пустой набор исключается из URL.

| Ключ | Аннотация |
| --- | --- |
| `versions` | Версии игры |
| `patches` | Патчи |
| `micropatches` | Микропатчи |
| `wotstat-outages` | Недоступность wotstat |
| ID из `historyEvents` | Историческое событие: `razvorot`, `stun-removal`, `bops-removal` и новые записи каталога |

Повторы удаляются. Неизвестный ключ отвергает весь параметр, QueryStorage применяет пустой default.
При записи из меню сначала идут типы аннотаций в порядке таблицы, затем события в порядке каталога.
Переключение аннотаций не меняет `compare`. Параметр записывается в URL только при наличии
источников сравнения; при пустом составе выбранные аннотации остаются в памяти.
Аннотации отдельных раскрытых строк таблицы по-прежнему имеют собственное локальное состояние.
Бинарные флаг аннотаций, маска видимости, счётчик и атомы событий удалены. Миграции старых ссылок нет.

## Фильтры

Дескриптор 1–63 — маска единого набора отличий. Дескриптор 65+ — `64 + число наборов`, затем наборы.
В последнем случае ссылка 0 означает контекст, 1+ — соответствующий набор. Повторные наборы записываются один раз.
Каждый набор упаковывается до дедупликации, затем готовые байты дописываются в payload без повторной упаковки.
Биты маски 0–5: регионы, режимы, арены, взвод, результат, уровень боя.
Регионы — битовая маска; арены — список атомов компактеров; остальные поля — индексы словарей.
Первый байт режимов 0–127 — маска постоянных кодов компактера 0–6:
`random`, `onslaught`, `random-standard`, `random-domination`, `random-assault`, `epic-battle`, `frontline`.
Нулевая маска означает пустой выбор (все режимы). Если есть режим вне маски, записывается список атомов:
первый байт 128–254 задаёт длину 1–127 (`byte - 127`), байт 255 — следующую длину unsigned LEB128 (128–1000).
Полные ключи неизвестных режимов сохраняются через строковые атомы.
При чтении региона он известен до чтения арен. При сравнении с контекстом разрешённые ID карт приводятся к полным тегам.

## Источники

Первое число задаёт цель и наличие дополнительных полей:

- 0 — следующий полный тег танка;
- 1–15 — уровень (с проверкой существования в игровом списке);
- 16–23 — класс (`16 + typeIndex`);
- 32–151 — уровень и класс (`32 + (level - 1) * 8 + typeIndex`);
- 152 — полный тег с дополнительными полями;
- 153 — следующий код категории с дополнительными полями;
- 154+ — танк: `(compactId + 77) * 2 + hasExtras`.

Числа в неиспользуемых диапазонах категорий отвергаются. Постоянный шаг 8 позволяет добавлять классы,
не меняя старые коды пар. Текущие обычные категории занимают один байт.
Из кода категории восстанавливаются `{ level?, type? }` и базовая выборка уровней/классов/наций.
Строковый `rowKey` вычисляет потребитель модели для таблицы; кодек его не разбирает и не сохраняет.

Дополнительные поля начинаются с unsigned LEB128 `filterRef * 16 + flags`.
У категории младшие четыре бита: 0 — цвет, 1/2/3 — переопределение уровней/классов/наций.
У танка младшие четыре бита — тип цвета: 0 — по позиции, 1 — индекс палитры, 2 — RGB, 3 — RGBA;
значения 4–15 пока запрещены. Тип не занимает отдельный байт.
Номер набора фильтров хранится в старших битах, отдельно не записывается. Ссылки 0–7 вместе с флагами занимают один байт.
При едином наборе фильтров разрешена только ссылка 0. Далее идут цвет и маски выборки в порядке флагов.
Маски выборки сохраняются только при отличии от базовой категории,
включая нулевую маску для снятия ограничения. У танка переопределения выборки запрещены.
После типа 1 у танка идёт индекс палитры (0–65535), после типа 2/3 — следующие 3/4 байта RGB/RGBA.
У категории цвет сохраняет отдельный код: `paletteIndex + 2`; 0/1 — следующие 3/4 байта RGB/RGBA.
Перед записью hex приводится к нижнему регистру; альфа `ff` удаляется. Совпадение с цветом по позиции
источника пропускается (включая вычисляемые цвета после первых десяти), с другим цветом постоянной
палитры — заменяется его индексом. Поэтому выбор того же цвета через пикер не удлиняет ссылку.
Альфа `00`–`fe` и все каналы произвольного цвета сохраняются точно, без округления.
Выключение первых трёх источников хранится в заголовке и не добавляет байтов.
Если выключен источник начиная с четвёртого, перед источниками записывается дополнительная битовая маска:
семь бит в байте, старший бит — продолжение, отдельной длины нет. Бит 0 первого байта соответствует четвёртому источнику,
бит 0 второго — одиннадцатому. Нулевой хвост пропускается; пустая дополнительная маска и выключение отсутствующих источников отвергаются.
Запись выполняет общий `Writer.bitset`; `Reader.bitset` ограничивает число битов и проверяет окончание записи;
недостающие биты, включая отброшенный нулевой хвост, означают `false`.
Нулевой бит означает включённый источник; без дополнительных битов/секции все источники включены.

## Примеры после загрузки каталогов

При стандартном контексте RU/random, после перехода с Base64url на Base62.
В обеих колонках длины сравниваются одни и те же байты, поэтому разница относится только к внешнему алфавиту.

| Сравнение | compare (Base62) | Base64url, символов | Base62, символов |
| --- | --- | ---: | ---: |
| ИС-7 | `HpeZ` | 4 | 4 |
| ИС-7, цвет `#0A84FFFF` (стандартный) | `HpeZ` | 4 | 4 |
| ИС-7, цвет `#ff9f0a` (второй в палитре) | `4u3KcaX` | 7 | 7 |
| ИС-7, цвет `#123456` | `1LbmchlBby` | 10 | 10 |
| ИС-7, цвет `#12345680` | `5ZE0ltNVBzs` | 11 | 11 |
| ИС-7, `metric=winrate` | `HpeZ` | 4 | 4 |
| ИС-7, `metric=blocked` | `HpeZ` | 4 | 4 |
| ИС-7, `metric=damage-q50` | `HpeZ` | 4 | 4 |
| ИС-7, линия выключена | `Ivqh` | 4 | 4 |
| ИС-7 + Объект 261 | `4u2COGR` | 7 | 7 |
| ИС-7 на Прохоровке | `KbtjnP8R` | 8 | 8 |
| Ch62 в RU и Ch62 в EU | `NUB1c0pL8tV2` | 12 | 12 |
| Ch62_ZZT_58 с фильтром RU + EU | `KbfizxPH` | 8 | 8 |
| X уровень, тяжёлые | `4Hw` | 3 | 3 |
| ИС-7, случайные и Натиск одной линией | `4zSC1YN` | 7 | 7 |
| ИС-7, случайные и Натиск разными линиями | `NUB2u0HV7XSi` | 12 | 12 |
| Уровни VIII–X, третья линия выключена | `1BpuoM` | 6 | 6 |
| Уровни VII–X, четвёртая линия выключена | `Oyg6pL0k` | 8 | 8 |
| Неразрешённые ID и полный тег (пример стенда) | `1BebBqeuZb72vUZoz7hpurJhy1AwRBJVBUjN1t8AwFKfazt3N` | 48 | 49 |

Ручной стенд `/debug/game/compact` показывает преобразования игровых значений,
длины типовых сравнений в Base62/Base64url, разницу, отдельные параметры графика и восстановленные модели.
Изменение метрики, шага, усреднения и аннотаций не меняет `compare` для тех же источников.
Длины в таблице относятся только к бинарному параметру, без читаемых настроек графика.
Теоретическая потеря плотности Base62 относительно Base64 — около 0,77% на длинных данных,
на коротких длина зависит от значения числа и округления до целого количества символов.

Замер альтернативных форматов: [game-encoding-size-comparison.md](game-encoding-size-comparison.md).

## Тест совместимости перед публикацией

`bun run test` запускает [codec.test.js](../src/pages/infographics/pages/vehicles/timeSeriesCompare/query/codec/codec.test.js)
встроенным раннером Bun без дополнительных зависимостей. В [codec.fixtures.json](../src/pages/infographics/pages/vehicles/timeSeriesCompare/query/codec/codec.fixtures.json)
сохранены 307 примеров текущего формата. Строки и ожидаемые модели фиксированы и не вычисляются кодеком во время теста.
`bun run build` запускает этот тест перед `vue-tsc` и Vite. При нарушении совместимости команда завершается с ошибкой, не переходя к сборке.

Каждый пример содержит:

- `compare` — значение бинарного query-параметра; домен и путь страницы на кодек не влияют;
- `context` — полный внешний контекст фильтров; отсутствие поля проверяет вызов без контекста;
- `sources` — точный ожидаемый JSON после декодирования и вход для повторной записи той же строки;
- `input` — необязательный исходный ввод с полными тегами, hex-цветами или ненормализованными наборами;
- `colors` — ожидаемые hex-цвета источников, включая цвета, заданные индексом палитры.

Проверяются прежние примеры со стенда, все текущие короткие коды режимов, компоненты общих пар,
регионы, нации, классы, уровни, значения фильтров, цвета, видимость, таблица фильтров и DEFLATE.
Компактеры, словари, палитра и бинарные утилиты используются настоящие. Только внешние каталоги
заменены небольшими постоянными наборами `catalogs` из того же JSON; теги с `Fixture` — синтетические
записи для проверки кодов наций и регионов. Тест не обращается к ClickHouse и не требует браузера.

При падении сначала проверяй совместимость изменения с сохранёнными ссылками. Не обновляй эталоны,
чтобы просто сделать тест зелёным: дополняй их новыми случаями, а существующие меняй только при
осознанном изменении формата. Метрика, шаг, усреднение и аннотации находятся вне бинарного `compare`
и этим тестом не покрываются.
