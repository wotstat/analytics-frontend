# Реактивные параметры URL

`src/shared/uiKit/queryStorage/useQueryStorage.ts` — общий механизм для параметров страниц.
`setupQueryStorage(router, history)` подключается в `routes.ts` до первой навигации,
где `history` — результат `createDeferredWebHistory()` из `shared/uiKit/queryStorage/utils/`.
Один координатор на роутер объединяет записи и следит за временем жизни владельцев.

`setupQueryStorage` возвращает координатор с read-only `readyRoute`. Во время навигации,
смены владельцев и синхронизации query значение равно `null`. После обработки текущих
изменений в естественном цикле координатор публикует актуальный маршрут роутера.
Наблюдение этого сигнала ничего не запускает, не вызывает `flush`, не ускоряет debounce
и не меняет порядок записи browser history. Будущие изменения с отложенной записью
не удерживают сигнал готовности: локальные refs уже содержат их актуальные значения.
Сигнал описывает параметры; монтирование асинхронных страниц отдельно учитывает
`shared/uiKit/pageNavigation/pageNavigation.ts`. Мета использует объединённую готовность.

Ядро находится в `src/shared/uiKit/queryStorage/`: публичный API `useQueryStorage.ts`,
координатор `utils/queryStorageCoordinator.ts`, обработка определений и значений в `utils/queryParamUtils.ts`
и типы `queryStorageTypes.ts`. Связанная реализация `utils/createDeferredWebHistory.ts` находится рядом,
внутри того же модуля: она управляет общим циклом синхронизации и отложенной записью browser history.
Координатор управляет состоянием, владельцами, навигацией и записью URL;
utils получает defaults, сериализует/десериализует значения, собирает контекст из query и проверяет определения.
Ядро зависит только от Vue и Vue Router и не содержит описаний параметров страниц.
Общие фильтры старой инфографики (`statQueryParams.ts`) и адаптер `useQueryStatParams.ts`
находятся в `src/shared/legacyStatQuery/`: это слой совместимости с существующими потребителями,
включая `StatParams`, SQL и выбор кеша. Он уже использует универсальный `useQueryStorage` внутри.
Новые страницы объявляют собственные параметры; параметры Натиска, выстрелов и сравнения версий
находятся рядом со своими страницами. Стенд `/debug/query-storage` использует собственные определения параметров.

```ts
import { queryStorageSync, useQueryStorage } from '@/shared/uiKit/queryStorage/useQueryStorage'

const storage = useQueryStorage({
  nickname: { type: String, default: '', debounce: 1000 },
  season: { type: String, default: null, history: 'push' },
  selection: { type: String, label: 'tank', key: 'example.tank' }
}, { history: 'replace', debounce: 0 })

const { nickname, season } = storage.params
nickname.value = 'SomePlayer'
queryStorageSync(() => {
  nickname.value = 'AnotherPlayer'
  season.value = 'season-id'
})
storage.patch({ nickname: '', season: 'season-id' }, { history: 'push', debounce: 0 })
await storage.flush()
await storage.flush('nickname')
```

## Объявление и типы

- Inline-объявление — основной вариант. Необязательный `defineParams({ ... })`
  сохраняет типизированное описание для повторного использования; сам состояние не создаёт.
- Имя в URL: `label ?? имя свойства`. Ключ памяти: `key ?? имя в URL`.
  Одинаковые ключи разделяют состояние между любыми активными компонентами.
- `priority` задаёт порядок в URL: по умолчанию `0`, большее число ставит параметр раньше.
  При одинаковом приоритете параметры сортируются по имени в URL (`label`) по алфавиту
  с фиксированной локалью `en`. Неизвестные QueryStorage параметры сохраняются с приоритетом `0`.
  Приоритет относится к активному объявлению, а не общему ключу памяти; если один label
  объявлен несколькими активными владельцами, используется наибольший приоритет.
  Сортируется готовый query после сериализации всех значений, поэтому порядок обработки `context` не меняется.
- `params` содержит записываемые refs, деструктуризация сохраняет реактивность.
- `type: String | Number | Boolean` задаёт встроенный формат. Без `type` примитив
  также может определяться по default. Boolean записывается как `1`/`0`.
- Без default отсутствующее значение — `undefined`. `null` допустим, например
  `{ type: String, default: null }` даёт `Ref<string | null>`.
- Default можно задавать напрямую, в том числе массивом, объектом, Date или Set:
  QueryStorage получает отдельную глубокую копию через `structuredClone` при создании записи,
  сбросе, обработке некорректного URL и чтении контекста. Мутации модели не меняют исходный
  default и сохранённый эталон для исключения из URL. Значение должно поддерживать `structuredClone`;
  для динамических defaults или особого создания экземпляров остаётся фабрика, результат которой
  не копируется: она сама должна возвращать новый экземпляр. Для простых объектов
  доступен JSON; Date, Set и компактные форматы используют `serialize`/`deserialize`.
  Десериализатор должен бросить ошибку для некорректного значения: тогда применяется default.
- Сериализатор детерминированный; равенство default проверяется по сериализованному
  представлению. Default исключается из URL. Остальные `0`, `false`, пустые строки
  сохраняются, если отличаются от default. `undefined` всегда означает отсутствие.
- Повторные объявления общего ключа обязаны совпадать по типу, default и функциям
  кодека и определениям зависимостей `context`. Для общего нестандартного формата переиспользуйте одни функции, например
  через `defineParams`. Несовместимое объявление и одновременный одинаковый label
  у разных ключей вызывают понятную ошибку.

## Стандартные сериализаторы

`shared/uiKit/queryStorage/serializers/` содержит отдельный файл для каждого сериализатора,
общие типы находятся в `types.ts`. Импорты идут напрямую из соответствующих файлов.
`Serializer<T>` задаёт только `serialize(value: T) → string` и `deserialize(raw: string) → T`.
Default, label, key, priority, context, enabled, debounce и history задаются в определении параметра.
Для готового определения используйте фабрики из `shared/uiKit/queryStorage/params.ts`, описанные ниже.

- `dateSerializer(precision = 'second')` округляет дату до ближайшей границы выбранной точности
  при чтении и записи: `day`, `hour`, `minute`, `second` или `millisecond`. Границы считаются
  в UTC, ровно половина шага округляется к более поздней дате. Исходный `Date` не изменяется.
  Записывает компактный ISO в UTC без `Z`: нулевые миллисекунды и секунды
  убираются, полночь записывается одной датой (`2026-10-06`), хвостовые нули дробной части
  сокращаются. Часы без минут читаются как `:00`, но записываются с минутами:
  `2026-10-07T10` → `2026-10-07T10:00`. При чтении компактное время без часового пояса считается UTC;
  полный ISO с `Z` или явным смещением тоже поддерживается. Некорректная дата вызывает ошибку.
- `stringSerializer` сохраняет строку без преобразования.
- `numberSerializer` принимает конечные числа; пустая строка, NaN и Infinity вызывают ошибку.
- `oneOfSerializer(options)` принимает строковые/числовые варианты и сохраняет их литеральный тип.
  В URL пишутся значения, не индексы. Неизвестный вариант отвергается при чтении и записи.
  Неоднозначные варианты вроде `[1, '1']` вызывают ошибку при создании сериализатора.
- `arraySerializer(itemSerializer, validate?)` использует сериализатор элемента и необязательную
  проверку каждого значения при чтении и записи. Порядок и дубликаты сохраняются.
  Ошибка одного элемента отвергает весь параметр; QueryStorage применяет default.
- `setSerializer(itemSerializer, validate?)` работает с настоящим `Set<T>` и использует тот же
  строковый формат и проверки элементов, что и массив. Порядок первого появления сохраняется,
  повторы удаляет сам Set по обычным правилам равенства JavaScript; структурного сравнения объектов нет.
- `setOfSerializer(options)` — `Set` допустимых строковых/числовых значений с сохранением
  литерального типа. Объединяет `setSerializer` и `oneOfSerializer`; неизвестный элемент
  отвергает весь параметр. Не сортирует значения.

```ts
import { arraySerializer } from '@/shared/uiKit/queryStorage/serializers/arraySerializer'
import { dateSerializer } from '@/shared/uiKit/queryStorage/serializers/dateSerializer'
import { numberSerializer } from '@/shared/uiKit/queryStorage/serializers/numberSerializer'
import { setOfSerializer } from '@/shared/uiKit/queryStorage/serializers/setOfSerializer'
import { setSerializer } from '@/shared/uiKit/queryStorage/serializers/setSerializer'

const params = defineParams({
  from: { ...dateSerializer('day'), default: undefined },
  regions: { ...setOfSerializer(['RU', 'EU']), default: new Set<'RU' | 'EU'>(['RU']) },
  levels: {
    ...arraySerializer(numberSerializer, value => Number.isInteger(value) && value >= 1 && value <= 11),
    default: []
  },
  selected: { ...setSerializer(numberSerializer, Number.isSafeInteger), default: new Set<number>() },
  settings: { default: { visible: true, columns: ['damage'] } }
})
```

Массив и Set записываются через запятую. Внутри элементов `%`, `~` и `,` экранируются как
`%25`, `%7E` и `%2C`; `~` обозначает пустой элемент. Поэтому `[] → ''`, `[''] → '~'`,
`['a,b', '~', '%'] → 'a%2Cb,%7E,%25'`. Обычные ID и числовые списки сохраняют прежний вид.
Vue Router дополнительно кодирует готовое значение параметра при записи URL.
Сортировка остаётся у потребителя; для набора уникальных значений используйте Set.

Фабрики создают новые функции: для параметра с общим key переиспользуйте одно определение
или настроенный сериализатор на уровне модуля. Фильтры техники используют `setOfParam` для регионов,
уровней, наций и классов, `setParam` с валидатором для карт. QueryStorage хранит Set;
`useVehicleQueryStorage` преобразует их в массивы модели страницы и обратно. Контекст кодека сравнения
также преобразует Set в массивы; URL-формат сохраняется. Legacy-фильтры переиспользуют `dateSerializer`, а прежняя фильтрация
строковых списков остаётся в адаптере совместимости. Ручной стенд: `/debug/query-storage#serializers`.

## Стандартные параметры

`shared/uiKit/queryStorage/params.ts` содержит готовые фабрики определений поверх стандартных
сериализаторов. Для стандартного формата используйте их вместо локальных обёрток и повторения
`{ ...serializer, default, ...settings }`. Сериализаторы отдельно остаются для композиции и работы без QueryStorage;
нестандартные и контекстные кодеки можно по-прежнему объявлять обычным объектом `QueryParam`.

| Фабрика | Аргументы |
| --- | --- |
| `stringParam` | `default, settings?` |
| `numberParam` | `default, settings?` |
| `booleanParam` | `default, settings?` |
| `dateParam` | `default, { precision?, ...settings }?` |
| `oneOfParam` | `options, default, settings?` |
| `arrayParam` | `itemSerializer, default, { validate?, ...settings }?` |
| `setParam` | `itemSerializer, default, { validate?, ...settings }?` |
| `setOfParam` | `options, default, settings?` |

`settings` принимает `label`, `key`, `priority`, `context`, `enabled`, `history` и `debounce`. Default и функции кодека
задаёт фабрика; их нельзя переопределить настройками. `precision` и `validate` настраивают сериализатор
и не входят в итоговое определение параметра. Все фабрики сохраняют явно переданные поля settings,
в том числе обязательность `label` для использования в `context`.

`oneOfParam` и `setOfParam` выводят литеральный тип из списка options; default не расширяет этот тип.
Параметры примитивов и даты поддерживают `null`/`undefined` как default, массив получает массив default,
а `setParam` и `setOfParam` принимают любой iterable (обычно массив или Set) и создают `Set<T>`.
Default также может быть фабрикой; фабрика iterable преобразуется в фабрику Set. Значения, заданные
напрямую, копирует QueryStorage, как и при обычном объектном определении.

```ts
import { arrayParam, dateParam, oneOfParam, setOfParam, stringParam } from '@/shared/uiKit/queryStorage/params'
import { numberSerializer } from '@/shared/uiKit/queryStorage/serializers/numberSerializer'

const params = defineParams({
  region: oneOfParam(['RU', 'EU'], 'RU', { label: 'region', history: 'push' }),
  nations: setOfParam(nations, localDefaults.nations, { label: 'nation', key: 'vehicles.nations' }),
  levels: arrayParam(numberSerializer, [], {
    label: 'level', validate: value => Number.isInteger(value) && value >= 1 && value <= 11
  }),
  from: dateParam(undefined, { precision: 'day' }),
  search: stringParam('', { history: 'replace', debounce: 300 })
})
```

Общие определения создавайте один раз на уровне модуля и переиспользуйте: вызов фабрики
каждый раз создаёт новые функции кодека. Ручной стенд фабрик: `/debug/query-storage#standard-params`.

## Контекст кодека

Параметр может объявить `context`: объект определений других параметров с **явным `label`**.
Имена свойств задают форму второго аргумента `serialize(value, context)` / `deserialize(raw, context)`.
Это ссылки на определения, а не refs; сами по себе они не создают владельцев URL.
Для проверки типов определения используйте `satisfies QueryParam<Value, Context>`.

```ts
const regionParam = { label: 'region', default: 'RU', type: String }
const sourceParam = {
  default: [] as string[],
  context: { region: regionParam },
  serialize: (values: string[], context?: { region: string }) =>
    values.map(value => value === context?.region ? '_' : value).join(','),
  deserialize: (raw: string, context?: { region: string }) => raw ? raw.split(',').map(value => {
    if (value !== '_') return value
    if (!context) throw new Error('Отсутствует контекст')
    return context.region
  }) : []
}
```

При чтении URL зависимости декодируются из того же исходного query со своими defaults.
Это не зависит от порядка регистрации или гидратации владельцев. При записи зависимости
сериализуются первыми, затем из итогового query собирается контекст зависимого параметра.
Default сравнивается в том же контексте. Смена зависимости пересчитывает URL-представление,
не меняя модель зависимого параметра. Контекст передаётся также при восстановлении после
отклонённой навигации. Вложенные зависимости поддерживаются, циклы и несовместимые определения запрещены.

Связанные активные параметры образуют атомарную группу записи. Группа ждёт самый поздний
из своих debounce; её готовый push/replace включает все зависимые представления.
`flush` и `queryStorageSync` снимают задержку всей затронутой группы, не затрагивая независимые параметры.
При отключении владельца зависимости оставшиеся параметры пересчитываются относительно
нового URL. Если их изменение ещё ожидает debounce, пересчитывается ранее опубликованная модель.

В `sessionStorage` и при сравнении определений контекст **не передаётся**. Кодек обязан
записывать и читать самодостаточное значение без второго аргумента. Это позволяет восстановить
модель из памяти до появления владельцев фильтров; нельзя замыкать кодек на текущие refs.
На стенде `/debug/query-storage` есть раздел с регистрацией зависимого параметра раньше
фильтра, разными debounce, ручным flush и отключением владельца зависимости.

## Жизненный цикл и память

Значение читается уже в setup. Mount/activation добавляют параметры в URL,
unmount/deactivation убирают их после ухода последнего активного владельца.
Общим циклом записи управляет history: после успешной навигации она ожидает обновления
Vue через `nextTick()`, затем вызывает координатор. Он синхронно проверяет владельцев
и рассчитывает итоговый query; собственного `nextTick()` у координатора нет.
History ждёт применения query через роутер и только затем записывает адрес браузера.
На синхронном переходе, включая открытие async-компонента из кеша,
новые владельцы уже зарегистрированы; общие параметры не удаляются и не возвращаются.
Фиксированной задержки очистки нет.
Вложенные вызовы независимы, общий ключ учитывает всех владельцев. `KeepAlive`
поддерживается, деактивированные компоненты не записывают URL.
При смене маршрута учитывается matched record владельца, чтобы уходящий компонент
не прочитал отсутствующий параметр целевой страницы как сброс своей памяти.

Опция хранилища `enabled: boolean | Ref | getter` позволяет условно отключать
владельца, который остаётся смонтированным. Выключение освобождает параметры в URL,
значения остаются в памяти. Обычные страницы полагаются на mount/unmount и KeepAlive.

Отдельный `QueryParam` также принимает `enabled`: boolean, Ref/computed или функцию
`enabled(context) → boolean` (getter без аргументов тоже допустим). По умолчанию — `true`.
Контекст задаётся тем же `context`, что и у кодека; без зависимостей функция получает пустой объект.
Условие принадлежит конкретному объявлению: несколько владельцев общего ключа могут иметь разные
`enabled`. Label остаётся в URL, пока хотя бы одно его объявление включено и владелец активен.
Условия не участвуют в проверке совместимости кодеков и не вызываются при сохранении в sessionStorage.

```ts
const groupParam = oneOfParam(['tanks', 'levels'], 'tanks', { label: 'group' })
const storage = useQueryStorage({
  group: groupParam,
  search: stringParam('', {
    context: { group: groupParam },
    enabled: ({ group }: { group: 'tanks' | 'levels' }) => group === 'tanks'
  })
})
```

Отключённый параметр сохраняет значение и ref; изменение ref/patch при активном владельце
обновляет память, но не добавляет параметр в URL. Фильтрацию данных и видимость полей задаёт страница.
При возвращении параметра публикуется сохранённое значение. Ожидающая запись отключённого
параметра отменяется, поэтому скрытый поиск с debounce не задерживает переключение группировки.

При чтении ссылки условие вычисляется по исходному query, независимо от порядка регистрации
владельцев. При обычной SPA-навигации отсутствующие зависимости дополняются памятью по общим
правилам восстановления; при прямом входе и Назад/Вперёд используются URL и defaults.
Отключённое объявление не читает входящее значение и не пытается прочитать его позднее при включении.
При записи условие вычисляется после зависимостей, по итоговому query; смена зависимости и
удаление/возврат параметров входят в одну запись истории с учётом debounce группы.

Память хранится в реактивном реестре и `sessionStorage` с префиксом
`wotstat:query:v1:`. При недоступном браузерном хранилище работает реестр.
Закрытие вкладки завершает сессию; постоянное хранение между вкладками не включено.

В dev событие Vite `vite:beforeUpdate` начинает новое поколение определений.
При первом повторном подключении ключа из прежнего поколения координатор принимает
новое определение и default: HMR пересоздаёт функции кодека, поэтому их ссылки меняются.
Существующие ref и значение сохраняются, включая записи деактивированных компонентов
в KeepAlive. Следующие объявления ключа в этом поколении проходят обычную строгую
проверку совместимости; в production замена определений отключена.

| Событие | Приоритет |
| --- | --- |
| Загрузка/перезагрузка по ссылке | URL → default, без подмешивания сохранённых значений активных параметров |
| Переход на другой путь внутри SPA | Явные параметры целевого URL → память → default |
| Повторная ссылка на текущий путь без query | Сохраняются текущие параметры, ссылка не считается сбросом |
| Назад/Вперёд | URL записи истории → default |
| Внешнее непустое query на текущем пути | URL → default, включая удалённые ключи |
| Изменение ref | Сразу состояние и память, затем URL |

Координатор сохраняет исходный снимок входящего query для асинхронно подключающихся
потомков. Собственные записи не запускают повторное чтение. Он изменяет только
известные ему labels, прочие параметры не удаляет. Ссылки сайта используют обычный
`RouterLink`, без копирования всего query. Открытие ссылки в новой вкладке следует
правилам прямого открытия URL; память вкладок не используется для дополнения ссылки.

При обычной SPA-навигации `useRoute()` сначала получает целевой маршрут, затем его
query уточняется по владельцам новой страницы. В browser history попадает сразу
окончательный адрес, без промежуточного пустого query или параметров старой страницы.
Исходный query ссылки сохраняется отдельно для чтения вновь подключающимися владельцами.
Guard сохраняет query только при повторной ссылке на текущий путь без параметров.
Прямой вход и Назад/Вперёд не дополняются значениями из памяти.
Страницы с `defineAsyncComponent` переключаются сразу и показывают `PageLoader` при
долгой загрузке. На время лоадера параметры без владельцев удаляются из URL; после
загрузки setup новой страницы восстанавливает их из памяти. Роутер не ждёт модуль страницы.
Для сброса используйте defaults через refs/patch; пустая SPA-ссылка сохраняет память.

## Записи и история

По умолчанию `history: 'replace'`, `debounce: 0`. Опции параметра перекрывают
опции вызова; опции `patch` перекрывают их для конкретной операции.
При deep-изменении массива/Set применяется конфигурация первого активного владельца;
если для операции важны особые опции, используйте `patch` или присваивание ref.

Debounce задерживает только URL. Запросы к данным при необходимости имеют собственную
задержку. `patch` обновляет группу одной записью: без явной задержки берётся максимальная
из задержек её параметров. Среди объединённых готовых изменений `push` приоритетнее
`replace`. `flush` немедленно отправляет ожидающие изменения выбранного поля или группы.
Неизменившийся URL не записывается.

`queryStorageSync(() => { ... })` в конце callback снимает debounce только с параметров,
которые действительно изменились внутри него, и их групп `context`. Работает с refs разных хранилищ, `patch`
и deep-изменениями, сохраняет выбранный `push`/`replace`. Остальные ожидающие параметры
сохраняют свою задержку; присваивание прежнего значения не вызывает flush.
Вложенные контексты объединяются и завершаются при выходе из внешнего.
Если callback бросил исключение, уже сделанные изменения также отправляются без debounce,
контекст очищается, ошибка передаётся вызывающему коду. Результат callback возвращается
как есть. Контекст синхронный: изменения после `await` или в отложенных watchers
в него не входят. Физическая запись URL остаётся в общем цикле history, без новых ожиданий.

`createDeferredWebHistory` сразу обновляет `location/state` в памяти, а физические
`pushState/replaceState` выполняет в конце общего цикла. Последовательность
`push(страница) → replace(страница с query)` создаёт одну запись с итоговым адресом;
два самостоятельных `push` остаются двумя записями. Перед добавлением записи сохраняются
прокрутка и ссылка вперёд в предыдущей записи, поэтому служебный `replaceState` с прежним
адресом допустим. Формат `history.state` совместим с Vue Router, включая `position`.
Браузерный Назад/Вперёд меняет адрес сам; ожидающие записи отменяются и применяется URL
выбранной записи. Программный `router.back()/forward()` сначала фиксирует ожидающую запись.
`storage.flush()` завершается после записи browser history, а не только `useRoute()`.
History отмечает начало `router.push/replace` синхронно, до асинхронных guards:
служебное уточнение query не может отменить уже начавшийся новый переход.
При обычном программном переходе его promise завершается после записи итогового адреса;
переключение компонентов при этом происходит раньше и не ждёт записи browser history.

При навигации ожидающие записи отменяются, последнее состояние уже сохранено в памяти.
Изменения состава владельцев и канонизация URL используют replace. Отклонённая роутером
запись не запускает бесконечные повторы; подтверждённые URL-значения восстанавливаются,
если их не успела заменить более новая операция.

  Проверка сезона по загруженному списку остаётся в Settings; поправка — replace,
  пользовательский выбор региона и сезона — атомарный push. Общий nickname есть
  только на персональной странице и в лидерборде, debounce URL — 1000 мс.
- Сравнение версий: `versions-left`/`versions-right`, кодек Set в `compareQueryParams.ts`.
- Стрельба: `shot`, открытие/закрытие/стрелки — push, слайдер — replace с debounce 150 мс,

  `queryStorageSync`. Владельцем остаётся страница, даже когда окно закрыто.
- Коробки: `selected-lootbox`, массив выбранных контейнеров принадлежит странице,
  список получает обычный v-model. Переключатель тестовых серверов остаётся localStorage.
- Техника: `filters/useVehicleQueryStorage.ts`, единственный владелец — `Vehicles.vue`.

  `classes`, `classes-by-level`; ключ памяти — `vehicles.grouping`, история — push.

  Через `context` группировки и `enabled` параметр `level` отключён для типов, `type` — для уровней,
  а `nation`, `only-actual` и `search` включены только для танков. Скрытые значения сохраняются
  в памяти и возвращаются вместе с полями; поиск больше не сбрасывается при смене группировки.

  Для `mode` используется общий с инфографикой кодек `shared/game/domain/battleModes/battleModeQueryParam.ts`.
  Ключи памяти имеют префикс `vehicles.`, независимо от одноимённых фильтров других страниц.
  `timeSeriesCompare/useVehicleComparison.ts` владеет `compare` с бинарным кодеком:
  массив источников, фильтры каждой выборки, цвета и видимость.
  Первыми идут фильтры боя с явными приоритетами: `region` (160) → `mode` (150) → `arena` (140) →
  `platoon` (130) → `result` (120) → `battle-level` (110).
  Затем параметры таблицы: `group` (100) → `search` (90) → `type` (80) → `nation` (70) →
  `level` (60) → `only-actual` (50) → `min-battles` (40) → `min-players` (30).
  Прочие параметры с приоритетом `0` следуют за ними по алфавиту.
  Настройки сравнения всегда в конце: `metric` (-1) → `step` (-2) → `avg` (-3) →
  `annotations` (-4) → `compare` (-10). Defaults и отключённые параметры пропускаются.
  `metric`, `step`, `avg` и `annotations` включены только при непустом `compare` через `context` и `enabled`.
  Без источников настройки остаются в памяти; при добавлении танка или категории возвращаются в URL.
  Метрика, шаг и усреднение вынесены в `metric`, `step`, `avg` в `query/settings.ts`.
  Метрика — ключ из `availableSlots` в kebab-case (`damage-q50`, `damage-per-life-minute-q50`),
  с обратной таблицей в исходный `Slot`. Шаг и усреднение используют `oneOfParam`:
  `day`/`week`/`month` и `3`/`5`/`7` соответственно.
  Defaults `damage`, `day` и выключенное усреднение (`null`) исключаются из URL.
  Аннотации хранятся независимо в читаемом `annotations` через `setOfParam`: `versions`, `patches`,
  `micropatches`, `wotstat-outages` и ID событий из `historyEvents`, разделённые запятыми.
  Определение — `timeSeriesCompare/query/annotations.ts`, ключ памяти — `vehicles.compare.annotations`.
  Все параметры сравнения используют replace с debounce 150 мс; пустой набор аннотаций исключается из URL.
  Настройки графика сохраняются и без источников; ошибочное значение сбрасывает только свой параметр.
  Шесть фильтров боя подключены через `context`: URL содержит только отличия, память — полные снимки.
  Пороги боёв/игроков не входят в сравнение. Декодирование синхронно восстанавливает короткие ID;
  загрузка полного списка техники и разрешение тегов происходят отдельно, без ожидания в query storage.
  Выбор и сброс фильтров используют атомарный push, поиск — replace с debounce 300 мс.
  Некорректные значения возвращаются к default, значения по умолчанию исключаются из URL.

Период и настройка столбцов техники, сортировки, пагинация и даты Натиска не добавлялись.
`preset` установщика и `no_metrika` сохраняют прежнюю обработку при открытии ссылки.
Старые `useQueryParamStorage` и `QueryPreserveRouterLink` удалены, legacy-форматы не читаются.

## Формат режимов боя

Один формат используется моделью селектора и URL инфографики/техники:
`mode=random-domination,onslaught`. Все ключи — kebab-case, без `@`, `/` и технических
кодов в верхнем регистре. `mode=all` означает пустой массив (любой режим).
Default — `['random']`, поэтому этот выбор не записывается в URL.

Ключ может обозначать режим (`random`, `epic-battle`, `skirmish`, `advance`, `versus-ai`, `bob`),
его геймплей (`random-standard`, `random-domination`, `random-assault`) или группу
(`steel-hunter`, `waffentrager`, `training-all`). Тренировки имеют префикс `training-`,
например `training-epic-battle`; архивные варианты используют тот же формат,
например `waffentrager-standard-2025`. Группы и уточнения работают и до загрузки каталога.
Словари и правила кодирования находятся в `shared/game/domain/battleModes/battleModeSelection.ts`;
семейства — в `shared/game/domain/battleModes/battleModeFamilies.ts`. Повторные ключи удаляются.
Старые значения (`any`, технические коды, ключи с `@`) не поддерживаются и сбрасываются к default.

## Компактный бинарный формат

Формат значения в URL принадлежит сериализатору; QueryStorage работает с готовой строкой.
Независимый `shared/utils/encoding/compactBinary.ts` содержит `Writer`/`Reader` с примитивами
`byte`, `uint`, `string`, `atom` (число или строка), `list` (счётчик и элементы).
`Writer.raw()` дописывает готовые байты, `Writer.finish()` возвращает массив байтов.
Ограничения общего размера и длины строки передаются сериализатором в конструкторы,
ограничения списков — в `list`. Примитивы не знают о страницах, компактерах или сохраняемой модели.

В этом же файле `compactMask(values, options)` и `expandMask(bits, options)` упаковывают и читают
выборку из словаря как битовую маску. Функции не знают о предметной области;
игровые словари передаются из `shared/game/encoding/masks.ts`.

`timeSeriesCompare/query/codec/codec.ts` предоставляет две функции для `compareParam`:
`serializeComparison(sources, context?)` и `deserializeComparison(raw, context?)`.
Вход и выход — массив `SavedComparisonSource[]`, настройки графика хранятся отдельно.
Кодек напрямую вызывает компактеры танков, карт и режимов, затем записывает значения через Writer.
Основной файл задаёт версию, порядок секций и решение о сжатии; соседние `filters.ts`, `sources.ts`
и `colors.ts` реализуют секции, `limits.ts` задаёт ограничения формата.
Общие Base62 и raw DEFLATE находятся в `shared/utils/encoding/{base62,deflate}.ts`.
При чтении числовые ID танков/карт остаются в модели,
а режимы разрешаются сразу через синхронный словарь.

Внешняя упаковка — `base62(header + payload)`, алфавит `0123456789ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz`.
Байты — одно big-endian число; ведущие нулевые байты сохраняются отдельными символами `0`.
Ссылки в Base64url не поддерживаются.
Биты 6–7 заголовка задают версию `01`; `11` зарезервирован под следующий unsigned LEB128
с расширенным номером версии. Бит 5 включает raw DEFLATE только для payload и только при уменьшении размера.
Бит 0 зарезервирован и должен быть нулём; бинарная секция настроек и её флаг удалены.
Неизвестная версия сбрасывается к default через обычную обработку ошибок QueryStorage.
Прежние экспериментальные форматы, включая отдельный байт версии, не поддерживаются.
Кодек содержит одну актуальную реализацию без миграций экспериментальных форматов.
Игровые компактеры остаются общими и не версионируются. Ручные примеры сравнений находятся
на `/debug/game/compact`: контекст страницы и самодостаточная запись, категории с переопределением
выборки, общие фильтры, выключенные линии после второй и неразрешённые ID.

## Загрузка каталогов и сериализация

QueryStorage не подписывается на каталоги, используемые сериализатором. Их загрузка сама по себе
не меняет URL или память вкладки. Компактеры используют доступные данные при каждой сериализации:
до загрузки или при неизвестном ID пишут полный тег, после загрузки — короткий ID, если он однозначен.
Полный тег корректно читается и после загрузки. При следующем изменении параметра или его `context`
кодек пересчитывает всё представление, поэтому ранние полные теги тоже сокращаются.
Реактивное разрешение сохранённых коротких ID для UI создаёт потребитель через обычный `computed`,
вызывая синхронные `expand` или `arenaCompactor.expandMany`. Ядро QueryStorage в этом не участвует.

## Ручная проверка

Раздел «Условные параметры» на `/debug/query-storage` проверяет объявление поиска раньше режима,
разные debounce, ручной flush, сохранение скрытой модели, enabled через boolean/ref/getter,
несколько владельцев одного ключа и отключение последнего из них. Вход с
`?debug-conditional-mode=summary&debug-conditional-search=лишнее` должен удалить поиск из URL
и не восстанавливать отвергнутое значение после включения подробной таблицы. Проверяйте также
Назад/Вперёд, перезагрузку и уход со стенда с последующим возвратом обычной ссылкой.

Стенд `/debug/query-storage`: общий nickname у двух компонентов, вложенный владелец
в KeepAlive, Number/Boolean/Set, debounce, атомарный patch, внешний сброс URL и история.
Раздел «Копирование default» позволяет менять вложенный объект и массив, видеть неизменный
исходный default и восстанавливать новую копию через URL. Для Set исходный default показан
рядом с моделью; раздел сериализаторов показывает экранирование, удаление повторов и ошибки SetOf.
Раздел «Стандартные параметры» использует `dateParam`, `arrayParam` и `setOfParam`: дата округляется
до дня, массив сохраняет повторы, SetOf удаляет дубли и проверяет допустимые регионы. Примитивы
и Set в основном разделе, а также регион контекста объявлены через соответствующие фабрики.
Кнопки переключения выстрелов и «Применить пару» используют `queryStorageSync`:
они записывают изменения без debounce, не ускоряя ожидающий ввод никнейма.
Проверяйте скрытие последнего владельца во время ввода, возврат обычной ссылкой,
Назад/Вперёд и прямое открытие ссылки при уже заполненном sessionStorage.
В dev меняйте `params.ts` после заполнения Set и источников: HMR должен сохранять
значения и запись URL без ошибок совместимости. Повторите обновление определений
техники, когда `Vehicles.vue` активен и когда находится в KeepAlive на другой странице.
Повторный клик на ссылку текущего стенда должен сохранять фильтры. При переходе
в инфографику nickname остаётся в URL непрерывно, debug-параметры удаляются после обновления Vue.
При медленной загрузке async-страницы проверяйте немедленную смену маршрута с лоадером
и восстановление параметров после загрузки; повторное открытие из кеша проходит без сброса.
Дополнительно проверяйте переходы инфографика → Натиск → техника и обратно, применение
периода в форме, выбор коробок и версий. Проверки проекта: `bun run build` и ESLint.
