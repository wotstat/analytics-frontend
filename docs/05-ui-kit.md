# UI-компоненты и стили

Два слоя общих компонентов, и это **не** «старое и новое»:

- **`src/shared/uiKit/`** — базовые компоненты без проектных зависимостей: их можно вынуть и перенести в другой проект как есть.
- **`src/shared/ui/`** — имплементации этих баз под специфику сайта, с проектными зависимостями. Именно они используются на страницах.

Примеры связки: `ui/tooltip/textTooltip.ts` оборачивает базовую `uiKit/tooltip/textTooltip`, подставляя проектный `popoverViewportOffset` из шапки сайта; `ui/tipBubble/TipBubble.vue` — обёртка над `uiKit/tipBubble/useTipBubble` с проектными дефолтами (`--content-page-margin`, политика `autoExtend`), и все страницы импортируют именно её.

Новый переносимый примитив клади в `uiKit`, его проектную настройку — в `ui`, а специфичный для одной страницы компонент — рядом со страницей.

## `src/shared/uiKit/`

- **`dropdown/DropdownCrossingArrow.vue`** — отдельная иконка «стрелка → крестик» из календаря Натиска. `expanded` (по умолчанию `false`) управляет исходной анимацией двух линий за 200 мс. Компонент только отображает состояние; кнопка и открытие меню остаются у потребителя. Размер по умолчанию — 20×20 px, цвет — `currentColor`; размеры и отступы задаются классом. `DaySelector` сохраняет прежние размер, цвет и масштаб. Пример с поповером: `/debug/dropdown-arrow#dropdown-crossing-arrow`.

- **`dropdown/DropdownArrow.vue`** — общая стрелка раскрытия. `expanded` задаёт состояние, `horizontal` меняет направления с «вниз → вверх» на «вправо → вниз», `weight` выбирает `bold` (по умолчанию) или `thin`, `angle` — малый наклон `small` (по умолчанию) или большой `large` (45°). Толщина и угол независимы; в строках таблицы техники используется `bold` с `angle="large"`. По умолчанию свёрнута, вертикальная; размер — `1em`, цвет — `currentColor`. Размер и отступы задаются обычным классом потребителя, поворот и переход 150 мс находятся внутри компонента. Примеры: `/debug/dropdown-arrow`.

- **`pageBackground/`** — общий слой фоновых компонентов: `BackgroundRoot.vue` рендерится в `App.vue`, страницы объявляют фон через `useBackground(BackgroundComponent, { mode?, placement?, props? })` или `<DefineBackground :component="BackgroundComponent" />`. По умолчанию `mode: 'replace'` временно скрывает нижние слои; `overlay` накладывает фон на родительский. `placement: 'viewport'` фиксирует слой на экране, `'page'` привязывает к высоте страницы. Вход и выход по умолчанию — fade по 350 мс. Индивидуальное движение элементов задаётся CSS внутри фонового компонента через классы `.page-background-enter-active`, `.page-background-enter-from`, `.page-background-leave-active`, `.page-background-leave-to`; общий слой ждёт завершения вложенных CSS-анимаций перед удалением фона. При системном `prefers-reduced-motion: reduce` анимации пропускаются. Живой пример с выездом силуэта танка — `/debug/page-background`.

  `KeepAlive` обрабатывается через activation/deactivation. Компонент фона рендерится вне дерева страницы, поэтому получает данные через props, а не её `provide` или scoped-стили. Для вложенности приоритет задаётся иерархией владельцев, а не порядком mount-хуков. Хост для `BackgroundRoot` должен быть позиционирован и создавать stacking context; в `App.vue` это `position: relative` и `isolation: isolate`. При смене корневого маршрута `App.vue` удерживает старый фон до регистрации нового или монтирования страницы без фона (максимум 10 секунд при неудачной загрузке).

  В scoped-стилях фонового `.vue` можно обращаться к классам перехода на внешнем слое обычным селектором, например `.page-background-enter-from .figure { transform: translateX(70vw); }`. Vue ограничит стилем компонента целевой `.figure`. Длительность её движения задаётся в `.page-background-enter-active .figure`; отдельно передавать её в `DefineBackground` не нужно.
- **`tableView/`** — виртуализированная таблица (основная таблица проекта). `TableView.vue` — Vue-обёртка; ядро на классах в `tableView/tableView/`: `TableView.ts` (движок), `Section.ts`, `ReusableStorage.ts` (переиспользование DOM-строк как в UITableView), дефолтные строки `default/` (`CellLine`, `HeaderLine`, `FooterLine`, `SelectableCellLine`). Используется в лидерборде Натиска, таблицах танков и т.д. Ячейка с подсветкой поиска — `shared/ui/tableView/cells/HighlightedCell.ts`. Живой стенд со всеми краями — `/debug/table-view`.

  Неочевидное: реактивности внутри нет, `delegate` читается один раз при монтировании, любое изменение данных доезжает только через `dataDidUpdate()`. Высоты объявляет делегат, таблица не измеряет ничего. За размерами контейнера следит `ResizeObserver` на слое прокрутки: он пересчитывает видимый интервал и класс `has-scroll`, но не высоты строк. `scrollTo(path)` ставит строку не под верхний край, а на высоту заголовка секции ниже (чтобы липкая шапка осталась видна); индекс вне набора — `console.warn` и никакой прокрутки. Пустой интервал видимых строк (`from > to`) — нормальное состояние: так таблица отвечает на нулевую высоту контейнера и на `display: none`.
- **`contextMenu/`** — контекстные меню: `ContextMenuRoot.vue` монтируется в App.vue; создание — `createContextMenu.ts` / `simpleContextMenu.ts` / `composition.ts`; строки меню в `lines/` (Button, Header, Separator, Child — вложенные меню). Опция `closeOnScroll` закрывает меню при прокрутке страницы или внешнего скролл-контейнера, но не при прокрутке внутри самого меню; по умолчанию выключена.
- **`popover/`** — поповеры: `Popover.vue` (базовый), `PopoverAnimated`, `PopoverAutoClose`, `PopoverStyled`; позиционирование в `utils.ts`. `Popover` независимо сообщает о выходе цели целиком за viewport (`targetOutsideWindow`), о том, что сам поповер не поместился после перебора placements (`popoverOutsideWindow`), и о выходе самого поповера целиком за viewport (`popoverFullyOutsideWindow`); все три считаются относительно вьюпорта, сжатого на `viewportOffset` со всех сторон (та же трактовка, что и при позиционировании). Видимую область даёт `getViewportRect()` из `utils.ts` — она берётся из `visualViewport`, а не из `documentElement.clientHeight`: на iOS Safari layout viewport не пересчитывается при сворачивании тулбара, и внизу экрана появлялась мёртвая зона; попутно это учитывает экранную клавиатуру и пинч-зум. Целью может быть как элемент DOM, так и виртуальная (`VirtualElement` из `utils.ts` — объект с одним `getBoundingClientRect()` в клиентских координатах, который поповер опрашивает каждый кадр); так поповер цепляется к точке без своего элемента, например к точке данных на графике. По умолчанию поповер уходит в общий контейнер `#popover-root` (создаётся лениво в `popoverRoot.ts` при первом показе, на нём не должно быть `position`/`transform`, иначе он станет containing block); `teleportTo` задаёт свой контейнер, а `null` рендерит на месте. У `PopoverAutoClose` проп `closeOnOutsideWindow: 'popover' | 'popover-full' | 'target'` выбирает условие закрытия: `'target'` (по умолчанию) — когда за границы viewport полностью ушла цель, `'popover-full'` — когда полностью ушёл сам поповер, `'popover'` — как только поповер перестал помещаться целиком. У `PopoverStyled` проп `interactive` (по умолчанию `true`) — с `false` карточка не перехватывает указатель. На них построены селекторы фильтров (см. 07).

  Неочевидные дефолты: в базовом `Popover` `viewportOffset` по умолчанию равен `offset` (`viewportOffset ?? offset ?? 0`) — задав только `offset`, молча получаешь такой же отступ от края экрана; в `PopoverStyled` это уже `10`, а `offset` считается от `arrowSize`. `snapToPixels` и `preserveLastPlacement` по умолчанию `true`. Три события про выход за viewport — **фронты**: летят только на переход в «истину», обратных нет, и из-за `immediate` могут прийти сразу при открытии, поэтому состояние по ним не залатчишь. Выбранный после перебора placement наружу не отдаётся — в слоте есть только направление стрелки.

  Базовый `Popover` задаёт `overscroll-behavior: contain` своему контейнеру, корневым элементам слота и вложенным областям `.nice-scrollbar` / `.nice-scrollbar-transparent`. У `PopoverStyled` его также получает `.popover-content`: на границе внутренней прокрутки движение не передаётся странице. Свойство не наследуется, поэтому новые вложенные области прокрутки в базовом поповере должны использовать эти классы или явно задавать `overscroll-behavior: contain`. Нельзя применять правило ко всем потомкам: текст с `overflow: hidden` тогда блокирует прокрутку списка при наведении. Правило работает и при телепортации, и при `teleportTo: null`; все обёртки получают поведение автоматически.
- **`tooltip/`** — тултипы на директивах. Глобальная `v-tooltip` показывает текст; объект значения поддерживает `text`, параметры поповера и опциональный `target: HTMLElement`. Для произвольного содержимого есть `defineTooltip`, а `useTooltip(Component, options)` сразу создаёт локальную директиву, передающую значение биндинга в props компонента. Параметры поповера в `useTooltip` принимают обычные и реактивные значения (`ref` / `computed` / getter); уже открытый тултип обновляется при их изменении. Опция `valueAdapter` позволяет отдельно преобразовать значение в props содержимого и параметры тултипа. На элементе с директивой отслеживаются наведение указателя и касания (фокус сам по себе тултип не открывает), а тултип позиционируется относительно `target` (по умолчанию — относительно самого элемента). На touch-устройствах тултип переключается тапом и закрывается тапом вне цели и самого тултипа; свайп для прокрутки его не закрывает. После перебора разрешённых placements тултип закрывается, только если сам поповер не помещается в viewport с учётом `viewportOffset`.
- **`tipBubble/`** — тултипы-подсказки с «умным» позиционированием: `TipBubble.vue`, `TipBubbleComponent.vue`, `useTipBubble.ts`, отладочное окно `DebugTipWindow.vue`. Проектная обёртка с дефолтами сайта — `shared/ui/tipBubble/`, на страницах используется она. `useTipBubble` проверяет «этот бабл уже приняли» **один раз при вызове**, поэтому принятая подсказка исчезает не в момент принятия, а при следующем монтировании компонента.
- **`focusEffect/`** — эффект подсветки элемента (обучающие подсказки): `FocusEffectRoot.vue` в App.vue, API — `focusEffect.ts`, `RectEffect.vue`.
- **`dropdown/DropDown.vue`** — выпадающий список.
- **`fallbackImg/`** — `FallbackImg.vue` — картинка с фолбэком и кешем ошибок (`store.ts`).
- **`highlightString/`** — подсветка совпадений поиска в строке.
- **`spriteAtlas/SpriteAtlas.ts`** — отрисовка иконок из спрайт-атласов (флаги наций: `shared/game/vehicles/nations/60x40/atlas/atlases.json`).
- **`newFeatureBadge/`** — бейдж «новое» с запоминанием просмотра.
- **`chart/`** — движок графиков UniversalChart, см. [06-charts.md](06-charts.md).

### Выбор варианта

`optionsSelect/OptionsSelect.vue` принимает обязательный `v-model` со строковым или числовым значением,
`options: readonly SelectOption<T>[]` (`value`, `label`, необязательный `disabled`), общий `disabled`
и `placeholder` (по умолчанию «Выбрать»). При `(hover: hover) and (pointer: fine)` кнопка открывает
общее контекстное меню на `pointerdown` основной кнопки мыши, с галочкой и стандартной задержкой закрытия.
Можно зажать кнопку селектора, навести указатель на пункт и выбрать его отпусканием (`actionOnPointerUp`).
Повторное нажатие на кнопку закрывает меню без повторного открытия на `click`. На сенсорных устройствах
поверх такого же оформления находится настоящий `<select>`: нажатие напрямую открывает системный
выбор без программного `showPicker`. Тип значения сохраняется через Vue `v-model` и `:value` опций.
Пустой список или список без доступных вариантов блокирует контрол. Смена способа ввода, опций,
блокировка и размонтирование закрывают принадлежащее компоненту меню.
Высота и размер шрифта задаются через `--options-select-height` и `--options-select-font-size`
(по умолчанию 30 и 14 px), стрелка масштабируется вместе с текстом (`0.75em`). Фон настраивается через
`--options-select-background` и `--options-select-active-background` (наведение и открытое меню);
у заголовка показателей в результатах оба прозрачные. Используется для группировки таблицы техники, режима и периода
в параметрах сессии, фильтров распределения карт, варианта показателей и результатов команд.
Стенд без БД:
`/debug/options-select` — связанная модель, недоступные пункты, пустой список, размонтирование и числа.

### Панель поповера

`uiKit/popover/usePopoverCloseDelay.ts` откладывает закрытие после одиночного выбора на 150 мс,
как контекстное меню, чтобы пользователь успел увидеть выбранный пункт. При закрытии,
повторном открытии или размонтировании таймер отменяется; `cancelClose` позволяет сохранить
панель открытой при переходе к множественному выбору. Используется в селекторах режима боя
и метрики техники.

`PanelPopover` принимает `v-model` открытия, `target`, `placement`, `closeOnOutsideWindow`, текстовый `title`, ширину `width` в пикселях, независимую плотность `density` (`standard`/`compact`) и `scrollbarOffsets: [number, number]` для отступов дорожки скроллбара сверху и снизу в пикселях. Плотность определяет отступы и типографику обычной панели; отступы содержимого и ограничения высоты через пропсы не передаются. Для простой шапки используются `title` и слот `toolbar`; слот `header` полностью заменяет их обоих вместе с обёрткой. Кастомная шапка с классом `panel-header` получает общие отступ, ширину и нижнюю границу через `:deep()`; `panel-header--row` включает расположение заголовка и действия в строке. Класс `panel-header-title` задаёт общую типографику заголовка, в том числе внутри содержимого при `scrollMode="child"`. Потребитель может переопределить `--panel-header-padding`, `--panel-header-border`, `--panel-header-title-font-size`, `--panel-header-title-line-height` и `--panel-header-title-margin`, оставляя свою раскладку локальной. `content` (или default) и `footer` задают остальные части.

По умолчанию прокручивается содержимое самой панели, а событие `contentScroll` позволяет закрыть вложенное меню при прокрутке. `scrollMode="child"` нужен для содержимого со своей прокруткой, например виртуализированной `TableView`: слот `content` выводится без обёртки и сам отвечает за отступы и прокрутку вложенного списка. Список сохраняет свою обычную высоту и сжимается, когда места вокруг цели мало. Селекторы техники и версий используют этот режим: их содержимое включает собственные шапки с фильтрами и поиском, а таблицы имеют высоту до 300 px. На экранах шириной до 500 px панели занимают доступную ширину. `BadgesLinePopover` монтирует такую панель для строки бейджей и передаёт ей ширину, плотность, режим прокрутки, размещение и параметры закрытия.

Панель использует отступ от шапки сайта, ограничивает высоту доступным местом над или под целью и включает плавающие варианты размещения для узкого экрана. В режиме `panel` при наличии занимающего место скроллбара содержимое получает `margin-right: 3px` для зазора между полосой и краем панели, а правый паддинг уменьшается до 3 px — такой же зазор между строками и полосой используется в выборе версии игры. Без скроллбара марджин отсутствует и остаётся симметричный отступ плотности. Наличие полосы определяется по `offsetWidth > clientWidth` в существующем цикле позиционирования открытого поповера; перекрывающий скроллбар не занимает ширину и не меняет отступы. Вертикальные отступы дорожки по умолчанию составляют `[10, 10]` px. Особые значения потребитель передаёт через `scrollbarOffsets`, например `:scrollbar-offsets="[15, 10]"` у выбора столбцов: первый элемент — сверху, второй — снизу. Проп относится к прокрутке в режиме `panel`; в режиме `child` скроллбаром управляет содержимое. Глобальный CSS-селектор и отдельный класс для такой настройки не нужны. Классы `panel-section`, `panel-divider`, `panel-note` оформляют согласованную структуру содержимого, включая h3/h4/h5 внутри секций. Примеры без БД: `/debug/panel-popover`.

### ComposableTable

`composableTable/ComposableTable.vue` — универсальная таблица данных на CSS Grid в стиле сайта.
Её текущие потребители — техника и пять таблиц Натиска; предметная логика задаётся снаружи.
Получает готовые `rows`, функцию устойчивого `rowKey(row)` и массив `columns`.
`ComposableTableColumn<Row, Key>` задаёт ключ, подпись, `value(row)`, ширину, выравнивание и поведение ячейки.
Числовая `width` — фиксированная ширина в px; строка задаёт растягиваемую ширину CSS (`1fr` по умолчанию).
`minWidth` ограничивает растягиваемую колонку снизу. Одна схема размеров используется для шапки
и всех строк; при недостатке места прокручивается сама таблица. `align` — left/center/right;
`overflow` — ellipsis (по умолчанию), wrap или visible. В сложном слоте обрезку вложенного текста
задаёт сам потребитель. Без renderer `null`/`undefined` выводятся как «—», ноль сохраняется.

`header-<ключ>` и `cell-<ключ>` явно заменяют содержимое отдельной колонки; общие `header`/`cell`
служат вариантом для остальных колонок. Оболочки сетки остаются у таблицы. Намеренно пустой слот
не запускает стандартный renderer. Ячейка получает `row`, `rowIndex`, `column`, `value`, `expanded`
и `toggleExpanded`; заголовок — `column`. Иконки, форматирование и предметные tooltip остаются
в слотах потребителя. `cellClass(row, column)` задаёт локальное оформление, например активную метрику.

Сортировка данных внешняя. `sort` — упорядоченный массив `{ key, ascending }`; общий
`ComposableTableHeading.vue` показывает направление и номер вторичного порядка. `sortable` включает
кнопку заголовка и событие `sort(key, MouseEvent)`, сохраняя модификаторы вроде Alt.
`headingTooltipClass` позволяет сохранить специальное оформление tooltip.

Раскрытие не зависит от колонки. Без слота `expanded` строки обычные. С ним можно включить
`expandOnRowClick`, использовать `toggleExpanded` из слота ячейки или управлять
`v-model:expandedRows` самостоятельно. Модель содержит ключи строк, сортировка их не меняет;
исчезнувшие из `rows` ключи очищаются. Слот `expanded` получает строку, индекс и `close`.
Вложенные кнопки/ссылки/поля не запускают автоматическое раскрытие по строке.
`cellClick({ row, rowKey, column, columnKey, event })` передаёт клик наружу и сам не выбирает метрику.
`interactive` явно превращает ячейку в кнопку с ховером; по умолчанию значения неинтерактивны.
В интерактивную ячейку не следует вкладывать ещё одну кнопку — для встроенного действия
используется обычная ячейка со своей кнопкой и `@click.stop`.

`loading` показывает skeleton (`skeletonRows`, по умолчанию 5), слот `loading` заменяет его.
`empty` задаёт пустое/ошибочное состояние, `footer` — порционное отображение. Фильтрация,
лимиты строк и загрузка данных остаются внешними. CSS-переменные `--composable-table-row-height`,
`--composable-table-heading-height`, `--composable-table-cell-padding` задают базовую геометрию.
Шапка и строки используют шрифт `mt-font`; раскрытая область сохраняет шрифт потребителя.
Независимый стенд `/debug/composable-table` использует только локальные демоданные и общий компонент,
без импорта страниц техники/Натиска и их моделей. Четыре секции проверяют колонки и сортировку
(ширины, выравнивание, переполнение, скрытие/перестановку, вторичные приоритеты, tooltip, `cellClass`),
приоритет общих/именных/пустых слотов и динамические имена, раскрытие и события
(клик строки, кнопка в слоте, `cellClick`, внешний v-model, удаление/перестановка строк),
стандартные/собственные loading и empty, footer и геометрию через CSS-переменные.

### Плитка выбора

`SelectionTile` принимает `selected`, `disabled`, `density` (`standard`/`compact`) и `accentColor` для полосы выбора. Основной текст или составная разметка передаются в default-слот. Плитка выводит нативную кнопку для основной области и событие `select` с исходным `MouseEvent`. Клавиатурную навигацию по списку опций организует потребитель; начальную выбранную опцию он определяет из своих данных.

Встроенная кнопка появляется при `action`, получает содержимое слота `action` и отправляет событие `action` с исходным `MouseEvent`. Визуальное состояние задаётся через `actionActive` и `actionOpen`. Соседние кнопки занимают всю площадь плитки каждая со своей стороны; вокруг встроенной кнопки нет отдельной некликабельной рамки. Фон встроенной кнопки при наведении — квадрат 24×24 px по центру её полной кликабельной области. Для специальных размеров содержимого доступны CSS-переменные `--selection-tile-main-padding`, `--selection-tile-min-height`, `--selection-tile-gap`, `--selection-tile-action-width`. Общая плитка не управляет предметным выбором и не открывает меню сама. Нативные `title` у плиток и кнопок этого этапа не используются. Пример без БД: `/debug/selection-tile`.

### Кнопка тулбара

`ToolbarButton` выводит нативную кнопку `type="button"` и принимает `icon` (Vue-компонент SVG) или содержимое default-слота. `variant` выбирает оформление: `surface` — кнопка на сером фоне, `accent` — прозрачная кнопка с синей подсветкой активного состояния, `plain` — кнопка без фона, `round` — круглая кнопка сброса. Размеры `small`/`medium`/`large` задают сторону 18/24/30 px; `round` по умолчанию имеет сторону 23 px. По умолчанию используются `plain` и `medium`. При необходимости потребитель задаёт точную ширину или высоту через `--toolbar-button-width` и `--toolbar-button-height`.

Пропсы `active` и `disabled` задают состояние; обработчик `click` получает исходный `MouseEvent` один раз. Кнопки этого этапа не используют нативные `title` и `aria-*`. Template ref на компоненте предоставляет `element: HTMLButtonElement | null` для `target` поповера; например, `computed(() => trigger.value?.element ?? null)`. Кнопка имеет видимый фокус при навигации с клавиатуры. Пример без БД: `/debug/toolbar-button`.

### Легенда графика

`useLegend(items, { highlightSync? })` хранит enabled-состояние по устойчивому `item.tag` и подключает легенду к семантическому `HighlightSynchronizer`. Если синхронизатор не передан, composable создаёт свой и возвращает его как `legend.highlightSync`; этот экземпляр передаётся в `Highlight.syncWith()`. Для нескольких графиков и легенд всем моделям передаётся один общий синхронизатор.

```ts
const series = [
  { name: 'Серверный', color: '#fbd080', tag: 'server' },
  { name: 'Клиентский', color: '#caffb7', tag: 'client' },
] as const

const legend = useLegend(series)
const highlight = new Highlight({ selection: linesNearStroke, class: 'highlighted' })
  .syncWith(legend.highlightSync)
```

```vue
<Legend :legend="legend" layout="horizontal" toggleable highlightable />
```

Модель отдаёт `items`, `enabled`, `enabledTags`, `highlighted`, проверки и действия `toggle` / `toggleFromClick` / `highlight` / `clearHighlight`, поэтому кастомную разметку можно написать без `Legend.vue`. `layout`, `toggleable`, `highlightable` относятся только к стандартному renderer. Disabled item остаётся кликабельным при `toggleable`, но не публикует и не анимирует highlight. Обычный клик в стандартной легенде переключает один элемент и запоминает его как начало диапазона; Shift + клик применяет то же включённое или выключенное состояние ко всему интервалу до текущего элемента включительно. Option/Alt + клик по выключенному элементу всегда включает только его. По включённому элементу — оставляет включённым только его, а если он единственный включённый — выключает его и включает все остальные; при Alt + Shift приоритет у Alt. Выбранный элемент и его состояние становятся началом диапазона для следующего Shift + клика. Программный `toggle` не меняет пользовательскую точку отсчёта.

`Legend.vue` переносит горизонтальные элементы; высоту и прокрутку списка ограничивает родитель.
Изменение цвета, имени или состояния загрузки при прежних тегах не пересоздаёт состояние видимости
легенды и не инвалидирует подписки, зависящие только от видимости.
Опциональный `colorEditable` открывает `LegendColorPicker` с общим `ColorPickerPopup` по нажатию
на кружок и отправляет `colorChange(item, color)`. Опциональный `removable` добавляет крестик
с событием `remove(item)`. Эти действия отделены от кнопки переключения линии; изменение массива
источников и его цветов остаётся ответственностью родителя. По умолчанию обе опции выключены.

У `LegendItem` есть опциональный `loading`: во время загрузки `Legend.vue` заменяет маркер
цветным `Loader` того же размера и сообщает состояние через `aria-busy`. Имя, переключение
видимости и удаление остаются доступны; пикер цвета возвращается после загрузки.

## Форматирование значений — процессоры (`src/shared/utils/processors/`)

Виджеты (`GenericInfo`, tween-значения) принимают `processor` — функцию `number → string`. Готовые: `useRoundProcessor` (округление), `useSpaceProcessor` (разряды через пробел), `useRoundSpaceProcessor`, `useRoundTweenProcessor`, `usePlayerNameProcessor`; фабрики в `processors.ts` (например `createFixedSpaceProcessor`).

## Утилиты (`src/shared/utils/`)

- `core.ts` — общие мелочи; `math.ts` — математика; `time.ts` — форматирование времени (`ms2sec`, `sec2minsec` и т.п. — смотри экспорты; `hourDayExp` к ним **не относится**, это локальная функция внутри `pages/infographics/pages/Battle.vue`).

- `types/` — `Prettify`, `ComponentInstance`.

## Стили (`src/styles/`)

Глобально подключается `index.scss` (из main.ts). Внутри:

- `variables.scss` — CSS-переменные темы (тёмная тема — единственная): цвета текста, фоны карточек и т.д.
- `mixins.scss` — SCSS-миксины (используются через `@use '@/styles/mixins.scss' as *;`).
- `table.scss` — стили классических таблиц; `nice-scrollbar.scss`; `textColors.scss` (классы `.green/.red/...`); `markdown.scss` — оформление markdown-страниц; `mtfont.scss` — игровой шрифт; `shared.scss`.
- Карточки инфографики — классы `.card`, `.card-main-info` и грид-раскладки задаются в самих страницах.

Конвенция: компонентные стили — `<style scoped lang="scss">`, глобальные токены — через CSS-переменные из `variables.scss`.
