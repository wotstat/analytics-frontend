# Страницы сайта (`src/pages/`)

## Главная — `pages/Main.vue`
Лендинг: описание сервиса, ссылки на разделы, реалтайм-счётчики (через `useAnalyticsRealtime`). Горизонтальные карусели — `pages/shared/HorizontalScrollItems.vue`.

## Сессионная инфографика — `pages/infographics/` (маршрут `/session`)

Ядро сайта: личная статистика игрока по событиям мода.

- `Index.vue` — лейаут: `SidebarLayout` (сайдбар с навигацией по под-страницам), заголовок `SettingsTitle`/`StatParamsTitle` (текущие фильтры), `TankList` (список танков за период с чекбоксами → фильтр `?tank=`). `RouterView` в `KeepAlive`. Сам layout не подключает хранилище фильтров и не пересоздаёт страницы при их изменении.
- Старые страницы подключают `useQueryStatParams` из `shared/legacyStatQuery/` локально: общий набор фильтров сохраняется как адаптер совместимости до их переписывания. Запросы используют `queryComputed` / `queryComputedFirst`: SQL, выбор MV и политика кеша пересчитываются из актуальных параметров. Дочерние карточки читают props в геттерах запросов, `ShotsCircle` при смене фильтров отменяет старую загрузку, очищает точки и перерисовывает canvas. Техника и виджеты не подключают общие фильтры; заголовок фильтров и список танков там также не монтируются.
- `settings/Settings.vue` — панель фильтров: ник, режимы через общий `BattleModeSelector` (множественный выбор и архив), период, уровень, тип танка. Хранит черновик, по «Применить» вызывает атомарный `useStatQueryStorage().patch`. См. [10-query-storage.md](10-query-storage.md).
- Под-страницы `pages/`:
  - `Battle.vue` — карточки о боях: количество, времена (очередь, бой, жизнь), винрейт, распределение длительности.
  - `shots/Shots.vue` — стрельба: точность, серверный/клиентский разброс, точки попадания на круге сведения (`ShotsCircle`), инфо о снарядах (`shotInfo/`). Выбранный `shot` хранится через useQueryStorage; слайдер обновляет URL через replace с debounce 150 мс и flush при отпускании.
  - `Damage.vue` — урон: распределения, `ShotDistribution`.
  - `Results.vue` — результаты боёв (`PlayerResultTable`, `TeamLevelTable`).
  - `Maps.vue` — карты: винрейт/статистика по аренам (`MapsTable`), миникарты.
  - `Coverage.vue` — «покрытие»: сколько игроков встречено (`PlayerCoverageTable`, MV `player_coverage_*`).
  - `chuck/Chuck.vue` — турнир «Чак Норрис» (ивент), `ChuckTable`.
  - `lootbox/` — статистика открытия лутбоксов: таблицы дропа, реролов; свой набор таблиц (`Table.vue`, `OpenByTable.vue`, `RerollTable.vue`, список контейнеров `lootboxList/`). Названия контейнеров, расходников и кастомизаций берутся соответственно из `LootboxesLocalizationDictionary`, `ArtefactsLocalizationDictionary` и `CustomizationsLocalizationDictionary`.
    Счётчики открытых коробок и знаменатели процентов суммируют `recordBoxCount`. `lootbox_*_mv` считают появления записей о награде через `countState()`; при открытии пачкой награды объединены в одной записи, поэтому восстановить распределение по отдельным коробкам из этих MV нельзя.
    Все запросы раздела, включая список контейнеров, используют `useLootboxQueryOptions`: общую группу с лимитом 5 запросов и новую политику локального/ClickHouse/proxy-кеша. Горизонтальный список контейнеров запрашивается с `priority: 1`, остальные запросы — с приоритетом `0`: список занимает ближайшее свободное место перед ожидающими таблицами, не прерывая начатые запросы. Срок берётся из `getQueryStatParamsCache`; для конкретного игрока TTL равен 0, поэтому ответ не кешируется и proxy-заголовки не отправляются. В неактивном KeepAlive запросы отключаются до возвращения на страницу.
  - `onslaught/` — см. ниже.
- `shared/widgets/` — переиспользуемые карточки-виджеты страниц: `GenericInfo.vue` (большое число + подпись + цвет, принимает `status`, `value`, `processor`), `GenericInfoQuery.vue` (то же с запросом внутри), таблицы и `charts/MiniBarNew.vue` на UniversalChart (см. 06). Donut винрейта в `Battle.vue` нарисован локальным SVG без движка графиков.
- `shared/ServerStatusWrapper.vue` — обёртка «сервер недоступен», `Timecodes.vue`, `bloomColors.ts` — палитра свечения карточек.

## Натиск (Onslaught / COMP7) — `pages/infographics/pages/onslaught/`

Два входа: внутри `/session` (свои фильтры) и публичный `/onslaught` (свой `Layout.vue`).
Регион и сезон подключены через `shared/useOnslaughtQueryStorage.ts` локально в страницах и Settings; layout не владеет параметрами. `shared/settings/Settings.vue` проверяет сезон непосредственно по результату запроса списка сезонов: поправки делает через patch с replace, пользовательский выбор региона/сезона — атомарный patch с push. Общий nickname подключён на персональной странице и в лидерборде; поле ввода работает через v-model.

- `general/General.vue` — общая страница раздела с выбором региона и сезона; `rankDistribution/` — столбчатое распределение игроков по рангам и рейтингу с одиночным и множественным выбором. Под распределением расположен график дневной аудитории (`dailyPlayersChart/`): DAU считается через `uniqMerge(players)` из `Comp7VehiclesStatistics`, всегда охватывает весь сезон и фильтруется выбранными рангами, но не календарным выбором дней. Ниже находятся глобальные таблицы техники и карт с общим календарным фильтром дней в поповере; выбранные столбики графика фильтруют обе таблицы по рангу. Таблица техники умеет группировать строки по навыку Натиска, а без группировки показывает самый популярный навык и распределение навыков в тултипе. Общий `shared/daySelector/DaySelector.vue` поддерживает произвольный множественный выбор и непрерывный интервал.
- `statistics/Onslaught.vue` — личная статистика сезона: `mainStat/` (рейтинг, дельта, винрейт, топ-рейтинг — карточки с тултипами), `secondaryStat/` (текущий рейтинг-бар, квалификация), `dayChart/` (бар-чарт по дням, выбор дня), `battleHistoryTable/`, `vehicleTable/`, `mapsTable/`, `tips/` — подсказки по горячим клавишам. Общая CSS Grid таблица `shared/ui/composableTable/ComposableTable.vue` используется в глобальных таблицах техники/карт, личных таблицах техники/карт и истории боёв. Локальный `onslaught/shared/useTableSorting.ts` сохраняет прежнюю сортировку, дополнительные ключи и базовые ширины; лимиты и игровые ячейки остаются у потребителей. Раскрытие и интерактивность значений выключены; лидерборд не менялся. Логика данных — в композаблах `useMainStat.ts`, `useBattleHistory.ts` и т.п.
  Для дневных порогов Легенды, позиции и рейтинга игрока читается только последний снимок каждого игрового дня: время берётся из инкрементального `Comp7LeaderboardDaily`, значения — из `Comp7LeaderboardByRank` по ключу `(region, recalculationTime)`. Зависимости от периодического refresh нет. Для CT сохраняется расчёт по всем снимкам, поскольку его границы дня в агрегате отличаются от персональной страницы.
- `leaderboard/Leaderboard.vue` — таблица лидеров с реалтайм-обновлением (`components/Live.vue`), пагинацией (`PageSelector`), деталкой игрока (`detail/Detail.vue` + графики `Charts.ts` на UniversalChart c зумом, выбор непрерывного интервала через `shared/daySelector/`). Поиск по нику (`NicknameInput` в Settings): карточка найденного игрока над таблицей (строка + Detail + кнопка «Перейти к таблице» со скроллом к подсвеченной строке).
  Страница владеет подпиской `comp7LastRecalculation` и перезагружает данные при смене `daily.recalculation` — версии, уже доступной в `Comp7LeaderboardDailyByRank`. Исходные `day` и `recalculation` канала продолжают описывать `Comp7Leaderboard` и не запускают загрузку дневных строк. Запросы используют часовой прокси-кеш (`leaderboard/utils/cache.ts`): SQL поиска актуального снимка содержит готовую версию из WebSocket в комментарии. Последний снимок, позиции и граница легенды определяются по `Comp7LeaderboardDailyByRank` с ограничением сезона по дню и времени пересчёта. Если сообщения с `daily` ещё нет или соединение закрыто, снимок определяется там же с TTL 0; комментарий с версией остаётся пустым. Страницы таблицы и поиск игрока включают полученное из БД время снимка в фильтры. Их SQL содержит маркер `ready-daily-snapshot`: он отделяет кеш от старых клиентов, которые могли запросить строки до завершения refresh и закешировать пустой ответ. Повторных запросов при пустом ответе и таймера повторных попыток нет: обновление запускает готовая версия из realtime. Общие графики и деталка получают время загруженного снимка отдельным prop и добавляют в SQL-комментарий. Без этого prop графики выполняют полный запрос с пустой версией и TTL 0, без локального и прокси-кеша. Недоступность realtime не блокирует загрузку страницы. Встроенный query cache ClickHouse отключён, поскольку его AST-ключ не учитывает комментарии.
- `shared/useSeasonInterval.ts` — границы сезонов; `shared/settings/` — настройки, ввод ника (`NicknameInput`).
- Реалтайм-каналы `comp7Info`, `comp7LastRecalculation`, `battleResult` — см. 08.
- Open Graph: пять карточек для общей статистики, личной статистики и лидерборда
  (последние две — с игроком и без). Учитывают регион, сезон и ник из URL;
  реализации в локальных `meta/`, предпросмотр в `/meta`. См. [11-open-graph.md](11-open-graph.md#карточки-натиска).

## Статистика техники — `pages/infographics/pages/vehicles/`

Селекторы метрик, столбцов и сравнения содержат отдельные разделы «Планки знаков классности»
(золотистый) и «Планки отметок на орудии» (бирюзовый). Классность: III/II/I степень и «Мастер»
(50/80/95/99%); отметки: первая/вторая/третья (65/85/95%). «Другое значение» по умолчанию
выбирает 100%, а кнопка рядом открывает общий `VehicleMetricOptionsPopover` с фиксированными вариантами:
классность — 1/5/10/25/50/75/80/90/95/99/100%; отметки — 0/20/40/55/65/75/85/95/100%.
Произвольного числового ввода нет.
Планки 0% классности нет. Степени классности используют иконки `mastery-3`/`mastery-2`/`mastery-1`/`mastery-m`;
для «Другого значения» используется `mastery-percent`. Первая, вторая и третья отметки используют
`moe-1`/`moe-2`/`moe-3`, значение 100% — `moe-4`, остальные проценты и плитка «Другое значение» — `moe-percent`.
Иконки отдельных процентилей задаются в `icons` независимо от набора отдельных плиток `presets`.
В заголовках таблицы у всех планок классности и отметок рядом с иконкой указан процент.

Разделы и выбранные столбцы планок всегда видимы и доступны независимо от боевых фильтров.
При нескольких регионах или группировке техники по типу/уровню значения остаются пустыми
(в таблице — прочерк); планки не усредняются между танками и регионами.
История планок не зависит от наличия боёв WotStat и не имеет разбиений по картам,
взводам, результатам или уровню боя; кнопка разбиения для этих метрик скрыта.

Одиночные файлы остаются рядом с непосредственным потребителем: например, `VehicleNameCell.vue`,
`useVehicleSorting.ts` — рядом с `VehicleListTable.vue`,
а `line-chart.svg` — рядом с использующим её `VehicleTimeSeries.vue`.
Ресурс нескольких потребителей лежит в их ближайшем общем каталоге: `vehicleListTable/plus-bold.svg`
используют сама таблица и `comparison/VehicleCompareButton.vue`.
Общий `HistoryTooltipHeader.vue` находится в `timeSeries/tooltip/`, поскольку нужен обоим графикам.

`Vehicles.vue` (`/session/vehicles`) содержит адаптер `VehicleListTable` общей `ComposableTable` на CSS Grid и отдельную секцию
`filters/VehicleFilters.vue`. Секция принимает обязательный `v-model` типа `VehicleFilters` из
`filters/types.ts`; начальные значения создаются через `createVehicleFilters()` (RU, случайные бои).
Фильтры боя, локальные фильтры таблицы и поиск хранятся через `filters/useVehicleQueryStorage.ts`:
страница владеет параметрами URL и передаёт моделям компонентов реактивные значения.
Источники сравнения хранятся в `compare`, настройки графика — в читаемых `metric`, `step`, `avg` и `annotations`. Группировка, период статистики, столбцы и сортировка таблицы пока остаются вне URL.
Под таблицей показано пояснение: статистика учитывает всех участников боёв, в которых хотя бы
один игрок использовал мод WotStat. Оно оформлено приглушённым текстом 14 px с разделителем сверху.
`vehicleListTable/useVehicleTableStatistics.ts` загружает данные в два этапа.
Сначала последовательно получает базовые строки обеих нужных частей: метаданные танков/категорий,
последние дни, число боёв и игроков. Затем загружает выбранные показатели со всеми агрегациями,
сначала актуальных, потом неактуальных строк, по одному запросу за раз.
Среднее, минимум, максимум, девять квантилей и доля нулей одного показателя загружаются одним запросом.
Запросы колонок используют даты базовых строк и не пересчитывают последние дни. Для актуальной
части передаётся общая дата, а ключи перечисляются только для групп с более свежим последним днём;
неактуальные сохраняют полный список ключей и индивидуальных дат. В списке танков галочка
«Только актуальные» исключает неактуальную часть; для категорий загружаются обе части.
Строки появляются после завершения всех нужных запросов, при сетевой загрузке виден общий спиннер
и счётчик «Загрузка статистики техники… N из M». Он считает запросы, а не возвращаемые колонки:
базовые строки с боями и игроками — один запрос на часть, все агрегации одной метрики — один пакет.
Сразу видно «0 из M»: базовые запросы и по одному пакету каждой выбранной метрики для первой
незагруженной части. Второй набор метрик заранее не прибавляется: SQL остальных частей добавляются
только после непустого базового ответа. Поэтому при пустой неактуальной части максимум не завышается
вдвое, а при наличии её данных увеличивается на реально необходимые запросы. После базового ответа
предварительные пакеты заменяются точными SQL; пустые части и ответы из кеша исключаются из плана.
Каждый уникальный завершённый SQL увеличивает числитель на один; кешированные ответы не считаются.
Наблюдение за выбором колонок использует пакеты метрик: добавление ещё одной квантильной колонки
уже выбранной метрики не перезапускает загрузку и не сбрасывает прогресс.
Смена выборки начинает новый счётчик; отменённые загрузки его не меняют.
При смене SQL-плана старые строки сразу убираются, даже если новый ответ целиком есть в кеше:
иначе при возврате от категорий к танкам строки с `tankTag: null` успевают попасть в компоненты танков.
Завершённые ответы кешируются раздельно: новый показатель догружает свой набор, а добавление другой
агрегации того же показателя использует кеш или уже выполняющийся запрос. Перестановка не влияет на SQL.
При смене столбцов запросы всё ещё нужных показателей продолжаются; набор отменяется, когда не выбрано ни одной его агрегации. Смена выборки отменяет
устаревшие запросы, уход со страницы — все запросы таблицы. Повтор после ошибки переиспользует успешные части.
В ячейках метрик таблицы тонкие вертикальные индикаторы показывают положение значения между минимумом
и максимумом своей колонки: красный → жёлтый → зелёный.
Шкала использует Apple System Colors для тёмной темы с плавным смешиванием соседних цветов в Oklab;
фон индикатора повторяет цвет заполнения с непрозрачностью 10%.
Диапазон считается по всем отфильтрованным строкам,
до ограничения «Показать ещё»; отсутствующие и нечисловые значения пропускаются, одинаковые получают
середину шкалы. Переключатель «Индикаторы значений» в настройках таблицы выключен по умолчанию
и сохраняется в localStorage (`vehicles-table-show-value-bars`).
При включённых индикаторах появляется чекбокс «Расширенная палитра», также выключенный по умолчанию:
он меняет шкалу на красный → оранжевый → жёлтый → зелёный → голубой → фиолетовый.
Выбор палитры сохраняется отдельно (`vehicles-table-extended-value-bar-palette`).
`timeSeriesCompare/useVehicleComparison.ts` владеет источниками сравнения: добавляет и удаляет их,
меняет цвета, очищает список, создаёт снимки фильтров и нумерует выборки. Страница связывает его
с таблицей и `TimeSeriesCompare.vue`; график получает `sources`, `v-model:settings` и `v-model:annotations`, отправляет события
`remove`, `colorChange`, `visibilityChange`, `clear`. Номера выборок вычисляются по текущим уникальным
наборам фильтров в порядке источников и могут меняться при удалении групп; отдельного счётчика и памяти номеров нет.
В URL номера выборок не записываются.
Назначенный индекс палитры резервируется за источником на время жизни composable: открытие
пикера и изменение цвета не освобождают его для следующего источника. При удалении источника
индекс освобождается, при очистке сравнения сбрасываются все резервы. Непрозрачные RGB и RGBA
считаются одним цветом при подборе свободного цвета. Эти резервы в URL не записываются.
`useQueryStorage` хранит бинарную модель под `compare` (ключ памяти `vehicles.compare`, replace, debounce 150 мс).
Модель — массив упорядоченных источников с фильтрами, цветами и видимостью.
Пороги боёв/игроков по-прежнему берутся из таблицы и не входят в `compare`.
Метрика, шаг и усреднение объявлены в `query/settings.ts`:
`metric` принимает ключи `availableSlots`, преобразованные в kebab-case (default `damage`),
например `damage-per-life-minute-q50`. Внутренний `Slot` восстанавливается по таблице известных ключей.
Шаг и усреднение используют `oneOfParam`: `step` — `day`/`week`/`month` (default `day`),
`avg` — `3`/`5`/`7` (default `null`, выключено). Ключи памяти — `vehicles.compare.metric`,
`vehicles.compare.step`, `vehicles.compare.averageWindow`. Настройки используют replace с debounce 150 мс,
сохраняются в URL без источников, значения по умолчанию исключаются. Неверное значение сбрасывается независимо.
Аннотации объявлены отдельно в `query/annotations.ts` через `setOfParam`: параметр `annotations`,
ключ памяти `vehicles.compare.annotations`, те же replace и debounce. Значения — `versions`, `patches`,
`micropatches`, `wotstat-outages` и ID из `historyEvents` через запятую. Пустой набор не записывается,
неизвестный ключ сбрасывает параметр к пустому набору. Аннотации сохраняются и без источников;
их переключение не меняет бинарную строку сравнения.
Идентичность категории учитывает не только ключ строки и фильтры боя, но и весь `VehicleSelection`.
Служебные функции находятся в `timeSeriesCompare/utils/`: `comparisonRowKey.ts` строит ключ строки,
`comparisonFilters.ts` создаёт снимки и сравнивает фильтры, `comparisonName.ts` формирует подписи источников.

`query/codec/codec.ts` синхронно декодирует ссылку без БД и браузерного окружения,
`serialize.ts` записывает её с сокращением тегов через браузерные каталоги.
Общие служебные файлы собраны в `query/codec/utils/`: `filters.ts` хранит отличия от контекста и таблицу фильтров,
`sources.ts` — цели, выборки и видимость,
`colors.ts` — нормализацию и упаковку цветов.
Фильтры упаковываются один раз: готовые байты используются для дедупликации и записи.
Частые режимы используют семибитную маску, остальные — список атомов.
Ссылка на фильтры совмещена с четырьмя флагами источника; маска выключенных линий записывается без отдельной длины.
Категория хранится в модели как `{ level?, type? }`; строковый `rowKey` строится для таблицы,
кодек использует категорию напрямую. `shared/utils/encoding/` содержит независимые
`Writer`/`Reader`, битовые маски, Base62 и raw DEFLATE с ограничением размера распаковки.
Внешний алфавит compare — только `0–9A–Za–z`, чтобы символы не сливались с подчёркиванием ссылок.
Ограничения конкретного формата заданы в `query/codec/utils/limits.ts`.
Один байт заголовка объединяет двухбитную версию `01`, пять флагов и зарезервированный нулевой бит 0;
он остаётся вне сжатия. Секция настроек графика и её флаг удалены.
Код версии `11` зарезервирован под расширенный номер в следующем unsigned LEB128.
Неизвестные версии отвергаются, прежний экспериментальный формат не поддерживается.
Игровые компактеры не версионируются, их словари дополняются только в конце.
Контекст `compare` ссылается на определения шести фильтров боя из `vehicleQueryParams`.
В URL записываются только отличия от фильтров страницы; при смене фильтров кодек пересчитывает
представление, сохраняя полные снимки источников. В памяти вкладки сравнение самодостаточно.
Без источников URL не содержит `compare`, но сохраняет отдельные параметры настроек графика.
Одинаковые фильтры записываются одним набором, выключенные линии — битовой маской,
стандартные цвета — индексами, изменённые — RGB/RGBA. Hex из пикера нормализуется: совпадение
с цветом по позиции не записывается, с постоянной палитрой — заменяется индексом; у танков тип цвета входит в extras.
Один обычный танк при совпадающих фильтрах занимает 4 символа, два — 7 (для двухбайтных ID).
Обычная категория текущих уровней/классов записывается одним байтом, поэтому сравнение одной категории занимает 3 символа. Маски
`VehicleSelection` сохраняются только при отличии от выборки, заданной кодом категории.
Шаг «неделя» добавляет один байт. Смена только основной метрики также добавляет один байт,
без отдельной маски настроек; дополнительные агрегации в таком формате занимают два байта.
Индексы игровых словарей и палитра сохраняют прежние значения;
новые неизвестные режимы имеют строковый fallback, карты сокращаются числовым префиксом. Точный формат — [comparison-query-format.md](comparison-query-format.md).

Статического каталога танков нет. `vehicleCompactor` и `arenaCompactor` используют общие стартовые
каталоги `shared/game/domain/vehicles/catalog.ts` и `shared/game/domain/arenas/catalog.ts`.
`useVehicleComparison.ts` получает полные значения в обычных `computed`, вызывая `vehicleCompactor.expand`
и `arenaCompactor.expandMany` для списка карт.
При единственном регионе источника ID относительный; при смешанных/пустых регионах ID содержит свой регион.
Загрузка каталогов разрешает короткие ID для UI, сохраняя состав сравнения и текущее представление URL.
Повторное добавление источников предотвращается в операциях добавления; отдельного watcher для удаления дублей после загрузки нет.
Если источник добавлен до загрузки каталога, полный тег остаётся в URL до следующего изменения сравнения
или его query-контекста; тогда кодек заново сокращает все источники. До разрешения коротких ID
легенда показывает «Загрузка…», а запрос истории не запускается.
Ошибка каталога и неразрешимый ID сохраняют источник и показывают сообщение.
Справочники загружаются при старте через `queryAsync`; сравнение не управляет их загрузкой.
Варианты с одинаковым номером разрешаются в основной тег только при однозначном общем префиксе;
специальные варианты, неоднозначные номера и неизвестные префиксы сохраняются полным тегом.
Кнопка «+» в заголовке столбца сравнения добавляет все отфильтрованные строки, включая ещё не показанные
страницы таблицы. Уже добавленные строки текущей выборки пропускаются; `addMany` добавляет источники пакетом.
Если итоговое число линий превышает 20, таблица показывает модальное предупреждение и ждёт явного подтверждения.
Если массовое добавление приведёт к более чем 100 линиям, общий «+» скрывается.
Одиночное и массовое добавление используют общий `vehicleHistorySelection` для танков и категорий.
`timeSeries/useVehicleHistories.ts` получает реактивный список источников, дату, шаг и метрику.
Он хранит состояния по тегам, управляет пакетами истории и предоставляет `retry(tag)`; сравнение читает
`states` для графика, маркеров загрузки и сообщений. При изменении списка модуль сохраняет загрузки
источников с прежним SQL, отменяет удалённые и запускает новые.
Таблица и сравнение используют универсальную очередь из `src/db/concurrency.ts`: каждый загрузчик создаёт
свою группу через `createConcurrencyGroup(limit)` и передаёт её в `query(..., { concurrency })`.
Таблица передаёт 1, сравнение — 5 одновременных запросов.
После завершения или ошибки запроса запускается следующий из очереди. Смена SQL и удаление источника
отменяют запросы без потребителей. Повторная попытка переиспользует успешные части; уход со страницы отменяет все запросы загрузчика.
Ожидающий отменённый запрос удаляется из очереди, а выполняющийся освобождает место после завершения отмены.

Оба графика используют общий `shared/ui/chart/timeSeries/panel/TimeSeriesPanel.vue`, который собирает toolbar,
график, легенду, tooltip и области сообщений. Локальный `timeSeries/period/HistoryToolbarOptions.vue`
передаёт в слот `toolbar` две группы выбора с моделями `step` и `averageWindow`.
Шаг имеет обязательный выбор; среднее использует `clearable`: повторное нажатие выключает его.
Наборы значений и подписи задаются внутри vehicles, типы `HistoryStep` и `HistoryAverageWindow`
находятся в `timeSeries/period/historyStep.ts`. `HistoryStep` использует общий `TimeSeriesStep`;
UTC-хелперы переэкспортируются из `shared/ui/chart/timeSeries/calendar/timeSeriesTime.ts`, набор окон 3/5/7 остаётся локальным.
Слот `header` содержит метрику, в сравнении — также заголовок. В истории строки
`density="compact"` и `tooltip="header"` сохраняют механизм пересечения tooltip с метрикой
и контролами в HeaderTooltip. Слот `actions` добавляет настройки аннотаций и кнопку разбиения.
Шаг и окно среднего остаются в `VehicleListTable` и синхронизируются между раскрытыми строками;
сравнение хранит свои независимые модели. Запросы, очередь, повторы и частичная загрузка
остаются в игровых компонентах. Один useLegend задаёт видимость готовых рядов, цвета и
highlightSync графика; панель отображает ту же модель, не создавая второе состояние.
Слоты `state` и `details` сохраняют сообщения и повторы, `legend-actions` — общий сброс;
события цвета, удаления и клика линии обрабатывает сравнение.
Выбор метрики в заголовках обоих графиков вынесен в `metrics/VehicleMetricSelector.vue` с общим каталогом
`metrics/VehicleSlotOptions.vue`. В таблице модель `slot` связана с общим `activeSlot`: выбор меняет показатель
во всех раскрытых строках, включая метрики вне видимых столбцов, и сохраняется при смене столбцов.
Панели выбора метрики и столбцов, фильтров списка, режимов боя, настроек таблицы и аннотаций
используют общий `shared/ui/popover/PanelPopover.vue`. Их содержимое и правила выбора остаются
локальными; меню агрегаций в `VehicleSlotOptions.vue` по-прежнему использует отдельный `Popover`.
Кнопки настроек таблицы, фильтров списка, аннотаций и разбиения истории используют
`shared/ui/toolbarButton/ToolbarButton.vue`; кнопки сброса в селекторе столбцов, панели фильтров,
верхних фильтрах страницы и легенде сравнения используют его варианты без фона или круглый.
Поповеры получают нативный элемент через `element` ссылки на `ToolbarButton`.
Встроенная кнопка меню агрегаций остаётся частью `SelectionTile`, чтобы сохранять отдельную
кликабельную область внутри плитки.
`HistoryAnnotationSettings.vue` — игровой адаптер общего `shared/ui/chart/timeSeries/toolbar/annotationSettings/ChartAnnotationSettings.vue`:
он передаёт группы версий и событий с выбранным состоянием и смысловыми CSS-классами, фильтрует события по
регионам и связывает событие `toggle(groupId, optionId)` с `useHistoryAnnotationSettings`.
Общий renderer отвечает за кнопку, панель и плитки; игровых каталогов и настроек страницы он не знает.
У каждой истории строки и у сравнения настройки аннотаций отдельные. `gameVersionAnnotations.ts`
читает `GameVersions`: в строке таблицы регионы берутся из фильтров этой строки,
а в сравнении — из объединения регионов сохранённых источников (источник без ограничения означает все регионы).
В пустом сравнении используются текущие регионы страницы.
`historyChartAnnotations.ts` подготавливает общие аннотации: разрешает совпадения версий,
задаёт цвета/приоритеты событий и добавляет интервалы `serverOutages` без подписи.
Подключаемый `shared/ui/chart/timeSeries/annotations/TimeSeriesAnnotationLayer.ts` задаёт подписи через `AutoLabels` в одной полосе над графиком,
а `TicksByLabels` проводит тики через всю высоту графика. Подписи у края плавно
сдвигаются и остаются видимыми, пока часть текста попадает в область графика;
верхний слот обрезает оставшуюся за краем часть. Версии и патчи
привязаны к началу дня UTC. Микропатчи внутри патча используют точное время из `GameVersions`;
первая сборка патча разделяет скорректированную дату патча. При совпадении событий
версия заменяет патч, а патч — микропатч. Подписи используют `AutoLabels.priorities`:
события → версии → патчи → микропатчи, с локальным отбором внутри каждого приоритета.
Расчёт учитывает соседей за экраном, чтобы панорамирование при постоянном масштабе
не меняло отбор внутри окна. Тики всех событий остаются видимыми независимо от подписей.
События выбираются вертикальным списком кнопок; у включённого пункта появляется полоска
его цвета. Недоступность wotstat отмечается красным и рисует интервалы из `serverOutages`.
`shared/game/domain/historyEvents.ts` задаёт общий каталог игровых событий и их основные hex-цвета;
он использует общий тип `GameRegion`. `timeSeries/annotations/events/useHistoryEventAnnotations.ts`
преобразует события в аннотации графиков техники с учётом настроек и выбранных регионов.
`start` без `end` даёт мгновенную метку,
с `end` — цветную зону с подписью посередине и тиками на границах. Даты используют UTC;
дата `end` без времени включается целиком, точное время задаёт исключительную границу.
Необязательный список `regions` ограничивает событие выбранными регионами так же, как версии;
события без пересечения с выбранными регионами скрыты и в графике, и в списке настроек.
Оба места используют `getHistoryEventRegions` из общего каталога; пустой выбор означает все регионы.
Без списка событие общее. При выборе нескольких или всех регионов региональные события
подписываются регионами. «Разворот» — бледно-зелёная зона для RU с 07.08.2025 по 02.09.2025 включительно.
Общие типы меток находятся в `historyAnnotations.ts`. Статические цвета версий и недоступности
задаёт `historyAnnotationStyles.scss`: четыре явных класса с цветом графика и акцентом меню.
`useHistoryEventStyles()` вызывается в `VehicleTimeSeries`, `TimeSeriesCompare` и
`HistoryAnnotationSettings`. Через VueUse `createSharedComposable` и `useStyleTag` они используют
одну таблицу правил `.history-event.annotation-${event.id}` из общего каталога.
Счётчик активных потребителей удаляет её после отключения последнего компонента, включая
деактивацию в `KeepAlive`; при возвращении стили подключаются снова.
Правила задают `--history-event-color` и непрозрачный,
чуть более насыщенный `--history-event-accent`; SCSS графика и меню используют эти переменные.
Новое событие добавляется только в каталог: меню, аннотации и стили получают его автоматически.
Исторические строки `GameVersions` с условным хешем `#0000` дают метки версии и патча,
но не метки микропатча.
Тултип сравнения под датой показывает полную версию с номером и хешем микропатча,
действовавшую к концу выбранного дня, недели или месяца. При нескольких регионах версии
подписываются регионами; условный `#0000` показывается только как номер патча.
На графике сравнения данные версий загружаются независимо от включения аннотаций;
в истории строки они нужны только для включённых аннотаций.
`historyValues.ts` применяет строгие пороги, всегда исключает дневные значения при суммарной
недоступности wotstat более трёх часов за UTC-день и проверяет наличие конечных значений метрики.
Раздела «График» и переключателя пропуска неполных дней в фильтрах таблицы нет.
`VehicleHistoryChart.ts` — игровой адаптер общего `TimeSeriesChart`: готовит точки выбранной
метрики, пропуски периодов, кеш, форматирование Y и диапазон от 01.01.2024 или более ранних
данных до текущего UTC-дня. Среднее применяется до передачи точек графику отдельной функцией
`shared/ui/chart/timeSeries/transforms/movingAverage.ts`; кеш исходных и сглаженных точек хранится в адаптере.
Отрисовка, механизм зума, подсветка и клики живут в общем графике. Адаптер подключает
`shared/ui/chart/timeSeries/chart/TimeSeriesViewport.ts`: прежний минимум 3/21/93 дня и сброс окна при смене
шага выбираются снаружи. Аннотации подключаются отдельным `TimeSeriesAnnotationLayer`;
`timeSeriesChart.scss` и `timeSeriesAnnotations.scss` содержат отдельные миксины оформления.
Tooltip сравнения сопоставляет hits с источниками по `interactionTag`. Проверка статуса загрузки остаётся
у каждого графика своей: история строки ожидает успешный ответ, сравнение может показывать уже
загруженные источники, пока остальные ещё загружаются.
Фоновый слой `VehiclesBackground.vue` подключён через общий `useBackground` и плавно сменяется при переходе между подстраницами `/session`. Финальный фон — тёмный графитовый градиент с приглушённой зернистой фактурой.

Над таблицей общий `OptionsSelect` открывает контекстное меню на компьютере и нативный список
на сенсорном устройстве. Варианты: танки (по умолчанию), уровни, классы, классы по уровням.
Варианты и тип выборки описаны в
`shared/vehicleGrouping.ts`.
`grouping` и `localFilters` хранятся в `Vehicles.vue` и передаются таблице через `v-model`.
В режиме танков поиск и раздел «Показывать» остаются над таблицей и в поповере соответственно.
В режимах категорий поиск скрыт, а раздел «Показывать» содержит фильтры соответствующих измерений:
уровни для группировки по уровням, типы для группировки по классам, оба ряда для классов по уровням.
Нации и «Только актуальные» доступны только в режиме танков.
Набор наций определяется по выбранным регионам через `regionToGame`: для Wargaming используется
`wotNations`, при наличии «Мира танков» или без ограничения регионов — `mtNations`.
При смене игры недоступные выбранные нации удаляются из локального фильтра;
Alt/Option и Shift выбирают только пункты доступного набора.
Выбранные уровни и типы фильтруют строки категорий локально; скрытые фильтры сохраняются, но не ограничивают текущую таблицу
и не учитываются в счётчике активных фильтров. Сброс очищает только доступные фильтры и пороги.
Группировка сохраняется через QueryStorage в `group` (`tanks` по умолчанию, `levels`, `classes`, `classes-by-level`).
Недоступные фильтры и поиск исключаются из URL через `enabled`, зависящий от контекста группировки;
их значения остаются в памяти и возвращаются при переключении обратно.
Переключение группировки сохраняет выбранные столбцы и доступную сортировку.
Отдельного столбца названия у категорий нет: они обозначены столбцами
уровня и класса, через которые раскрывается та же история, что и у строки танка.
В группировке по уровням таблица скрывает столбец класса, а в группировке по классам —
столбец уровня; освободившаяся ширина доступна показателям. Если скрытый столбец участвовал
в сортировке, его порядок убирается. Если порядков не осталось, выбираются бои по убыванию,
а при отсутствии выбранных «Боёв» — первый выбранный показатель по убыванию.
При переключении с танков на категории также убирается сортировка по названию.

`shared/vehicleStatisticsQuery.ts` строит запросы на набор фильтров. Таблица, история и сравнение
читают результаты участников из `PlayerBattleResults` при любых комбинациях фильтров.
Старые агрегатные таблицы сохранены в БД для сравнения, но запросы этого раздела их не используют.
Процент побед — `countIf(result = 'win') / count() * 100`.
В подзапросе `latest` ищется последний доступный завершённый день **для каждого tankTag после фильтрации**
по `PlayerBattleLatestDays`; `beforeDay` — явная дата в UTC, текущий день исключён.
Шестерёнка справа от выбора столбцов задаёт период таблицы: последний день,
последние 7 или 30 дней (по умолчанию) до последнего доступного завершённого дня строки включительно.
При открытии шестерёнки с Alt/Option после «Оформления» появляется секция «История данных»
с галочкой «Начинать с самого начала». Настройка сохраняется в localStorage (`vehicles-from-beginning`),
по умолчанию выключена. `Vehicles.vue` передаёт общую включающую границу `fromDay = '2024-03-06'`
в таблицу, раскрываемую историю и сравнение; включённая галочка убирает эту границу (`null`).
Таблица скрывает строки с последним днём до границы на клиенте. SQL, загрузка и кеши остаются прежними.
Опорный `actualDay` — наиболее частый последний день в пределах двух дней от максимального
`latestDay` выборки включительно; при равенстве частот выбирается более поздний день.
Первый запрос читает актуальные танки с `latestDay >= actualDay`, второй — более старые.
Оба используют пары `(tankTag, day)` через `IN` в `PREWHERE` и явные общие границы дат;
список дат получается разворачиванием 1/7/30 дней до собственного `latestDay` каждого танка.
Метрики читаются после отбора нужных участий. Подпись даты показывается только при
`isActual = false` из SQL-ответа, без повторного определения актуальности на фронте.
Средние считаются через `avgOrNull`, игроки — `uniqIf(participantId, participantId != 0)`;
nullable время оглушения и неопределённые индивидуальные отношения исключаются из своих агрегаций.
«Бои» означают участия на танке, а не уникальные арены. Общая настройка `VEHICLE_STATISTICS_QUERY_OPTIONS`
включает серверный кеш на 24 часа и разрешает кеширование `any`/TDigest. Кеш вкладки включён;
UTC-дата входит в SQL и фиксируется при создании `Vehicles.vue`. Эта же дата передаётся
в сравнение и раскрываемые графики; таймера обновления нет.
Пока запросы работают без MV, у общего клиента ClickHouse задан `request_timeout: 120_000`.

Для категорий тот же запрос группирует по `tankLevel`, `tankType` или их паре.
Категория объединяет участия
за выбранный период до своего последнего дня: средние взвешены числом участий, уникальные игроки
объединены между танками. Период категории общий для всех входящих в неё танков,
а не сумма их индивидуальных последних периодов. `rowKey` служит ключом строки; у категорий `tankTag = null`,
отсутствующие измерения уровня/класса тоже `null`.

Каталог и выбор метрик раздела находятся в `vehicles/vehicleMetricSelector/`: `vehicleMetrics/vehicleMetrics.ts` содержит каталог
метрик и плиток с иконками, подписями, категориями и порядком столбцов;
`vehicleMetricSelector/utils/formatMetricValue.ts` — форматирование значений, `shared/formatStatisticsDay.ts` — формат даты,
`shared/vehicleName.ts` — подпись танка или категории.
В `vehicles/shared/` остаются общие запросы, группировки и подписи; `shared/types.ts` описывает
строки статистики, периоды и серии истории, пороги боёв/игроков.
Таблица, запросы и графики используют эти определения напрямую, без зависимости от реализации друг друга.
Базовый запрос таблицы возвращает строки и размер выборки. Для выбранных столбцов и активной
метрики графика загружаются только необходимые группы данных; каждая группа содержит все
агрегации показателя. Порядок выбранных столбцов не меняет SQL и ключ кеша.
`Slot` включает базовый показатель и его варианты (`damage_max`, `damage_q50` и т.п.);
`Slot` выводится из ключей единого каталога. `metricTileFor` определяет плитку, которой принадлежит
значение; `orderSlots` использует порядок каталога. Группы загрузки задаются независимо через `data`.
`VehicleListTable.vue` хранит полный настроенный набор слотов, а через модель `slots` передаёт
в `Vehicles.vue` только видимую часть для загрузки данных.
Целые значения от 100 тысяч отображаются сокращённо (`123.4k`, `1.23M`); на оси Y точность
сокращения зависит от фактического шага подписей, включая автоматически добавленные крупные шаги.
При шаге, кратном тысяче, сокращение начинается уже с `1k` (`50k` вместо `50 000` при шаге `10k`).

`defaultSlots` задаёт стандартный набор из 20 показателей в порядке приоритета. Первые семь: бои,
игроки, победы, средний урон, содействие, уничтожения, длительность боя; далее — выживаемость, опыт,
заблокированный урон, урон для отметки, обнаруженные противники, выстрелы, полученный урон,
содействие по разведданным и гусеницам, пробития, прямые попадания, время жизни и дистанция.
Для отображения берутся первые N показателей сохранённого набора по текущему лимиту, затем столбцы сортируются
в порядке плиток. Полный стандартный набор сохраняется: при расширении окна или переходе от танков к категориям
новые места заполняются следующими стандартными показателями. Кнопка справа от счётчика в заголовке селектора
при непустом выборе показывает крестик и очищает все столбцы, а при пустом — иконку сброса (как в легенде сравнения).
Сброс восстанавливает первые N показателей стандартного набора, где N — текущий доступный лимит;
дополнительные агрегации снимаются. Мгновенный тултип (`v-tooltip.instant`) показывает «Очистить» или «По умолчанию».
Ширина компактной кнопки постоянна, а высота строки заголовка задана явно,
чтобы переключение состояния не меняло размеры заголовка и расположение поповера.
Кнопка открытия селектора имеет ширину 120 px при однозначном лимите и 136 px при двузначном.
Ширина зависит от лимита, а не количества выбранных столбцов, чтобы изменение счётчика не сдвигало поповер.
Тулбар таблицы разделён на две группы: режим, поиск и фильтр слева; столбцы и настройки справа.
Пока обе группы в одной строке, поиск сохраняет стандартную ширину 240 px.
При недостатке места правая группа целиком переносится на следующую строку и остаётся справа,
а поиск растягивается на свободную ширину левой группы. При ширине содержимого до 420 px
режим растягивается рядом с фильтром, поиск занимает отдельную строку ниже, а селектор столбцов
растягивается рядом с настройками на следующей строке. В группировках без поиска пустой строки нет.
Справа над таблицей `VehicleColumnSelector.vue` показывает все показатели плитками
с иконками по пяти категориям; выбранные столбцы идут в порядке плиток селектора независимо от порядка кликов. Число столбцов ограничено
шириной контейнера: максимум семь для танков и двенадцать для категорий; при сужении окна
или возвращении к танкам лишние выбранные столбцы скрываются, а при увеличении лимита возвращаются.
Ручное изменение в селекторе, включая очистку и сброс, заменяет весь сохранённый набор текущим выбором:
ранее скрытые столбцы после этого не восстанавливаются. Набор общий для всех группировок.
В режиме танков при ширине таблицы менее 720 px первой скрывается колонка стрелки раскрытия,
менее 520 px — уровень и тип вместе. Картинка танка скрывается последней, только при ширине менее 320 px.
После скрытия уровня и типа, при ширине содержимого менее 520 px, картинка занимает 56 px вместо 80 px: изображение сдвинуто влево на 12 px
и обрезается через `overflow: hidden`, освобождая место для названия без изменения масштаба танка.
При ширине менее 440 px колонка сравнения скрывается во всех группировках; её кнопка появляется
в заголовке раскрытого графика слева от селектора метрики через слот `VehicleTimeSeries.header-before`.
Кнопка сохраняет состояние плюс/галочка и переключает сравнение той же строки.
В графике у кнопки такой же фон и цвет плюсика, как у селектора метрики; добавленная строка отмечается зелёной галочкой.
Освободившаяся ширина колонок учитывается в лимите показателей;
дальнейшее сужение снова скрывает показатели. Название сохраняет действие раскрытия.
В группировках по категориям уровень и тип остаются видимыми, поскольку обозначают строки.
Справа от каждой числовой метрики в селекторе кнопка «⋯» открывает меню доступных агрегаций: среднее,
минимум, максимум, квантили 1/5/10/25/50/75/90/95/99%
и доля нулевых значений. Этот набор доступен и для числа противников по уровню. Бои, игроки, победы и выживаемость имеют
фиксированную агрегацию. Меню позволяет независимо включать несколько агрегаций одной метрики:
каждая добавляет отдельный столбец и учитывается в общем лимите. Выбранные варианты отмечены вертикальной
полоской, как в настройках аннотаций; меню остаётся открытым при переключении. Можно снять все столбцы.
Метрики описаны в `vehicleMetrics/vehicleMetrics.ts`: общее представление (`icon`, `label`, `subtitle`, `color`,
`headingLabel`, `headingColor`, `variantLabel`, `format`), общий интерфейс загрузки `data` и возможности истории. Формула производной метрики —
обычный `subtitle`; отдельного поля формулы и неиспользуемого `description` нет.
`color` задаёт мягкий акцент плитки, `headingColor` — отдельный более насыщенный цвет модификатора
в заголовке таблицы и Open Graph. Иконки таблицы остаются белыми.
При создании метрики фабрикой `statisticMetric` поле `label` — явное общее название для плитки и дополнительных агрегаций («Урон»).
Необязательный `defaultLabel` задаёт название значения по умолчанию («Средний урон»);
если его нет, используется `label`. Тексты не разбираются и не преобразуются по языковым правилам.
Идентификатор обозначает конкретное значение: `damage_q95`, `mastery_p99`, `marks_p95`.

Единый `metricCatalog` описывает разделы и записи `MetricCatalogEntry`: каждая содержит
метрики и плитки одного общего формата. Из него выводятся `availableSlots`, `metricCategories`,
тип `Slot` и порядок столбцов. Отдельных глобальных каталогов для статистики и планок нет.
Фабрики `vehicleMetrics/statisticMetric.ts` и `vehicleMetrics/snapshotMetrics.ts` сокращают повторяющиеся описания,
но возвращают одинаковые записи. Новый источник данных реализует `MetricData` и подключается
при создании метрики; расширять общий тип через `kind` и менять загрузчики не нужно.

Плитка содержит представление, `defaultValue`, принадлежащие ей `values` и необязательные
`sections` меню. `VehicleSlotOptions.vue` рисует весь каталог одним циклом без проверок источника.
`metricOptions/VehicleMetricOptionsPopover.vue` на основе `PopoverAutoClose` рисует секции с заголовком,
справкой, числом колонок и фиксированными вариантами. Справка задаётся ключом `help`;
соответствующий Vue-компонент подключается только в поповере, поэтому каталог можно читать
в Bun и серверной сборке без зависимости от Vue SFC.
Для статистики список `aggregations` определяет доступные варианты каждой метрики:
можно убрать минимум, максимум, долю нулей или отдельные квантили без изменения компонентов.
Пустые секции не отображаются.

`VehicleSlotOptions.vue` передаёт плитку, кнопку, выбранные значения и лимит столбцов;
состояние открытия отделено от плитки, чтобы содержимое сохранялось до конца анимации закрытия.
В боевом меню среднее занимает всю строку, ниже минимум и максимум в два столбца,
затем квантили сеткой 3×3 и отдельный пункт «Доля нулевых значений».
Квантили подписаны процентами; рядом с заголовком значок «?» с интерактивным `metricOptions/QuantileTooltip.vue`:
секция «Пример» со схемой распределения и отсортированными результатами 10 условных боёв. Наведение на график или строки,
ползунок и кнопки Q10/медианы/Q90 синхронно меняют границу и пояснение; по умолчанию выбран
Q20 с границей 600 урона. Шкала ползунка охватывает 0–100%, а выбор ограничен 10–90%.
График и таблица выделяют результаты
не выше выбранной границы. Подсказка использует `useTooltip` с `interactive: true`,
поддерживает касания и закрывается при закрытии меню агрегаций.
На экранах шириной до 600 px график и таблица скрыты: остаются определение, подзаголовок «Пример»,
ползунок с кнопками квантилей и карточка пояснения.
Нативные `title` у плиток и опций меню удалены.
При множественном выборе нажатие на активную плитку снимает все принадлежащие ей значения.
Неактивная плитка включает только `defaultValue`, без восстановления прежнего набора.
«Другое значение» владеет только нестандартными планками, поэтому его выключение не снимает
«Мастера», степени классности и основные отметки. Меню при этом позволяет выбирать все
фиксированные планки, включая основные. Каждый пункт меню независимо переключает одно значение.
При одиночном выборе нажатие на плитку выбирает её `defaultValue`; пустого выбора нет.
Общая логика принадлежности и переключения находится в `utils/metricSelection.ts`.

Плитки селекторов метрик, режимов боя и аннотаций используют `shared/ui/selectionTile/SelectionTile.vue`.
У плитки общий ховер и две соседние кнопки без мёртвых зон на основной поверхности; «⋯» дополнительно
имеет собственный фон при наведении и синюю активную подсветку, как у настроек аннотаций на графиках.
Единственный выбранный вариант подписан справа в строке плитки; несколько вариантов показывают
только числовой бейдж на «⋯», без текста «выбрано N». Столбцы упорядочены по категориям
и порядку вариантов, независимо от порядка кликов.
Пока селектор открыт, минимальная высота таблицы сохраняется, чтобы перезагрузка данных
при добавлении агрегаций не сдвигала кнопку и не закрывала меню.
Квантили рассчитываются через `quantilesTDigest(0.01, 0.05, 0.1, 0.25, 0.5, 0.75, 0.9, 0.95, 0.99)` с выбором
элемента результата.
Минимумы/максимумы — через `minOrNull`/`maxOrNull` по индивидуальным значениям. Отдельной агрегации суммы нет.
Доля нулей делится на число не-NULL значений; если таких значений нет, все варианты возвращают NULL.
В заголовке столбца отображается краткая подпись агрегации; каждый вариант сортируется независимо,
добавление других агрегаций сохраняет направление и приоритет сортировки видимых столбцов.
Селектор метрики истории и сравнения поддерживает одиночный выбор тех же вариантов; раскрытие ячейки
открывает историю её агрегации.

Производные показатели (разделы единого каталога в `vehicleMetrics/vehicleMetrics.ts`) доступны в таблице, истории и сравнении,
и имеют агрегации по индивидуальным отношениям: минимум/максимум, квантили
и доля нулей.
Три отдельные группы селектора («Производные · время», «Производные · стрельба»,
«Производные · урон и прочность») используют нейтральный фон плиток, фиолетовую иконку,
светлые заголовки групп и фиолетовую полосу выбора, а также короткую формулу второй строкой.
Добавлены доля времени жизни; выстрелы, урон и содействие в минуту жизни; доля прямых попаданий;
пробития среди попаданий и на выстрел; доля входящих пробитий; отношение нанесённого и полученного
урона; урон к собственной прочности; доля заблокированного урона; оставшаяся прочность в процентах;
доля урона от незасвеченных; доля содействия в сумме урона и содействия.
По умолчанию отношения рассчитываются по общим суммам за выбранный период с `nullIf` для нулевого знаменателя
(в UI — прочерк), а не усреднением отношений по боям или готовых дневных процентов.
Время в формулах задано в секундах; показатели в минуту умножаются на 60, проценты — на 100.
В меню этот вариант подписан «Среднее». Минимум/максимум, квантили и доля нулей считаются
по ALIAS-колонкам `PlayerBattleResults`, исключая участия с нулевым знаменателем.
В `VehicleStatistics` обязательны метаданные, бои и игроки; остальные поля опциональны и
загружаются только для выбранных столбцов. В истории первичные показатели остаются обязательными,
производные и дополнительные агрегации — опциональными. В заголовках таблицы
`slotHeadingLabel` добавляет фиолетовые краткие обозначения (например, `%`, `/мин`, `/HP`),
сохраняя центр белой иконки и полное название в подсказке. Стандартный набор столбцов не меняется.

`VehicleListTable.vue`
локально ищет, фильтрует и сортирует танки, показывает строки порциями по 50 без дополнительных запросов.
В режиме танков над таблицей стоят `SearchLine` и кнопка с поповером `VehicleListFilters.vue`: множественный
выбор уровня, нации и типа поддерживает одиночный клик, Ctrl/Cmd и Shift.

Названия наций показываются над флагами через `v-tooltip:vehicleFilters.top-float`:
первый тултип появляется через 500 мс (`delay: 500` в значении директивы), переход к соседнему пункту общей группы — сразу.
«Только актуальные» включён по умолчанию и оставляет строки с последним днём не старше опорного `actualDay`,

В режиме танков локальные фильтры применяются к уже полученным строкам. Исключение —
«Только актуальные»: при включении не выполняется второй SQL-запрос с неактуальными танками.
В категориях в поповере доступны соответствующие фильтры уровней/типов и пороги боёв/игроков;
пороги проверяют категорию целиком, а не исключают отдельные танки из её состава.
Поиск использует общий `shared/game/components/vehicles/vehicleSearch.ts`: буквы по порядку в отображаемом
коротком названии, без учёта регистра и диакритики (`ис7` находит `ИС-7`). Полное название и тег
дополнительно не проверяются, поэтому `ис7` не находит «Драгуна».
Выбранная сортировка столбца сохраняется и при поиске. При равном значении показателя строки
упорядочиваются по числу боёв (по убыванию), затем по ключу строки.
Заголовок с иконкой танка сортирует танки по названию; в категориях этого столбца нет.
Повторный клик меняет направление.
Alt+клик добавляет заголовок следующим порядком сортировки, повторный Alt+клик меняет направление,
третий убирает его. Иконки остаются белыми, первый порядок обозначен белой стрелкой без номера;
у вторичных стрелка и номер серые. Обычный клик оставляет один порядок.
Правила сортировки сосредоточены в `vehicleListTable/useVehicleSorting.ts`, состояние передаётся из QueryStorage:
`compare` сравнивает строки, `toggle` переключает столбец (второй аргумент — множественная
сортировка), `sortOrders` передаёт порядки в общую таблицу. Модуль следит за группировкой
и выбранными столбцами, удаляя недоступные порядки; `null` всегда остаются в конце.
Очистка столбцов удаляет сортировку по показателям. При пустой сортировке первый добавленный
столбец становится её целью по убыванию; восстановление дефолтного набора возвращает сортировку по боям.
Сохранившиеся порядки, включая сортировку по названию, уровню или типу, не заменяются.
Пустая сортировка использует default-представление ссылки и не записывается как `sort=`.
Параметры `vehicleListTable/query/settings.ts` сохраняют период значений (`period=day/week/month`),
весь выбранный набор столбцов (`columns=winrate,damage-q50`) и порядки сортировки
с направлениями (`sort=damage-q50,winrate-asc`): без суффикса — убывание, `-asc` — возрастание.
Столбцы используют тот же сериализатор
`vehicleMetricSelector/utils/slotSerializer.ts`, что и метрика сравнения; название, уровень
и тип сортируются по ключам `name`, `tank-level`, `tank-type`. Эти параметры идут в URL
после фильтров таблицы и перед `metric`, `step`, `avg`, `annotations`, `compare`.
Изменение ширины скрывает часть выбранных столбцов, сохраняя полный набор и сортировку в URL;
для загрузки данных таблица отдельно передаёт видимые слоты, а страница добавляет показатели сортировки.
Значения по умолчанию (месяц, стандартный набор столбцов, бои по убыванию) исключаются из URL.
Пустой набор столбцов также исключается из URL вместо `columns=`. После очистки таблица
остаётся без показателей, а перезагрузка страницы без `columns` восстанавливает полный дефолтный набор.
Сброс столбцов восстанавливает весь `defaultSlots` с исходным порядком приоритета, а не только
видимую часть. Если ручной выбор или набор из URL совпал с дефолтным набором для текущего лимита,
он также превращается в полный `defaultSlots` и `columns` исключается из URL.
Поэтому восстановленные вручную 7/7 столбцов танков становятся 12/12 при переходе к уровням;
пользовательский набор из семи столбцов остаётся 7/12. Скрытые столбцы пользовательского набора
учитываются при сравнении, чтобы сужение таблицы не заменяло его дефолтным.
`shared/ui/composableTable/ComposableTableHeading.vue` отображает общий заголовок со стрелкой и номером; содержимое передаётся слотом.
Уровень и тип техники вынесены в сортируемые столбцы слева от названия в режиме танков;
их ширина учитывается при расчёте числа видимых слотов. Типы сортируются в порядке общего селектора
техники (`HT`, `MT`, `LT`, `AT`, `SPG`) при первом клике; уровень — по числовому значению.
`VehicleListTable.vue` связывает `v-model:expandedRows` общей таблицы с ключами строк; активный показатель остаётся общим для всех раскрытых строк. Именные слоты задают сравнение, стрелку, уровень, тип и название, остальные колонки получают форматирование метрики через `value`. `VehicleNameCell.vue` сохраняет картинку, имя и дату устаревшего среза; `VehicleCompareButton.vue` — кнопку и анимацию плюс/галочка.
Стрелка раскрытия стоит в отдельной узкой колонке слева от уровня; уровень, тип и название
в строке имеют одинаковое действие раскрытия и общую подсветку строки при наведении.
Значения переключают открытый показатель; повторное нажатие на активный сворачивает строку.
В раскрытой строке `timeSeries/VehicleTimeSeries.vue` самостоятельно загружает всю доступную историю
одного танка или категории с общими фильтрами страницы. История принимает `VehicleSelection`
и название строки: для танка ограничение по тегу, для категории — её измерения.
Пороги не меняют состав категории;
пороги скрывают недостаточно наполненные периоды после агрегации.
`timeSeries/vehicleHistoryQuery.ts` строит пакеты истории из raw и дневных витрин
по выбранному шагу: день (`stats.day`), неделя с понедельника (`toMonday`) или календарный месяц
(`toStartOfMonth`). Общий `useVehicleHistories` сначала получает бои/игроков, затем только выбранную
метрику со всеми её агрегациями. Оба пакета разбиты на завершённые годы, завершённые месяцы
текущего года и остаток. Подробные границы и кеширование — [в слое данных](03-data-clickhouse.md#загрузка-истории-техники).
Переключатель «День / Неделя / Месяц» в тулбаре общий для всех раскрытых графиков таблицы.
Смена шага меняет SQL, смена метрики догружает только её пакеты, смена её агрегации не делает запросов.
Дни загружаются до UTC-дня открытия страницы исключительно; недели/месяцы — только завершённые.
Граница дня остаётся одной для таблицы, истории и сравнения до нового открытия страницы.
Смена дня в фоне не вызывает запросов. При повторном раскрытии строки используется кеш вкладки.
Отображение истории и сравнения по умолчанию начинается с 6 марта 2024 года: более ранние
периоды отбрасываются перед подготовкой точек и скользящего среднего. Диапазон viewport
остаётся прежним, от 01.01.2024 или более ранних данных; обрезаются только линии графика.
Неделя и месяц, пересекающие границу, сохраняются целиком
со своей исходной агрегацией. Полная история всегда загружается; галочка возвращает её без новых запросов.
Есть состояния загрузки, ошибки с повтором и отсутствия данных; запрос начинается только при раскрытии строки.

`VehicleHistoryChart.ts` собирает UniversalChart с линией, маркерами, плавающим тултипом и
горизонтальным зумом/перемещением (колесо, drag, pinch). Начальный диапазон начинается с первого
периода истории и заканчивается UTC-днём открытия страницы, даже если последних данных ещё нет;
переключение шага возвращает полный диапазон. Переключение показателя сохраняет диапазон X,
ось Y подстраивается под видимый участок. Пропущенные периоды и NULL разрывают линию,
только если общая длительность пропуска превышает четверо суток.
После выбора шага в тулбаре доступны `avg3`, `avg5` и `avg7` с подсказками:
выбранное сглаживание синхронизируется между раскрытыми графиками, повторный клик его выключает.
Скользящее среднее берётся по 3, 5 или 7 соседним точкам внутри непрерывного участка,
на краях — по доступным точкам; разрывы не сглаживаются. Сглаженное значение показывается и в тултипе.
Справа от `avg` находится меню разбиения конкретного раскрытого графика: по картам, размеру взвода,
результату или положению танка по уровню боя. Выбранное разбиение хранится локально в строке и запускает
те же пакеты истории по `PlayerBattleResults`, но с дополнительным измерением в базовых и метрических запросах.
Метрики каждой линии заново считаются из её числителей и знаменателей; фильтры страницы применяются до
группировки, поэтому разбиение уточняет уже выбранную выборку. У линий появляются общая переключаемая
легенда, синхронная подсветка и плавающий tooltip общей панели; пункт «Без разбиения» возвращает одиночную
линию и обычный tooltip в заголовке. Карты локализуются через `getArenaName`, остальные значения и порядок
совпадают с вариантами расширенных фильтров. Для разбиения по результату используются семантические цвета:
победа — зелёный, поражение — красный, ничья — жёлтый.
Для недели и месяца текущий неполный период не загружается; точка ставится
посередине полного периода. Тултип недели показывает фактический диапазон дат,
тултип месяца — название месяца и год (например, «Январь 2026»).
Вертикальный отступ через `renderBoundsPxPadding` составляет 12 CSS-пикселей относительно текущей области
построения; для неотрицательных показателей нижняя граница не уходит ниже нуля при приближении.
Локальные фильтры «Боёв больше» и «Игроков больше» применяются к каждому периоду истории:
точка видна только при `battles > minBattles` и `playerCount > minPlayers`.
Исключённые периоды не участвуют в тултипе или масштабе Y. Пропуски до четырёх суток включительно
соединяются линией между соседними доступными точками с сохранением их дат; новых точек
и значений внутри пропуска нет. Более длинные пропуски остаются разрывами. Длительность
считается от конца последнего доступного периода до начала следующего, включая отсутствующие строки и NULL.
Фильтрация использует уже загруженные данные, сохраняет диапазон X и текущий зум.
`timeLabels.ts` задаёт массивы этажей X в зависимости от шага: день → `[день, месяц, год]`,
неделя → `[ISO-неделя, месяц, год]`, месяц → `[месяц, год]`; UniversalChart выбирает вариант
по плотности подписей. Для недельного шага дневных подписей и сабтиков нет, для месячного нет
ни дневных, ни недельных. Месяцы и годы используют реальные календарные границы UTC, включая
високосные годы. Зум недели ограничен минимум тремя неделями, месяца — тремя месяцами
консервативной длины по 31 дню; на короткой истории предел равен всей доступной ширине.
Эти два предела жёсткие, дневной шаг сохраняет прежний упругий зум. Слишком плотные уровни
сабтиков скрываются целиком по `minPixelSpacing`. Между `VehicleFilters` и таблицей расположен `timeSeriesCompare/TimeSeriesCompare.vue` —
общий график сравнения с независимыми показателем, шагом и сглаживанием. Показатель выбирается
в поповере с категориями и иконками: общий `VehicleSlotOptions.vue` используется также в выборе
столбцов таблицы. В сравнении выбирается одна метрика, после выбора поповер закрывается. Кнопка «+» каждой строки
добавляет танк или категорию (уровень, класс, класс по уровню) и меняется на SVG-галочку;
повторное нажатие удаляет источник из сравнения.
Выбранные источники хранятся в `Vehicles.vue` и сохраняются при переключении группировки таблицы.
Кнопка с иконкой сброса справа от легенды очищает все источники сравнения.
Параметры `metric`, `step`, `avg` и `annotations` записываются в URL только при непустом составе
сравнения. При удалении последнего источника они исчезают вместе с `compare`, а выбранные настройки
остаются в памяти и возвращаются в URL при добавлении танка или категории. Выключенная линия
по-прежнему считается источником. Условие использует `context` параметра `compare` и `enabled` QueryStorage.
При добавлении источник сохраняет копию общих фильтров страницы и выбора техники.
Один танк или категория может участвовать несколько раз с разными фильтрами; галочка в таблице
относится только к текущему набору фильтров. Порядок выбранных регионов, режимов и карт не влияет
на идентичность выборки. Локальный поиск и фильтры списка техники не меняют уже выбранный состав.
Пороги боёв/игроков не входят в источник, его ключ и подпись легенды. Текущие пороги таблицы
применяются ко всем линиям сравнения только для отсечения шумных точек уже загруженной истории;
их изменение не создаёт новую выборку, не сбрасывает галочку сравнения и не запускает новый запрос.
Легенда, тултип и сообщения показывают только отличия сохранённых фильтров от текущих:
регион — `[RU] Название`, остальные — через `•`; для одной карты используется её название
(и выбранный респ), для нескольких — число карт. При более чем трёх отличающихся полях
подпись сокращается до `Название (выборка N)`. Номер закреплён за набором фильтров на время жизни страницы.
`useVehicleHistories` загружает историю каждого источника с сохранёнными фильтрами,
тем же разбиением на части и кешем, что у раскрытой строки. Общая concurrency-группа — 5,
части каждого источника идут последовательно. Смена текущих фильтров страницы, цвета, подписи
или видимости не запускает запрос уже добавленного источника заново. Переход между агрегациями
одного показателя тоже не меняет SQL; новая метрика догружается без повторения боёв/игроков.

В истории таблицы `HeaderTooltip` показывает значение и период внутри заголовка
графика, как в лидерборде Натиска; пересекающиеся с ним элементы заголовка временно скрываются.
Плавающий tooltip `TimeSeriesPanel` через общие `TimeSeriesTooltip.vue` и `SeriesTooltip.vue` перечисляет все включённые в легенде источники
в порядке легенды. Игровую шапку задаёт `timeSeries/tooltip/HistoryTooltipHeader.vue`. Значения есть только у источников с точкой на выбранную дату;
остальные строки приглушены, место значения пустое. По высоте тултип привязан к ближайшей
точке по Y с плавным перемещением, как на `/bb25`. Подсветка выбирает ближайший к курсору
участок нарисованной линии в пределах 20 CSS-пикселей; если рядом нет линии, подсветка снимается.
Это правило также применяется к разбиению истории строки и синхронизируется с легендой и тултипом.
В графике сравнения клик по линии в том же радиусе 20 px выключает её в легенде,
Alt/Option + клик выключает все остальные источники, оставляя выбранный включённым.
Видимость меняется сразу: контроллер зума завершает пан до клика и отпускает
подстройку противоположной оси, если после отпускания нет инерции или пружины возврата.
Переключение линии вызывает `event.preventPanInertion()`: после всех обработчиков клика
контроллер отменяет инерцию короткого пана, сохраняя возврат из оверскролла.
Повторный Alt-клик по единственной включённой линии сохраняет её видимость.
Клик по пустому месту не меняет состав; перетаскивание дальше 4 px не вызывает клик.
До десяти источников tooltip показывает одной колонкой, до двадцати — двумя, остальные — тремя.
Последовательные источники распределяются между колонками примерно поровну (`11 → 6+5`),
а не заполняют первую колонку до лимита; общая ширина ограничена шириной viewport.
Ошибки и отсутствие данных показываются для каждого источника отдельно; доступные линии остаются видны.
Базовая адаптивная высота включает график и резерв под одну строку легенды (21 px с отступом 12 px).
Первая строка не сдвигает таблицу; дополнительные строки легенды и сообщения увеличивают
высоту секции вниз, не уменьшая график и не создавая внутреннюю прокрутку.
Загрузка каждого источника обозначается цветным лоадером вместо маркера легенды.
Средние категорий считаются из исходных агрегатов, как в раскрытой истории, а не усреднением средних танков.
`VehicleHistoryChart.setHistories()` поддерживает динамические линии и общий тултип;
цвета передаются отдельно через `setSeriesColors()` и обновляют только CSS линий и маркеров,
без повторной фильтрации истории, пересчёта точек или SVG-путей. Цвет источника сравнения
меняется на месте, чтобы не инвалидировать список источников и таблицу.
Цвет и видимость UI-источников — обычные геттеры без reactive-обёрток; построение
списка источников не читает их значения. Элементы легенды так же сохраняют ссылки при смене цвета.
Преобразование цвета палитры и составная подпись легенды кешируются отдельными `computed`,
которые читаются через геттеры; простой проброс полей и проверка загрузки обходятся без них.
Фильтрация истории вычисляется отдельно от видимости в легенде — и в сравнении, и в разбиении
истории строки. При скрытии или показе линии `applyHistoryFilters` не запускается повторно.
График сохраняет готовые точки каждой серии и обновляет только линии с изменившимися данными
или видимостью. Кеш точек учитывает ссылку на отфильтрованную историю, показатель, текущий день,
шаг и сглаживание; удаление источника освобождает его кеш.
`setHistory()` сохраняет API одиночных графиков. Легенда позволяет скрыть линию, изменить цвет
и удалить источник. Начальные цвета сравнения и разбиения берутся из общей палитры в стиле Apple в
`shared/ui/chart/legend/seriesColors.ts`; локальный `timeSeries/split/seriesColors.ts` задаёт семантические цвета результатов боя.

Основные фильтры — регионы и режимы из `shared/game/domain/battleModes/battleModes.ts` с дополнительными сочетаниями из БД.
Параметры собраны в одну строку с переносом на узких экранах. Регионы выбираются открытым рядом кнопок:
обычный клик выбирает один регион, Shift+клик добавляет или убирает регион; хотя бы один остаётся выбранным.
Режимы используют общий `shared/game/components/selectors/battleMode/BattleModeSelector.vue`.
Страница передаёт выбранные `regions`, скрывая внутренний переключатель Lesta/WG.
Одноколоночный список разделён на Основные, Клановые, Особые, Обучение, События и Другое.
Основной клик выбирает любой геймплей, три точки справа открывают компактное подменю.
В нём режимы и геймплеи составных групп показаны на одном уровне, с заголовками секций.
Выбор подварианта подсвечивает родительскую плитку. «Полигон» (бои с ИИ) находится в Основных.
Галочка в шапке добавляет архивные пункты в те же категории с оттенком текста и оранжевым акцентом при выборе.
Справочник дополняется кешируемым запросом при первом открытии; неизвестные режимы показаны техническими кодами.
Обычный клик выбирает один вариант и закрывает поповер; Shift/Ctrl/⌘ + клик переключает выбор без закрытия.
«Все режимы» первым пунктом очищает модель. Начальный фильтр — `['random']`: режим случайных боёв с любым геймплеем.
`battleModeSelection(key)` разворачивает читаемые ключи режимов, геймплеев и групп в цели SQL;
подписи сравнений используют ту же функцию. Подробности контракта — в 07-game-domain.md.
`regions` и `battleModes` — массивы; пустой массив означает отсутствие ограничения, выбранные варианты
внутри одного фильтра соединяются через OR (у режимов учитывается пара mode/gameplay).

В раскрываемой части — карты через `ArenaSelectorBadges`, размер взвода, результат и положение танка по уровням участников
боя. Варианты каждого условия показаны рядом кнопок с одиночным выбором. Уровень и класс самого танка
сюда не входят: они выбираются в локальном поповере таблицы после запроса.
Выбранные карты отображаются бейджами и учитываются счётчиком дополнительных фильтров.
`useBadgeSelection` синхронизирует массив карт с изменяемым Set общего селектора, включая удаление
бейджа и внешний сброс.
Сворачивание сохраняет выбор; сброс возвращает начальные значения остальных фильтров, сохраняя регионы.
Изменение региона само по себе не активирует кнопку сброса.
`arenas` — массив тегов карт без команды. Селектор работает с `allowTeamSelection=false`:
выбранная карта получает синюю рамку без переключателя респауна. Запросы к
`PlayerBattleResults` фильтруют по `arenaTag`; команды в этой таблице нет.

Условия PREWHERE по `PlayerBattleResults`:

- `platoon`: solo — `squadmatesCount = 0`, duo — `= 1`, trio — `= 2`, large (4 и более игроков) — `>= 3`.
  Поле хранит число совзводных, без самого игрока.
- `battleLevel = same`: `minBattleTankLevel = tankLevel AND maxBattleTankLevel = tankLevel`.
- `battleLevel = top`: `minBattleTankLevel < tankLevel AND maxBattleTankLevel = tankLevel`.
- `battleLevel = middle`: `minBattleTankLevel < tankLevel AND maxBattleTankLevel > tankLevel`.
- `battleLevel = bottom`: `minBattleTankLevel = tankLevel AND maxBattleTankLevel > tankLevel`.

Категории уровней не пересекаются: одноуровневый бой не относится одновременно к топу и низу.
Минимум/максимум в агрегате посчитан по всем участникам боя, а не только противникам. Все необходимые
значения заранее вычислены в материализованном Enum8 `battleLevel` и входят в ключ сортировки.
SQL фильтрует непосредственно `battleLevel = 'same'/'top'/'middle'/'bottom'`.
Условия применяются до агрегации, вместе с ограничениями по регионам и режимам
из префикса ключа (правило `schema-pk-filter-on-orderby`).

## Установщик модов — `pages/install/` (маршрут `/install`)

Устанавливает моды прямо в папку игры через **File System Access API** (только Chromium).

- `utils/installer.ts` — ядро: выбор папки игры (`showDirectoryPicker`), хэндл хранится в IndexedDB (`idb-keyval`), определение игры/региона и версии, парсинг имён `*.wotmod|*.mtmod`, копирование файлов, сравнение версий (`dotSeparatedCompare`). Для чтения версии `fflate.unzip` извлекает только корневой `meta.xml`.
- `utils/downloader.ts` — скачивание модов с `INSTALL_URL`.
- `mods/mods.ts` — реестр модов: обязательный `wotstat.analytics`, `wotstat.positions`, `wotstat.widgets` + списки `lestaMods`/`wgMods` (разные для Lesta и WG) с зависимостями `required`. Описания модов — markdown в `mods/details/ru/*.md`, i18n — `mods/i18n.json`.
- `components/` — карточки модов с 3D-наклоном (`modCard/useCardRotation.ts`), экспорт архива вместо установки (`exportArchive/` через `fflate.zip`), конфетти по завершении. ZIP создаётся без сжатия (`level: 0`), с `ИНСТРУКЦИЯ.txt` и файлами в `mods/<версия>/`; байты самих `.mtmod`/`.wotmod` не меняются. Служебные ZIP-заголовки отличаются от прежнего экспорта через JSZip.
